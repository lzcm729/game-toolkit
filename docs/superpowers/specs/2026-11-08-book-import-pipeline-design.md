# 书籍导入流程重做（以 cangjie-skill 为基底）：框架稿 v0.3

> 状态：定稿（2026-11-08）。框架级取舍用户已拍板，经 codex 两轮复核，见第 2、9 节。规则、数值、文件格式放第 10 节备忘，细节轮可以回改框架。
> 依据：用 cangjie-skill v2.5.0 处理 Sylvester《Designing Games》全书，做到验证、写卡和可达测试；回答对比只在试点的第 5–9 章做过。产物在作者本地，含书的全文，不进本仓库。
> 版本：v0.1 初稿。v0.2 吸收 codex 第一轮意见，用户推翻「已有参考不整体迁移」、定口径 B、拍 D1–D6。v0.3 吸收 codex 第二轮意见：收紧 B 的判法和 D3 的走向，执行顺序前置淘汰步骤，胃口上限提到约 1200 万。

## 1. 起点：现象

**A. 覆盖有缺口。**

- 现有 7 份 `sylvester-*.md` 没有系统覆盖第 6 章平衡、第 7 章多人、第 9 章界面、第 10 章市场。开发过程部分，第 12 章只摘了几句，第 13–17 章没有。
- 按术语查：退化策略、纳什均衡、yomi、griefing、隐喻、视觉层级、价值曲线、天然权威、依赖栈，7 份里一次都没出现。零命中不等于整章全无，旧 `sylvester-iteration.md` 就提到过平衡测试。
- 试点给平衡、多人、界面三章写了卡。盲评满分 12，每格只跑一次：平衡比指定的 Schell 参考高 2 分，界面高 1 分，多人比不带资料高 4 分。只能算初步信号。

**B. 引文和出处核不了。**

- 7 份 Sylvester 参考一个页码都没有。
- 脚本筛出 51 句引号句，对原书核：34 句标准化后逐字命中，10 句部分对得上，7 句没找到。脚本按字符串和 5 词片段比对，没找到不等于书里没有，也不能单凭它断定是改写冒充引文。
- Schell 参考用第 3 版核了一遍：71 句里 44 句命中、8 句部分、19 句没找到，多是格言式的短句。
- 试点的新核对脚本也只查摘句在不在全书里，不查它在不在卡上标的那一页。

**C. 导入没有验收，试点的第一次测试也说明不了格式。**

- `book-to-reference` 的检查清单查定义、操作框架和格式，没有一步测回答有没有变好。
- 试点里同书同章的新卡和现有摘要，盲评 24 比 23。这只说明两题没测出差别，不说明格式无所谓：
  - 量表有天花板：评委认为新卡的一个回答实用性较弱，仍给了满分；
  - 比的是两套资料包，不只是格式；
  - 评分项按书中路线写，压低了其他合理路线；
  - 每格只跑一次，页码还泄露了变体身份。
- 补上没有的章节，分数涨了，同样只是信号。

**D. 走全流程很贵。** Sylvester 全书实测约 1690 万子代理 token：

- 阶段 0 约 130 万，阶段 1 约 400 万，阶段 1.5 约 300 万；
- 第 5–9 章试点写卡和测试约 410 万；
- 补齐全书（复核其余章节、写其余 28 张卡、全书可达测试）约 450 万。

这个数含试点的试错和两轮复核，干净地再跑一本书要多少没测过。每个子代理约 12 万固定开销，是按单次用量估的，没逐个核。

**E. 结构对不上。**

- cangjie 一本书出一个 skill；本插件是一个多书 skill（`game-design-theory`）。
- 6 个文件按文件名引用 Sylvester 旧参考：3 个 agent、`design-discuss` 的理论框架、`game-design-theory` 的 SKILL.md、`book-to-reference` 的模板。
- 仓库外也有消费者：`scripts/export_codex_agents.py` 把 agent 正文原样导出到使用者项目的 `.codex/agents/`，插件更新后不会自己跟着变。
- `game-design-theory` 的 description 已有 994 字符，测试上限 1024。它按书名和主题列，写不下这次要补的多人、市场、团队决策这些任务。
- 更早加载的摘要和新卡口径冲突：SKILL.md、`game-designer.md`、`theory-framework.md` 都把决策的秒数分级当事实列出，新卡按原书标成作者的经验估计。只换参考文件，回答还会照旧摘要说。

**F. 子代理会判宽，合卡时复核结论还会走样。**

- 阶段 1.5 首轮判了 181 个 verified。按「照原文现在能不能写出每一步」的口径全部复核后：162 个通过，59 个只作参考，4 个待核查，2 个并入别的单元。首批定向复核的 39 个里，33 个要收窄。
- 晋级门 19 张卡五条判据全判通过。这本身不证明判宽，只说明这道门在这里分不出高下。
- 单元复核对了，合成卡后仍会走样（codex 第二轮抽读发现）：
  - 试玩卡把一个待核查单元的场次数字写进了执行步骤，分卡方案原本规定放在边界段；
  - 「知识创造方法」卡把只对辩论分支成立的「单人不适用」放进了整卡边界，照字面执行会连另外两个分支一起挡掉。

**G. 可达测试的机械期望只能当参考答案。** 全书可达测试由没看过卡的子代理只按读者任务出题，期望卡按「任务 → 单元 → 卡」机械推出。92 道任务题，主卡命中 82；8 道诱饵全部拒绝。没命中机械期望的里：

- 4 道是意图没写到；
- 2 道选了相邻的卡，其中「一套阵容总是最优」那道选的退化策略卡同样能完成任务，不一定算错；
- 2 道是题目和任务对不上。

### 要回答的问题

导入一本书时，怎样在说得清的成本内做到：

1. 覆盖可审：漏掉哪些任务，要么能看见，要么是有意不收的；
2. 引文和出处可核；
3. 不把作者没给的判据写成规则；
4. 导入后验证回答真的变好了，至少没变差；
5. 已有参考换成新卡时，回答不退步。

### 维持现行能做到多少

现行流程便宜。试点两题里，同书新旧没测出差别（现象 C），但这不等于旧参考覆盖的任务都验过了。缺的是：

- 覆盖靠导入者挑主题；
- 引文没人核；
- 没有验收；
- 旧摘要和新口径冲突时没人管（现象 E）。

## 4. 原则

1. **一个入口。** 书的知识都经 `game-design-theory` 进来。一书一 skill 会撞上 cangjie 自己警告过的「skill 太多、互相抢调用」。入口要先被激活才有用，所以 description 写得下这些任务，也算入口的一部分。
2. **可核，分三件事核。**
   - 摘句在不在原书、在不在标的那一页，由脚本核；
   - 方法的每一步有没有原文支持，由验证阶段判；
   - 验证阶段的结论（收窄、缺口、待核查）有没有原样传到最终卡上，单独核。
   - 每条方法都要能回到页码。
3. **不替作者定规则，也不让 agent 闭嘴。** 原书没给的判据，卡里写「原书未说明」；转换时丢了图，写「原图缺失」，两者不混。入口允许 agent 补自己的建议，标明不出自本书。
   - 试点里有一题，带新卡的回答照卡上的「原书不给解法」，把解法整个交还给了设计者。
4. **覆盖可审，去向要落地。** 导入前列全书的读者任务，导入后逐条标去向。标「只作参考」的，要有消费方读得到的去处，不能留在仓库外的工作目录里还算作保留。去向齐了不等于交付完：承诺交付的任务另标完成状态。
5. **验收到实际消费方。** 一条链测到底：description 激活、选对卡、读到卡、回答用上。消费方按引用读 1–3 张卡的路径也要测，不只测从选卡表自己选一张。不拿「文件写出来了」「格式检查过了」当完成（「让 AI 和人都能用的软件」原则八）。
6. **按任务接替旧参考。** 去重的单位是任务，不是章：同一章支持不同任务，同一任务也会跨章。一个任务的旧内容，等新卡过了 B 才换掉。
7. **默认子代理会判宽。** 验证首轮就用严格口径，再抽一部分做对抗复核。抽样不只看判定者自述拿不准的。也不把「不能全过」当质量要求，那会逼出随意的淘汰。
8. **独立就是没见过答案。** 复核、出题、评分都要在没见过上一轮判断和答案的上下文里做。宿主给不了独立上下文时，流程可以做完，但这几步标「未独立验证」，不能拿来过验收。
9. **书的全文留在仓库外。** 书的全文、分块和中间产物都不进仓库（第 2 节第 7 条）。卡按试点的形态带原文摘句和翻译进仓库（D6）；摘句由脚本按全文和页码核对。

## 6. 框架级取舍（用户 2026-11-08 已拍板）

**D1 迁移时，消费方对旧文件名的引用怎么办。**

- 已定：同一次提交里把引用改成直接指向接替它的卡（一个任务一般 1–3 张），被完整接替的旧文件删掉；加一条测试，查 agent、`design-discuss`、SKILL.md 和 `book-to-reference` 模板里指向参考文件的路径都在。理由：
  - 引用方在本仓库里的一次改得完，测试能抓漏；
  - 只跳一层，和官方建议一致；
  - 不留索引壳，免得多一份要手工同步的路由。
- Codex 导出的 agent 是仓库外的副本：升级说明里写明要重新导出、开新会话，不宣称一个提交就升级了所有消费者。
- 部分迁移时，旧文件只要还承担没被接替的任务就留着，只删已接替的部分；最后一个任务被接替后再删文件。
- 备选，未采纳（codex 第一轮的建议，第二轮它改判同意上面的做法）：旧文件名保留，内容按任务逐项换。

**D2 选卡表放哪。**

- 已定：SKILL.md 正文按任务直接链到卡，只有一层。每行写触发意图，以及它和最容易混的那张卡怎么分。

**D3 胃口与停止条件。**

- 本轮胃口上限约 1200 万子代理 token（用户定），覆盖第 7 节的全部步骤。回答对比的计划按实际题数报价，跑前给用户看。
- 题目分两类：决定 B 成不成立的必测题，和事先标明的可选探索题。钱紧时只砍可选题；必测题没跑完，结论记「未完成」，不能减了必测题还批准原范围。
- 回答对比之后的三种走向，互斥：
  - **全部迁移**：两组都过，没有确认过的实质退步，可核性过，最终插件的消费链过。删掉被完整接替的 7 份旧参考，然后用同一流程做 Schell 第 3 版（另定胃口）。
  - **部分迁移**：只有能定位到具体任务的局部退步或未决，其他条件都过。退步和未决的任务留旧参考，其余按任务接替。胃口里预留一次对最终混合版本的受影响任务验收；它是确认真正要发布的组合，不是继续改卡找分。没有这笔预留，或混合版本没过，本轮不批准部分迁移。
  - **不迁移**：新增组整体退步，另外三本书的既有入口受损，可核性没过，必要验证不完整，或证据不够支撑上面两种。记下原因，结束本轮，下一步做什么由用户定。

## 7. 执行顺序

每一步不过就停在那一步，不往更贵的下一步推。

1. **冻结基线，做入口和宿主的小实验。**
   - 冻结现行插件版本、两组任务和必测范围。
   - 确认插件副本能在无界面的 Claude Code 里加载，能看到 skill 激活和实际读了哪些文件；不给被测模型预先塞选卡表，也不强制调用目标 skill。
   - 先写 description，看 1024 字符内能不能既写下新任务、又不丢旧三本书的触发；测几个新能力、三本旧书受影响的能力和代码实现之类的排除项。排除项不照搬独立 Sylvester 入口：它把「经济系统动力学」列为不适用，现行插件却用 Meadows 处理经济问题。
   - 加载链不成立，或入口明显丢了旧能力，就停在这里。
2. **材料验收，在批量接入之前。**
   - 摘句按页段核对；
   - 复核结论到最终卡的核对，包括分支边界的作用域；
   - 「只作参考」的任务定下实际去处（编译入口里另有 overview、术语表的消费路径，不必照搬，但每项要有落点）。
   - 发现的走样在这一步改卡。
3. **接入，冻结待比较的版本**，在本地分支里做，按 B 定下迁移之前不推送：
   - 选卡表（D2，含近邻区分，补上可达测试里没写到的意图）；
   - 改消费方引用和冲突的旧摘要，跑 Codex 导出；
   - 加引用链测试。
4. **可达测试**：旧题回归加新题验收，成绩分开；测插件入口和实际消费链，不只测独立选卡表。入口失效或必要路线够不着，就不进回答对比。
5. **回答对比**：按冻结的计划跑，按 D3 收口；部分迁移只用预留的那一次混合版本验收。
6. **写回流程**：把实验定下的做法写进 `book-to-reference`，本次重做结束。Schell 另起一轮。

这次实验证明的是「现有全书卡的接入和迁移效果」，不证明按章合并提取能降本（第 5 节阶段 1）。

## 10. 备忘（细节，本轮不议）

- **卡的格式**：R/I/A1/A2/E/B 六段。
  - R 段沿用试点：英文摘句加中文翻译，每条不超过 60 个英文词，每卡不超过 150 词。
  - 篇幅：2–3 个分支 3000–5500 字符，4–5 个分支不超过 7500。
- **入口写一句**：原书未说明处可以给自己的建议，标明不出自本书。
- **回答对比的计划要点**（跑前给用户看，含题数和报价）：
  - 评分项由不参与写卡的子代理按读者任务写，不按方法单元写；
  - 每题盲评判「更好、持平、更差」并写差异；0–3 分（对不对、具体不具体、有没有编造、原书没说时还能不能帮上忙）只作记录；
  - 每格跑 2 次，矛盾记未决；
  - 题目覆盖两组，旧覆盖组含另外三本书受影响的能力；
  - 在真实插件环境里跑：无界面的 Claude Code 加载插件副本，从 description 激活开始；加载方式在第 7 节第 1 步定；
  - 单次运行约 13 万子代理 token（试点 14 次约 178 万），每题新旧各 2 次加评分约 60 万；要省可以改走 Max 附赠的 API 额度，先测单价。
- **可达测试**：独立出题，机械期望作参考答案，按能否完成任务判；加诱饵题；沿用全书测试的脚本。
- **提取阶段怎么分工**（每段章节一个子代理，还是按类型）：做 Schell 时再试，按同等范围比成本。
- **脚本**：
  - PDF 转文本：试点用 PyMuPDF 按字体还原章节，字体映射要按书调；
  - 摘句与页码核对；
  - 覆盖与去向审计；
  - 复核结论写回，以及复核结论到最终卡的核对；
  - 引用链检查。
  - 都带测试，进 `pytest` 的 testpaths。
- **工作目录放仓库外**，skill 里写明全书文本不进仓库。
- **宿主**：Codex 支持子代理，能不能用看宿主配置。skill 里写明各宿主怎么跑、没有独立上下文时怎么标。
- **术语表**：`game-design-theory` 没有统一的术语表，要不要建再议。
- **成本口径**：按「子代理个数 × 固定开销 + 实际读写」来估。
