# 玩家感知与反馈

## 8. 玩家感知到了才算做完

- 玩家说「X 太弱、没生效、看不懂」时，先查 X 实现了没有、有没有数据，再查玩家看不看得见，最后才调数值。
- 设计里写的高光时刻，要确认它真的出现在玩家会走的路径上，而不是只在模拟里生效。资产是二进制的引擎项目里，文本搜不到调用不能判定「没接入」，要走引擎入口或实际运行去验证。
- 一个新机制，逻辑、反馈文字、教学、视觉四层都在才算完整。
- 验证功能能不能被认出来，要按最坏的呈现条件验：最小尺寸、最远视角、最短停留时间。停留不到 0.5 秒的纯视觉信息几乎一定看不到。
- 玩家看得到的标签（预告、描述、名称），情绪倾向要和实际体验一致。
- 随时间积累的数值，至少要有 3 档能感觉到的变化。难度断崖比整体偏难更伤人。新威胁第一次出现，要安排在有安全网的时段，并配一次首见提示。
- 「看不到、不会用」这类问题，先查可供性（看不看得出能点、是不是让玩家先困惑再给答案），再考虑加闪烁、加亮度。「看不懂」先分清是心智模型冲突还是教学缺失；如果是前者，加文字没用。
- 行动教学胜过文字教学。只对新手生效的逻辑归到教学层。
- 一个手动操作要从决策、反馈感知、参与感三方面评估，三项都为零才自动化。
- 改动前写明受众是谁、在什么条件下能碰到、触达率多少；接触率低于一成，等于没做。新手期按玩家实际经历的秒数算，不按关卡或波次算。

## 9. 反馈与界面的判断标准

- 要拉大差异，不要统一放大；用具体数字，不用抽象倍率。
- 信息出现在玩家做决策的地方；反馈同时给出当前值和变化值。
- 按下反馈（可供性）、状态指示和教学三者分开设计。
- 随机爆发要有预告、触发、结果三段表现。常驻警告必须有「做对了就消失」的路径。
- 视觉优先级看同一屏里有多少个，而不是单个有多醒目；加标记前先估一下最密集的时候同屏会有几个。
- 按「感官通道 × 时间段」检查反馈的分布。
- 文案要对应到玩家此刻已经能看到的画面。
- 节奏靠低谷来调：休息是增速放缓，不是倒退。
- 一般原则见 game-ui-design；这里补的是具体判据。
