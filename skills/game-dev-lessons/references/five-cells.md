# 五格：从问题行开始的设计项检查表

**它防什么。** 推理链的五种毛病：从比喻起步、链越长越像对、抽象藏错、自己查自己、看不见链外。再加一种：讨论一开始就默认某个设计一定要做。

**什么时候用。** 讨论或方案里出现新机制、新状态、新规则、新文案，或改动现行规则的一条，就是一条「设计项」，每条单独填一张。先填问题行；问题行没过，设计项不填。两处固定时刻：稿子送出去之前（给评审或拍板人）五格填满；落册之前，第 4 格要有填稿人以外的答案，第 1 格标签要是事实、原话或观察。

## 问题行（先于一切设计项）

| 栏 | 填什么 |
|---|---|
| 现象 | 谁、什么时刻、遇到什么。写观察到的事，不写想要的机制 |
| 来源 | 四选一：事实（原文或数据，给出处）、用户原话（引原话和日期）、试玩观察（谁、什么时候看到）、比喻或猜（别的游戏这么做、从别的条推出来、一句概括性说法） |
| 不改会怎样 | 现在有什么在处理它（已有机制、规则、道具、系统）；损失是什么 |
| 判定 | 成立且现有机制不覆盖：开设计项。不成立，或已被覆盖：不开，进点子库或备忘。来源是比喻或猜：先去观察或试玩，不开 |

默认结论是不开。从设计开头的讨论（「准备大改 X」）先倒填问题行，填不出事实或观察就停在「去看」，不进框架轮。设计者的目标（「想让玩家更合作」）可以当来源，但目标不是缺口：问题行要再答一句「这件事现在发生了多少」。

## 五格（每条设计项）

| 格 | 填什么 | 不许怎么填 |
|---|---|---|
| 1 体验 | 谁、什么时刻、感到什么。起点标签四选一同问题行，另加「随上级」：这一项是上一项的必然后果、自己没有起点，判定写「随 X」。起点要往上追到最早那一句。用户原话若只是机制句（「X 不进 Y」），第 1 格仍算空，判定是回问一句体验，不是砍。从比喻生成的选项被用户选中，起点仍记比喻，选择另记一笔 | 不许把机制写成体验；找不到出处就标比喻或猜，不替它补猜出处 |
| 2 不提供会怎样 | 对着「维持现行」答：现行做到多少、差多少；现在有什么在干这件事。固定再问两句：现行文档有没有把这题标成暂定、待试玩、回审；裁决单里哪个选项等于现状 | 不许用「可以增加…」这种收益句回答；答不出就写答不出 |
| 3 设计 | 一句话规则，加两个实例：一个顺路，一个带现行的锁或占用（满了、占着、叠满、锁住）。规则有分支的每个分支各一个。写「沿用」的地方把被沿用的原句抄过来对。没选的版本写一行；维持现行不算备选，它在第 2 格 | 实例要有具体的名字、数字、时刻；填不出就写填不出 |
| 4 达成了吗 | 谁答、凭什么。凭据只认四种：填好的表、模拟、试玩数据、设计原文。填稿人以外的人可以答，每个结论带凭据。答不了的分两种写：待试玩（写明看什么、谁记）；无法验证 | 不许凭「读起来合理」答是 |
| 5 副作用 | 三行：消费者（谁引用这条；草稿阶段可只写搜索式和命中文件数，逐条留给落册）；推翻了哪条已拍裁决；和别的条矛盾在哪。按对象搜（「地上有鱼」），不只按规则名搜（「祭坛」）。写清查到的、查过没碰到的、没法查的 | 不许只写「无明显副作用」 |

## 判定

- 问题行没过：不填设计项。
- 第 1 格比喻或猜，或第 2 格答不出：待拍，默认建议砍。第 1 格是用户原话但只是机制句：回问。
- 第 3 格填不出：砍或退回重写。
- 第 4 格待试玩：不进真值，进备忘记成假设、写明试玩看什么。无法验证：砍。
- 其余：留。随上级的项写「随 X」。
- 五格过了不等于要做。问题行成立、设计项过了五格，仍由拍板人定；五格给的是「不是砍的理由」，维持现行始终是正式选项。

## 输出格式

1. 问题行一张。
2. 总表：项目 | 起点标签 | 判定 | 死在哪格 | 一句话原因。
3. 每项一节：五格表（格 | 内容，每格一到三句，引出处「文件:节」或行号），然后判定。
4. 「对五格本身的评价」和「查过没问题的」。

中文；不写套话；不确定就写不确定。
