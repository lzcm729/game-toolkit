# 建模—推演—验证—更新：数值问题的工作环

## 一句话

数值问题不靠「跑一批看看」回答。先把机制写成一个能算的模型，用它算出每一格的预期并**写下来**，再去跑；跑完逐格对照，对的算对、错的算错，**结果和模型不符先修模型，再选下一批**。一轮试验回答一个问题，环一直转到问题答了或胃口用完。

**REQUIRED BACKGROUND：** game-dev-lessons 的「数值模拟与调参」（样本量、杠杆极值、快慢工具分歧）与「五格」（问题行：现象、来源、不改会怎样）。本 skill 不重复那些判据，只定工作环的形状。

## 什么时候用

- 要跑模拟器、数值尺、批量自动化测试来回答平衡、强度、节奏、经济类问题
- 一个杠杆改了「没效果」，或两种策略的差距怎么调都出不来
- 刚拿到一批结果，要决定下一批跑什么
- 有人（包括你自己）说「先扫一遍参数再说」

不用于：没有数字的设计讨论；要不要加某机制的准入判断；一次性查某个值。

## 工作环（每一步都要留下东西）

| 步 | 做什么 | 留下什么 |
|---|---|---|
| 0 问题行 | 现象是什么、来源、不改会怎样；这一轮要回答的一个问题；判据与样本量先定 | 一句话问题 ＋ 写死的判据 |
| 1 建模 | 把机制写成能算的账：每个量写来源（代码常量、设计值、实测），校准项单独标出；**先用已有数据校准**，复现不了已有的格就先修模型 | 模型文件 ＋ 校准表（模型值对实测值） |
| 2 推演 | 用模型算出**每一格**的预期数字（不是区间感觉），写明算式和「什么结果算猜想错了、错会出在模型哪一项」 | 结果页里的「推演与预期」一节，开跑前写完 |
| 3 验证 | 最小批定方向（几场一格），确认批用**没用过的种子**；基线变过（合并、换版本）先跑复刻格，看旧结果还在不在 | 原始数据 ＋ 版本戳 |
| 4 对照 | 逐格把预期和实测放一张表：全中／方向对幅度错／错；错的写出模型哪一项错了 | 对照表 |
| 5 更新模型 | 改校准项或结构，重跑校准表，记下仍对不上的「已知缺口」；预期区间以后要为缺口打折 | 新版模型 ＋ 缺口清单 |
| 6 下一批 | 由更新后的模型选最能分辨猜想的格；结果不符时不在同一层换参数重跑 | 下一批的「推演与预期」 |

每批的记录模板、模型文件的骨架和一个精简例子见 [references/loop-template.md](references/loop-template.md)。

## 停机与升层

- 问题答了（判据过或明确不过），或胃口用完，就停；不因「再跑一批也许就行」续。
- 同一失败形态第二次出现，或连改三次结果不动：停在这一层，查改动真被执行到了没，然后退一层查前提、结构或测量工具。
- 三次按预期判据的确认都落在同一个数上，这个数就是上限，报它，不再找「还有哪个旋钮」。

## 常见错法

| 错法 | 为什么错 | 改成 |
|---|---|---|
| 把判据当预期（「X 要 ≥26/30 才算过」） | 判据不告诉你模型对不对；跑完只知过没过，不知道哪一项猜错 | 判据之外写模型算出的数字 |
| 预期写成凭感觉的区间 | 对了也不知为什么对，错了修不了模型 | 每个数带算式与来源 |
| 用合并各配置的分布当成与配置无关 | 节奏一变分布就变（如磨损随搏斗长度） | 校准用同配置的锚 |
| 几个固定种子跑出的「处处 100%」当定论 | 五个种子只是五个种子 | 确认批换没用过的种子、按样本量算区间 |
| 合并别人的改动后直接续跑 | 基线漂了，差异记到了你的杠杆头上 | 先跑复刻格逐场比旧结果 |
| 全程平均掩盖阶段（「顶着时每秒只掉 0.6%」） | 真僵持只占收线时间 2%～8%，平均把它抹平了 | 按阶段拆开量 |
| 结果不符就换一个参数再跑 | 模型错着，再跑多少都是在错的地图上搜索 | 先修模型、重跑校准表 |
| 直觉与模型相反时信直觉 | 直觉没有算式可查 | 两个都写下，让数据判，赢的留 |

## 报告怎么写

每批一节：跑前写死的预期 → 实测表 → 逐格对照（全中／方向对幅度错／错，错在模型哪项）→ 模型改了什么 → 下一批。给决策者的收口只写：验过的猜想对错清单、能用的结论（带上限）、剩下要拍的几个方向各一句后果。
