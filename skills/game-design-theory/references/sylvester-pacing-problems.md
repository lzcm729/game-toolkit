# 节奏问题诊断：空档、溢出、单调

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Too little, and it drains out within seconds and boredom sets in. Too much, and it overflows, breaking flow.
>
> 译：倒得太少，几秒内就流干，无聊随之而来；倒得太多，杯子就会溢出，心流被打断。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Decisions and Flow, p.140

> A FLOW GAP is a period of time—whether a second or an hour—when the player’s mind has nothing to chew on.
>
> 译：断流空档（flow gap）是玩家脑子里无事可想的一段时间，不管它是一秒还是一小时。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Avoiding Flow Gaps, p.142

> The only hard-and-fast rule of flow pacing is that it should vary. Neither bore the player with long, slow periods, nor exhaust him with long, fast ones.
>
> 译：心流节奏唯一的铁律是要有变化。既不要用长时间的慢段让玩家无聊，也不要用长时间的快段把他累垮。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Decision Variation, p.146

## I — 方法骨架 (Interpretation)

这张卡回答「玩家觉得拖、累、腻，问题出在哪、怎么修」。作者的模型：玩家的心智像底部有洞的小杯子，决策是倒进去的水，要按合适的大小和时机不断倒；太少，几秒就流干、开始无聊，这是空档（flow gap）；太多就溢出（overflow）。两种都会断掉心流（p.140）。决策规模（decision scope）指想清一个决定要花多少心思，分级见 `sylvester-decision-rhythm-mapping.md`。

作者观点（参考单元）：最要紧的设计错误是打断心流的错误；有了心流，玩家能接受怪虚构、粗画面、不清楚的交互（p.139）。这是作者的经验判断，未经验证；原文也没给判断某条抱怨是否由心流中断引起的方法，所以本卡不做这种归因，也不负责给一轮试玩问题排序。

四个分支按症状分流：无事可想的时段 → 分支 1；被决策淹没 → 分支 2；回合制里操作比思考久、或有人长考 → 分支 3（回合制由玩家自定节奏，空档和溢出的表现不同，p.144）；一直一个调子 → 分支 4。

## A1 — 书中案例 (Past Application)

- **分支 1｜法杖与眩晕（例题 + 转述，p.142–144）**：为平衡给法杖两秒一发的限制，两发之间无事可做就是空档；修法是充能时还能移动、用刀。眩晕改干扰式的三例：MW2 眩晕弹降低转向速度、晃视角；老街机颠倒方向键；CS 闪光弹白屏但操作照常，可凭记忆站位、听脚步。**CS 的两种停顿（作者分析，p.149, p.153）**：观战时定下一局策略，时间长但被大决策填满，不算空档；死亡后的等待有时长于定策略所需，作者称之为该作的设计缺陷。
- **分支 2｜原书未提供案例，以下是合成演练**：手机即时塔防第 8 波同时来三种敌人；设计者定的最低技能水平是「玩过至少一款塔防并完成教程」。两名没玩过塔防的试玩者抱怨，落在最低水平以下，记为可接受；一名老玩家也说太乱，落在目标范围内，要减压。
- **分支 3｜原书未提供案例，以下是合成演练**：4 人数字桌游每回合逐个移动 20 个工人，移完约 60 秒、想清约 10 秒，判为微操；后期单人回合常超 3 分钟，其他人干等，按多人桌游这一条件判为致命的分析瘫痪。
- **分支 4｜调兵与选址建厂（例题，p.145）**：两类决策规模相近、题材不同，交替出现比反复一种有意思。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 加了冷却、动画、过场、控制技能后，觉得拖或憋屈。
2. 试玩者手忙脚乱、抱怨压力大。
3. 回合制每回合要操作很多单位，或有人一想就是几分钟。
4. 一整段都是同一种遭遇、同一个速度。

**语言信号**

- 等待太多 ／ 过场太长 ／ 冷却时没事做 ／ 被控住什么都做不了 ／ 死了要等很久 ／ 太累 ／ 手忙脚乱 ／ 回合太慢 ／ 微操太多 ／ 一直一个调子
- flow gap ／ downtime ／ cooldown ／ stun ／ overwhelmed ／ micromanagement ／ analysis paralysis ／ monotonous pacing

**与相邻卡的区分（初稿）**

- 要整段测绘节奏、逐秒拆解、实现前推演 → `sylvester-decision-rhythm-mapping.md`
- 这里根本没有决策、只有一条路 → `sylvester-decision-quality-audit.md`
- 平衡给哪个技能段 → `sylvester-balance-target.md`
- 玩家在领奖、通关等节点因没了盼头而离开 → `sylvester-reward-schedule-diagnosis.md`
- 一轮试玩反馈怎么解读、先信哪条 → `sylvester-playtest-observation.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 等待、冷却、过场、被控、死后等待 | 分支 1 |
| 试玩者被淹没、压力大 | 分支 2 |
| 回合制太慢、操作太碎、有人长考 | 分支 3 |
| 一直一个调子，或某段太长太慢、太长太快 | 分支 4 |

### 分支 1：Flow gap 排查与修复阶梯

- **输入**：玩家不能行动或无事可想的时段：平衡用的冷却、菜单过渡、移动动画、对话、控制剥夺、等待，以及各自时长。实时游戏适用；回合制 → 分支 3。
- **步骤**：
  1. 列出这些时段（p.142–143, p.153）。作者的经验估计：一秒的空档玩家也感觉得到，空档够多，流畅的体验会退化成走走停停（p.142）。完成标准：候选清单。
  2. 排除被决策填满的：时间长但决策大到填满了它，不算空档（p.149）；等待超过玩家想下一步所需的时间，多出的部分是空档（p.153）。想清要多久，可用 `sylvester-decision-rhythm-mapping.md` 分支 1 的经验秒数估。完成标准：每个候选标「空档 / 已填满」。
  3. 按阶梯修（p.143）：能删则删，要取舍时多数游戏从持续的心流里得到的比花哨过渡和动画多；删不掉就往里填决策，有时只要让别的能力可用；控制类把冻结改成干扰，让受害者仍能行动、做决定（p.143–144）。完成标准：每个空档对应一级修法。
- **判停 / 转向**：最好的办法是找到既好看又保住心流的设计（p.143），阶梯只在必须取舍时用。
- **输出**（约定）：表，列为「时段 / 来源 / 是否空档 / 修法」。

### 分支 2：Overflow 识别与按最低技能水平归类

- **输入**：试玩记录（谁、在什么时刻抱怨或显得紧张）；设计者选定的最低技能水平。没有就请设计者定，原文没给选法，本卡不替他选。
- **步骤**：
  1. 盯住 overflow：玩家被决策淹没的时刻，表现为抱怨、显得紧张的试玩者（p.144）。完成标准：时刻清单。
  2. 记下每次发生者相对最低技能水平的位置，标「低于最低水平 / 在目标范围内」（约定，由 p.144 推出）。依据：成品里的 overflow 多出在技能较低的玩家身上，总有人技能低到没法玩，作者说这一定程度上不可避免，主张刻意选定最低技能水平、围绕它设计，而不是想包括所有人（p.144）。完成标准：每次标一类。
  3. 原文的做法只是盯住 overflow、出现时降低决策压力（p.144），没有按技能分开处理。本卡的分法（约定，由 p.144 推出）：在目标范围内的减压；低于最低水平的记为可接受，依据是作者说这一部分一定程度上不可避免，他没有说让记为可接受。完成标准：每次一个处理决定。
- **判停 / 转向**：本分支只承诺识别、归类和「接受 / 减压」的决定。具体怎么减压原文没给，由设计者定。
- **输出**（约定）：表，列为「时刻 / 试玩者技能 / 归类 / 处理」。

### 分支 3：回合制决策规模诊断

- **输入**：确认是回合制：玩家自己控制决策节奏，但决策规模仍然要紧（p.144）。每回合执行操作的耗时、想清怎么做的耗时；单人回合时长；人数；作品定位的节奏。
- **步骤**：
  1. 微操：小规模决策太多，要反复挪动几十上百个几乎无意义的单位；挪动的时间超过决定的时间，玩家就经历空档（p.144）。完成标准：两段耗时及比较。
  2. 分析瘫痪：决策规模太大，玩家长时间枯坐（p.145）。完成标准：标出长考的决策。
  3. 判是否致命：象棋里不一定是问题；多人桌游、本该快节奏的游戏里会毁掉体验（p.145）。完成标准：写明属于哪类。
- **判停 / 转向**：本分支只做两种诊断和严重度判断。原文没给修法，记为开放问题；「太久」没有时长阈值，由设计者定。
- **输出**（约定）：两种病各自的判定与证据。

### 分支 4：决策节奏要有变化

- **输入**：一段游玩里决策的密度、规模、题材，按时间排开。时间线可用 `sylvester-decision-rhythm-mapping.md` 的逐秒推演或追踪得到。
- **步骤**：
  1. 找单调段：同规模的决策长时间按同一速率出现，心流还在，但拖沓重复；作者的反例是一小时每四秒一个 tactical 决策（p.145）。完成标准：单调段清单。
  2. 找过长的慢段、过长的快段（p.146）。完成标准：候选清单。
  3. 从三处给变化（p.145）：密度；规模，比如一串 twitch 决策、一个不限时的 profound 决策、几个五秒的 tactical 决策；风味，规模相近、题材不同的交替出现。完成标准：每段至少一条变化方案。
  4. 经典强度曲线（慢起、几轮起伏、高潮、收尾，p.145）只作参考。系统丰富的游戏常随机多次高潮，或有纸面上嫌长的慢段，作者说这不成问题（p.145）。完成标准：不把「不合曲线」列为问题。
- **判停 / 转向**：「长」没有时长标准，由设计者或试玩判断。作者说 CS 的高压段若远超 10 秒可能开始累人（p.153），这是对该例的单一观察，不是阈值。
- **输出**（约定）：单调段与过长段清单，加变化方案。

## B — 边界 (Boundary)

**不要用这张卡**

- 要测绘一段的节奏而不是修已知症状 → `sylvester-decision-rhythm-mapping.md`；决策不存在 → `sylvester-decision-quality-audit.md`；目标技能段之争 → `sylvester-balance-target.md`。
- 给一轮试玩问题排优先级，或判断某条画面、剧情抱怨是不是心流断了引起的：原文没有归因方法，本卡不做（见 I 段作者观点）。

**作者警告的失败模式**

- 为平衡加的延迟造出空档（p.142）；冻结式眩晕（p.143）；死后等待长于所需思考（p.153）。
- 按熟练测试者调节奏，低水平玩家被压垮；想包括所有人（p.144）。
- 微操与分析瘫痪（p.144–145）；节奏一成不变（p.145）。

**适用限制与推导说明**

- 作者观点：「最要紧的错误是打断心流的错误」（p.139）是经验判断，未经验证。
- 分支 1：「一秒的空档也能察觉」是作者的经验估计（p.142）。只适用于实时游戏，回合制走分支 3。原图缺失（转换时丢失）：CS 的决策节奏图，回合间空档的判断靠正文（p.149, p.153）。
- 分支 2：作者明说不再展开 overflow（p.144），减压手法只能由杯子比喻推出（少往杯里倒）；选最低技能水平没有原文判据；accessibility 只讲技能和知识门槛，不涉及身体或感官障碍。回合制压力过大的表现是分析瘫痪而非 overflow（p.144–145），走分支 3。
- 分支 3：只诊断不修；分析瘫痪没有时长阈值。
- 分支 4：原图缺失（转换时丢失）：经典强度曲线图在第 1 章（p.37），那里的文字是钩子、上升、高潮、收尾，第 5 章多了「几轮起伏」（p.145）；10 秒是 CS 的单一观察，不是阈值。
