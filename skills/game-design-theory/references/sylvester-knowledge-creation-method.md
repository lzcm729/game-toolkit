# 知识创造：选方法、辩论与测试类型

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Think of each method as a card we can play. Different cards have different effects and consume different resources. … Mastering design process means knowing which card to play, and when. … In reality, there is no simple algorithm for knowledge creation.
>
> 译：把每种方法想成一张可以出的牌。不同的牌效果不同，消耗的资源也不同。……掌握设计过程，就是知道该出哪张牌、什么时候出。……现实里，知识创造没有简单的算法。
>
> — Tynan Sylvester, *Designing Games*, Ch12 Knowledge Creation / Knowledge Creation Methods, p.311–312

> Debate has a specific purpose: it finds flaws in ideas. … Productive debate requires a very specific combination of skills and social conditions.
>
> 译：辩论有专门的用途：找出想法里的缺陷。……有成效的辩论，需要一组非常特定的技能和社会条件同时具备。
>
> — Tynan Sylvester, *Designing Games*, Ch12 Knowledge Creation / Debate, p.315

> The term focus testing is often mistakenly used as a synonym for playtesting. This is incorrect. … It doesn’t require a working game.
>
> 译：焦点测试常被误当成试玩的同义词。这是错的。……它不需要一个能玩的游戏。
>
> — Tynan Sylvester, *Designing Games*, Ch12 Knowledge Creation / Testing, p.316

## I — 方法骨架 (Interpretation)

这张卡回答「这个未知该用什么办法弄清楚」。作者认为游戏是一套知识，设计难在发明和打磨关于设计的知识，不在把它做出来（p.311）。弄清一个未知的办法叫知识创造方法，每种像一张牌，各有效果和代价；选牌没有算法，只能对照每张牌的效果、代价和前提来选（p.312）。

分支 1 是总入口：把每个未知对到候选的牌，写明理由。出的牌是辩论时进分支 2，先核对四个条件；出的牌是测试时进分支 3，按问题选测试类型。分支 2、3 也可以直接进入。

作者观点（参考单元）：反刍指长时间琢磨一个问题，包括无意识的琢磨，靠知识储备和放松（p.312–313）；研究分定向研究和扩充储备的半随机研究（p.313–314）；艺术方法是边画、边写、边做，让错误和限制逼出新想法（p.314–315）；现成方法答不了就自创（p.318）；莱特兄弟把资源投在真正缺的控制知识上，而 Langley 投在容易花钱的发动机上（p.320）；三步迭代环是过度简化，过程只能规划大笔触（p.321）。

## A1 — 书中案例 (Past Application)

- **分支 1｜莱特兄弟（转述，p.318–320）**：几年里用计算、野外测试、实验室测试、反刍、争论、研究，每架滑翔机、每片翼型都为回答一个具体问题而做；自建风洞测了 200 种翼型，全尺寸滑翔机试错太贵时改造自行车装置做测量。1903 年动力飞行，1905 年飞行 40 分钟。
- **分支 2｜原书未提供案例，以下是合成演练**：主策想和一位初级策划辩后者的「手牌上限随回合增长」方案。目的是找缺陷，适合辩论；两人只玩过同一款竞品，多样性弱；主策过去评审时常叹气，是作者点名的反面信号。记两条不满足，建议换一位与提案人无上下级关系、背景不同的策划来辩。
- **分支 3｜原书未提供案例，以下是合成演练**：三消手游列了四个问题：新连锁加分会不会让后期太容易、引导里的滑动手势会不会做、第 12 关闪退、玩家喜不喜欢猫咪咖啡馆主题，依次归为 playtest、usability、QA、focus test。有人提议「开个 focus group 看连锁规则好不好玩」，标为误用。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 评审卡在一个问题上，不知道该开会讨论、找资料、做原型、写分析还是找人测。
2. 准备开一场设计争论会，想找出某个方案的漏洞。
3. 写测试计划，要定这次做哪种测试。
4. 团队打算用头脑风暴来定方案，或想用焦点小组判断好不好玩。

**语言信号**

- 这个问题怎么弄清楚 ／ 要不要开会讨论一下 ／ 来个头脑风暴 ／ 拉几个人辩一辩 ／ 做个焦点测试 ／ 这次测试该测什么 ／ 可用性测试和试玩有什么区别
- how do we find out ／ brainstorm ／ debate the design ／ focus group ／ usability test ／ QA vs playtest ／ knowledge creation

**与相邻卡的区分（初稿）**

- 试玩怎么组织、找谁、测几场 → `sylvester-playtest-protocol.md`；试玩现场怎么看、怎么问 → `sylvester-playtest-observation.md`
- 已经决定用数据，要定埋哪些点、怎么读 → `sylvester-metrics-and-telemetry.md`
- 大决定怎么定、谁拍板 → `sylvester-complex-decisions.md`、`sylvester-natural-authority.md`
- 开发流程、规划视距 → `sylvester-process-and-planning-horizon.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 有几个未知，不知道各用什么办法弄清 | 分支 1 |
| 打算开辩论或争论会找漏洞 | 分支 2 |
| 要做测试，不确定该做哪种 | 分支 3 |

### 分支 1：按当前未知选方法（u12-01）

- **输入**：要消除的未知清单；可用的资源（人数、时间、有无可玩版本、有无埋点和大样本）。资源说不清先问。
- **步骤**：
  1. 每个未知写成一个问题（p.311）。完成标准：一行一个问题。
  2. 标出要哪类知识：大量新点子、想法的缺陷、细节推敲、设计在游玩中怎样运作、界面操控、技术缺陷、试玩看不到的小差异或罕见情况（由 p.312–318 各牌的效果归纳）。完成标准：每个问题一类。
  3. 列候选牌，写上作者给的效果和代价（p.312–318）：反刍结果出现的时间无法预测，可交替处理几个问题；研究分定向和半随机；艺术方法边做边出点子；头脑风暴快速出量、质量参差，很不适合精炼；书面分析逼出细节、可用统计或数学，深度分析可能要几周，有时值得，因为得到随口猜不出的知识；辩论专找缺陷；测试各类返回不同知识；metrics 看小失衡和罕见情况；现成方法都答不了就自创。完成标准：每个问题至少一张候选。
  4. 查前提：辩论走分支 2；metrics 要埋点和大量对局（p.316–317）；不满足就换牌。完成标准：每张候选标「满足 / 不满足 / 不确定」。
  5. 拦误用：用头脑风暴精炼（p.315），把 focus test 当 playtest（p.316）。
- **判停 / 转向**：几张牌都合适时先出哪张，原书未说明，作者明说没有简单算法（p.312），写明取舍由设计者定。想要唯一正确的方法或固定先后，本分支给不了，只产出带理由的候选。
- **输出**（约定）：表，列为「问题 / 要哪类知识 / 候选方法 / 效果与代价 / 前提是否满足」。

### 分支 2：辩论前核对四个条件（u12-05）

- **输入**：要辩的想法；参辩者、彼此的上下级关系和背景；会上有无惩罚异议的信号。
- **步骤**：
  1. 确认要的是找缺陷（隐藏假设、逻辑谬误）；要的是出量就回分支 1（p.315）。
  2. 逐条核对，对照作者给的反面信号（p.315–316）：
     - 双方会辩：能快速有效地攻防；差的辩手会去攻强论点、漏掉对方的谬误
     - 思想多样：知识、观点、经历、假设各不相同；作者说组织里少见，要刻意培养
     - 彼此尊重：能把个人情绪和论证分开，否则会毁掉关系、适得其反
     - 互不畏惧：有上下级时上级要先证明自己公正；惩罚异议（包括不自觉地叹气、翻白眼）会让人对上级的坏主意手下留情

     完成标准：四条各写「满足 / 不满足 / 无法判定」及依据。
  3. 权力不对等的，建议改由彼此没有权力关系的人来辩（p.316）。
- **判停 / 转向**：多会辩算会辩、上级怎样证明公正、其余条件不满足怎么补，原书未说明；是否仍开辩交还设计者，卡里不编做法。四个条件按有上下级的团队写，单人开发不适用。
- **输出**（约定）：四行核对表加一条建议（照开 / 换人 / 交设计者定）。

### 分支 3：按要回答的问题选测试类型（u12-06）

- **输入**：这次测试要回答的问题；有无可玩版本。
- **步骤**：
  1. 逐个归类（p.316；playtest 的用途见 p.295）：
     - 设计在游玩中怎样运作：哪里困惑、太易太难、是否平衡、有无退化策略、叙事看不看得懂 → playtest；它不是用来找技术问题或收市场数据的
     - 界面与操控 → usability test：让一个真实用户面对界面，看他怎样尝试使用
     - 技术 bug → 专职测试员做 QA test
     - 产品点子的市场反应 → focus test：小组讨论产品点子，不需要能玩的版本

     完成标准：每个问题归一类。
  2. 标误用：拿 focus test 回答玩法问题（p.316）。
  3. 现成测试都答不了，回分支 1 考虑自创方法（p.318）。
- **判停 / 转向**：交界问题（玩家没看懂，可能是规则也可能是界面）原书没有分法，由设计者判断或两类都做。playtest 怎么执行见 `sylvester-playtest-protocol.md`；其余三类的执行流程原书未说明。
- **输出**（约定）：表，列为「问题 / 测试类型 / 是否要可玩版本 / 误用标记」。

## B — 边界 (Boundary)

**不要用这张卡**

- 已经定了做试玩，问的是协议和测试者 → `sylvester-playtest-protocol.md`。

**作者警告的失败模式**

- 用头脑风暴精炼想法，得到更多良莠不齐的点子（p.315）。
- 被权力压住的辩论被当作「已经找过漏洞」；第 15 章说坏氛围会让人不提冒险的点子、不开必要的辩论（p.355）。
- 把焦点小组的讨论当作试玩结论（p.316）。

**作者盲点与时代局限**

- 四个辩论条件是作者的经验主张，没有引研究。
- 作者在第 10 章讲过 Doll House：1993 年的焦点小组评价它是四个点子里最差的，它后来成了 The Sims（p.253–254）。焦点测试对创新设计的预测力有限。
- 莱特兄弟对 Langley 有幸存者偏差（批判节）。
- metrics 的例子是大工作室和公测规模，小团队怎么办原书未说明；遥测、自动模拟只一笔带过；metrics 不在四类测试里；成书于 2012 年前后。

**各分支的已知缺口**

- 分支 1：牌之间没有排序；头脑风暴作者不展开流程，书面分析何时值得只说 sometimes。
- 分支 2：四条只有定性描述和反面信号，没有正面标准。
- 分支 3：四类各只有一两句定义，不能编 usability、QA、focus test 的执行流程。
