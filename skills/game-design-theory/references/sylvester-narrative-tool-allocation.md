# 叙事手段分配与脚本事件

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Our narrative tools divide roughly into three main classes: scripted story, world narrative, and emergent story.
>
> 译：我们的叙事工具大致分成三大类：脚本故事、世界叙事、涌现故事。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Narrative Tools, p.83

> Every scripted sequence must balance player influence with designer control, and there is a whole spectrum of ways to do this. Which to choose depends on the story event being expressed and the game’s core mechanics.
>
> 译：每段脚本序列都得在玩家的影响和设计者的控制之间取平衡，做法是一整条光谱。选哪种，取决于要表达的剧情事件和游戏的核心机制。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Soft Scripting, p.84

> The integrated story that the player experiences arises emergently from the interaction of scripts, game systems, and the player’s decisions.
>
> 译：玩家经历的那个完整故事，是脚本、游戏系统和玩家决定相互作用涌现出来的。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Case Study: Fallout 3 / Breakdown, p.113

## I — 方法骨架 (Interpretation)

这张卡回答「这块故事用什么手段讲」「必须当场发生的剧情怎么演才不被玩家搞坏」「一段游玩里的叙事怎么拆」。叙事工具（narrative tool）指在玩家脑中形成一块故事的装置（p.83）。三类：脚本故事是写死在游戏里、每次一样的事件，最基本的是过场；软脚本（soft scripting）在脚本演出时保留玩家的部分操作。世界叙事用地点和物件讲过去；涌现故事在玩法中由机制和玩家生成。

各工具的代价不同：过场全控，但必然打断心流；软脚本不断心流，设计者却失去控制；世界叙事只能讲已经发生的事，玩家干扰不了；涌现可以无限生成，也是唯一能跨过虚构与现实的工具，但设计者只能间接著作。作者没给分配规则，所以卡只列选项和代价，由设计者选。

三个分支：分支 1 在规划期逐片段列工具；落到脚本的片段进分支 2，定载体、控制档位和干扰预案；分支 3 是事后复盘，拆一段已有的游玩，把改进点交给相邻卡。

## A1 — 书中案例 (Past Application)

- **分支 1｜第一次赢哥哥的棋局（例题，p.91–92）**：讲给朋友听时，主线是他和哥哥关系的变化，不是那几步妙棋。这是玩家人生里的真故事，设计者替玩家写不了人生，只能靠涌现。原书没有逐片段的分配案例。
- **分支 2｜小巷谋杀与光谱三例（例题 + 转述，p.84–85）**：谋杀的每一刀都是预制的，玩家可以走过、驻足或逃跑，也可能射杀凶手或受害者、跳到他们头上、错过。光谱从最控制到最放任：Half-Life 开场电车只能走动、换窗看；Dead Space 2 脱轨车厢拿走移动、保留射击；Halo: Reach 只给 AI 预设战术提示。免干扰载体：定时邮件、玩家在别的房间时物件增减、广播。原书未说明结果。
- **分支 3｜Fallout 3 的 Super-Duper Mart（作者亲历，p.108–115）**：作者先讲故事，再拆。荒原、建筑和垃圾、尸体的摆放是世界叙事；Moira 的对话是硬脚本；战斗遭遇是软脚本。掠夺者是脚本放的，猎人是随机刷出的，两边碰巧交火。猎人临死的豪言被读成一次动人的交流，这是 apophenia。戴鹿角的掠夺者靠标签有了个性。作者指出的改进：大多数敌人没有身份标签。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 写叙事规划或剧情大纲，要定每段故事用过场、实机脚本、环境还是系统来讲。
2. 某个剧情节拍（处决、背叛、角色死亡）要在玩家在场时发生，担心被打断、被错过，或 NPC 被打死。
3. 过场太多，节奏走走停停，想改成实机或广播。
4. 复盘一次试玩，或拆竞品的叙事手法。

**语言信号**

- 这段用过场还是实机 ／ 玩家会不会把剧情打断 ／ NPC 说话时玩家开枪怎么办 ／ 过场太多了 ／ 拆一下这段游玩的叙事
- cutscene vs in-game ／ scripted sequence ／ soft scripting ／ player interrupts the scene ／ narrative tools breakdown

**与相邻卡的区分（初稿）**

- 世界叙事具体怎么布置、线索怎么分层 → `sylvester-world-narrative.md`
- 涌现故事怎么放大（标签、记录、解说）→ `sylvester-emergent-story.md`
- 内容先后、整体结构、分支数 → `sylvester-story-structure.md`
- 玩家胡闹的处理方式、NPC 对话方案 → `sylvester-desk-jumping-and-characters.md`
- 过场造成的空档、节奏单调 → `sylvester-pacing-problems.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 有一份故事内容，要定每块用什么手段讲 | 分支 1 |
| 某个剧情节拍必须当场发生；过场太多 | 分支 2 |
| 已有一段游玩，要拆出各手段起的作用 | 分支 3 |

### 分支 1：片段—工具—代价表（u04-02）

- **输入**：要讲的故事内容；本作的核心机制；表现方式（远景符号还是近景）。缺核心机制先问。
- **步骤**：
  1. 拆片段：背景史、当下的剧情节点、角色关系、玩家自己的经历等，每块是要在玩家脑中形成的一块故事（p.83；拆法参照 p.113）。完成标准：片段清单。
  2. 逐片段列可选工具及代价（p.84–92）：
     - 已发生的事 → 世界叙事：玩家干扰不了，不需线性顺序，由概括到细节支持重玩；只能讲过去和世界的状况。
     - 必须当下按意图发生 → 脚本：过场必断心流，过多会走走停停；软脚本保留操作，设计者失控；免干扰载体便宜。细化走分支 2。
     - 随玩家选择持续生成、或要跨虚构与现实（玩家自己的胜负、和真人的关系）→ 涌现：设计者只能通过机制定边界和倾向。作者观察：远景、数值符号表现的品类更容易，近景的射击和体育少见（p.94–95）。

     完成标准：每片段至少一个候选，写明代价。
  3. 交设计者选：作者只说看剧情事件和核心机制（p.84），几种性质冲突时没有优先级。完成标准：每行标「选定」或「待定」及理由。
- **判停 / 转向**：选了世界叙事 → `sylvester-world-narrative.md`；涌现 → `sylvester-emergent-story.md`；要和类人角色对话 → `sylvester-desk-jumping-and-characters.md` 分支 3。
- **输出**（约定）：表，列为「片段 / 候选工具 / 代价 / 选定与理由」。

### 分支 2：脚本事件的载体、档位与干扰预案（u04-03）

- **输入**：要表达的剧情事件；此时玩家手里有哪些操作；事件前后的游玩强度。
- **步骤**：
  1. 先查免干扰载体：定时到达的邮件、玩家在别的房间时物件或角色出现或消失、广播和喇叭；作者说它们有力、便宜，不用定制半交互序列（p.85）。完成标准：写明能否改用。
  2. 要玩家在场目睹，按光谱列档位和代价（p.84–85）：过场（全控，必断心流，可当激烈段之间的休息）→ 只能走动观看 → 拿走部分操作、保留其余 → 只给 AI 战术提示。完成标准：每档写代价，选哪档由设计者定。
  3. 软脚本逐项列干扰：从难看的角度看、完全错过、射杀凶手或受害者、跳到他们头上、被别的事分心（p.84）。完成标准：五项都过。
  4. 每项定应对方向：限制玩家行动、处理该情形，或改成事后的世界叙事；作者把前两项和自适应剧情列为现在时叙事的成本，都难做、都贵（p.88）。具体做法（忽略、虚构上禁止、纳入）转 `sylvester-desk-jumping-and-characters.md` 分支 2。
- **判停 / 转向**：过场多少算太多，原书未说明，只有「走走停停」的定性说法。
- **输出**（约定）：载体与档位决定，加「干扰 / 应对方向」表。

### 分支 3：先讲故事，再拆工具（u04-22）

- **输入**：一段实际游玩（亲玩或录像）；对实现的了解：哪些是脚本固定的、哪些是随机刷出的、AI 有没有意图。
- **步骤**：
  1. 用第一人称把这段游玩写成带情绪的故事（p.108）。完成标准：有开头、经过、结尾。
  2. 逐段标工具：世界叙事、硬脚本、软脚本、随机系统、apophenia、标签（p.113–115）。不了解实现的标「推测」。完成标准：每段都有标注。
  3. 标出同时运行的两条线：背景故事和玩家自己的涌现故事（p.113）。
  4. 用故事术语标小段弧线：铺陈、紧张上升、顶点、顿悟、解决（p.114–115）。
  5. 记下可改进处（如标签太少，p.115）和排序、节奏、设定起的作用（p.115–117）。完成标准：列出发现，没有就写「未发现」。
- **判停 / 转向**：不评价故事好坏。标签问题 → `sylvester-emergent-story.md`；排序、节奏 → `sylvester-story-structure.md`；设定 → `sylvester-world-narrative.md` 分支 4。
- **输出**（约定）：带工具标注的故事稿，加改进清单。

## B — 边界 (Boundary)

**不要用这张卡**

- 问故事本身好不好（情节、人物、主题）。作者声明自己不是专门的故事作者，本章只讲表达故事的工具（p.83）。

**作者警告的失败模式**

- 过场太多，游玩在操作和观看之间来回切，节奏走走停停（p.84）。
- 把关键剧情做成玩家在场时发生的事件，却没有预算处理玩家的干扰和路线差异（p.88）。

**作者盲点与时代局限**

- 工具分配和选档都没有规则；光谱只有三个射击、动作类先例；过场多少算太多没有阈值。
- 「近景品类少有丰富的涌现故事」是作者的观察（p.94–95），未经验证。
- 人际互动的论述写在大模型之前（p.106），涌现故事处理对话的限制可能已经变了。
- 分支 3 只有 Fallout 3 一个完整案例，作者的归因靠他对实现的了解。
- 作者观点（参考单元）：游戏看起来像电影，却不像电影那样运作；找叙事参照先看沉浸式戏剧、博物馆、遗址、犯罪现场（p.81–83）。原书没给从参照落到设计的步骤。
