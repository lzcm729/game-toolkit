# 故事结构与分支：排序、结构、分支数和可挂起任务

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Sometimes we want to ensure the setup occurs before the payoff. We might want to let one subplot play out before we add another so we don’t have too many plot threads running at once.
>
> 译：有时我们要保证铺垫出现在回报之前；也可能想让一条支线讲完再加下一条，免得同时有太多线头。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Story Ordering, p.96

> The problem with branching events is that the number of possible timelines rapidly explodes. Any given player experiencing the story misses most content.
>
> 译：分支事件的问题在于，可能的时间线数量会迅速爆炸。任何一个经历这个故事的玩家，都会错过大部分内容。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Story Structures, p.99

> In such an unpredictable environment, the game’s steady-with-spikes pacing might be the best solution because it is robust against being chopped up and reassembled.
>
> 译：在这么难预料的环境里，这款游戏「平稳加尖峰」的节奏也许是最好的办法，因为它经得起被切碎再重组。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Case Study: Fallout 3 / Pacing, p.116

## I — 方法骨架 (Interpretation)

多数叙事工具在顺序受控时更好用。作者列了三种排序需求：铺垫先于回报；一条支线讲完再开下一条；配合剧情逐个教机制（p.96）。排序装置分硬软两档：硬装置保证顺序，如关卡、任务、阻挡；软装置只鼓励大致顺序，保留开放感，如技能门槛、定时事件、进度开放、空间远近。

装置组合成结构。串珠（string of pearls）：每颗珠是一块可以自由活动的场地，珠与珠之间是单向过渡；珠子越大，内部自由度越高。轴辐（hub and spokes）：每根辐是一块自成一体的内容，彼此独立。分支：为每个决定建模所有后果。收束：分叉后再汇回一条线。混合结构把几种拼起来。

这几种结构原书各有示意图，原图缺失（转换时丢失），但正文对每种都有文字描述，本卡依正文写；手里有原书的可对照补图。

四个分支：分支 1 逐对内容定排序装置，是其余分支的底；分支 2 把装置组合成全局结构，用分支 1 的内容对；结构里有真分支时进分支 3 压分支数；结构里的任务能被挂起时，进分支 4 查节奏。

## A1 — 书中案例 (Past Application)

- **分支 1｜店主与勒索者（例题，p.97）**：任务内部顺序固定：见店主、找到黑帮、说服或揍他、回去领钱；整体随时可以开始和结束，也能半途挂起去屠龙再回来。阻挡不必是锁门：守卫要你先帮个忙，或者先关灯躲过摄像头。**MMO 的技能门槛（转述，p.97）**：理论上一开始哪都能去，但没有技能、装备和盟友就活不出新手区，于是既有巨大开放世界的感觉，又温和地把新人引过入门挑战。Dead Rising 让事件按钟点发生（p.98）。
- **分支 2｜四种结构实例（转述，p.98–100）**：Quake、Super Mario Bros.、StarCraft 单人战役是串珠；Mega Man 是轴辐；Mega Man 2 先轴辐（任意顺序打八个机器人头目），再线性（攻入 Wily 的城堡）；Mass Effect 2 首尾是串珠，中间 80% 是按技能和等级软排序的一大堆任务，一条主线任务贯穿其中，用分支和收束。作者列的好处：开头能精心引入故事和机制，中段玩家觉得自由，高潮能精心打造。原书未说明结果。
- **分支 3｜Moira 的对话树（转述，p.113–114）**：每次问候 Moira 都给同一组话题，话题结束就回到根列表。作者说这让对话树本身成了轴辐结构，以此避开无限分支。
- **分支 4｜Fallout 3 的节奏（转述，p.115–116）**：内容靠脚本和地形排序：先过停车场，再进大厅，然后药房，掠夺者在玩家探完药房后才从门口刷出。但玩家能做一半就走，20 小时后再回来。战斗尖峰夹在较长的对话、探索、治疗、搜刮之间。作者认为递进到高潮的曲线看起来更好，却会被切碎。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 排任务、章节、关卡的先后，开放结构里要保证某段先于另一段。
2. 定整体结构：线性关卡、自由选关、开放世界，还是混合。
3. 分支剧情写不过来，每个选择都要写后果。
4. 开放世界任务可以随时搁置，原本设计的情绪递进会被打断。

**语言信号**

- 剧情顺序怎么保证 ／ 玩家跳过铺垫直接到了后面 ／ 要不要锁门或卡等级 ／ 线性还是开放 ／ 分支太多写不过来 ／ 选项后果爆炸 ／ 任务能挂起，节奏乱了
- story ordering ／ gating ／ string of pearls ／ hub and spokes ／ branching narrative ／ story convergence ／ side quests ／ quest pacing

**与相邻卡的区分（初稿）**

- 某块故事用什么手段讲 → `sylvester-narrative-tool-allocation.md`
- 已发生的故事线索可自由发现、不需要排序 → `sylvester-world-narrative.md` 分支 2
- 剧情选项算不算有意义的决策 → `sylvester-decision-quality-audit.md` 分支 3
- 一段游玩里的空档、溢出、单调 → `sylvester-pacing-problems.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 某段内容必须在另一段之前 | 分支 1 |
| 要定或评审整体结构 | 分支 2（先做分支 1） |
| 分支剧情、对话树内容量失控 | 分支 3 |
| 任务可挂起，节奏设计会被切碎 | 分支 4 |

### 分支 1：排序装置表（u04-14）

- **输入**：需要先后的内容对。
- **步骤**：
  1. 列内容对，写明理由：铺垫先于回报；一条支线讲完再开下一条；配合剧情逐个教机制（p.96）。完成标准：每对有理由。
  2. 每对判断：顺序必须保证，还是大致引导就够（p.97）。原书没给规则，由设计者在开放感和确定性之间取舍。
  3. 必须保证的用硬装置：关卡；任务（内部顺序固定，整体可随时开始和挂起）；阻挡（锁门、守卫要你帮忙、摄像头）（p.97）。
  4. 只需引导的用软装置：技能门槛、按钟点发生的事件、进度达到后才开放的任务、空间远近（p.97–98）。完成标准：每对有装置和强度。
- **判停 / 转向**：作者说排序装置还有无数种（p.98），清单不穷尽。用任务排序、玩家又能挂起 → 分支 4。
- **输出**（约定）：表，列为「内容对 / 理由 / 装置 / 硬或软」。

### 分支 2：结构草图（u04-15）

- **输入**：分支 1 的表；游戏的大致段落。
- **步骤**：
  1. 用分支 1 的表给每段标排序手段。
  2. 每段选骨架，写内部自由度（p.98–99）：串珠，珠子越大越自由，太小会受限到失去意义；轴辐，各辐彼此独立；分支只在内容几乎全由涌现生成时可行，否则转分支 3。完成标准：每段有结构和自由度。
  3. 需要时分段混合：开头线性，引入故事和机制；中段软排序，让玩家觉得自由；结尾线性，精心编排高潮（p.100）。
  4. 中段是可挂起的任务堆 → 分支 4。
- **判停 / 转向**：没有选型规则，只有各结构的性质和混合的好处。珠子做多大、在哪切换、同时开几条线，原书未说明（只说别让太多线并行，p.96），由设计者定。
- **输出**（约定）：表，列为「段 / 结构 / 排序手段 / 内部自由度 / 依据的原文性质」。

### 分支 3：压分支数（u04-16）

- **输入**：剧情里的抉择点；每个抉择之后的内容是预先写好的，还是系统生成的。
- **步骤**：
  1. 判断内容几乎全部涌现生成，还是在相当程度上预先定义（p.99）。
  2. 几乎全涌现，才可以放任分支；只要相当程度上预先定义，就必须压分支数，否则时间线爆炸，玩家错过大部分内容（p.99）。完成标准：写明判断；按抉择数乘出朴素时间线数（约定）。
  3. 逐个抉择选压法（p.99，p.114）：
     - 支线：内容放在路边，可做可不做，对主线影响小；
     - 故事收束：主线分叉后再汇回一条；
     - 对话树：每个话题结束都回到根话题列表。
  4. 和分支 2 的结构合并，如 Mass Effect 2 的主线用分支加收束（p.100）。
- **判停 / 转向**：「相当程度」和可接受的分支数，原书未说明，保留几条真分支由设计者定。
- **输出**（约定）：表，列为「抉择 / 内容性质 / 压法 / 收束点」，附压前与压后的时间线数。

### 分支 4：可挂起内容的节奏（u04-24）

- **输入**：内容段落；玩家能否随时挂起、隔很久再回来。
- **步骤**：
  1. 判断能否挂起：任务做一半走开、20 小时后再完成（p.115–116）。
  2. 能挂起的，认定递进式强度曲线很可能被切碎重组，不要依赖它（p.116）。
  3. 改用平稳加尖峰：紧张的战斗落在较长的对话、探索、治疗、搜刮之间（p.116）。
  4. 把各段拆开打乱，检查每段单独仍然成立（据案例归纳）。
- **判停 / 转向**：作者说的是「might be」，不是最优解。改成不可挂起、保住递进曲线，划不划算，原书未说明。
- **输出**（约定）：节奏改法，附打乱检查结论。

## B — 边界 (Boundary)

**不要用这张卡**

- 已经发生的故事，线索靠自由探索拼起来，不需要排序装置 → `sylvester-world-narrative.md`。

**作者警告的失败模式**

- 朴素分支：为每个决定建模所有后果，时间线爆炸，每个玩家都错过大部分内容（p.99）。
- 珠子太小：线性游戏受限到失去意义（p.98）。

**作者盲点、缺图与跨章**

- 原图缺失（转换时丢失）：串珠、轴辐、朴素分支、支线与收束的结构示意图（p.98–100），分支 2、3 只能依正文描述。
- 作者没有结构选型规则，只有各结构的性质与混合的好处；排序装置清单作者自己说只是一部分（p.98）；例子集中在 PC 和主机的关卡制游戏、开放世界 RPG 和 MMO。
- 可接受的分支数没有标准。
- 分支 4 只有 Fallout 3 一个案例，措辞带保留。
- 原图缺失（转换时丢失）：第 1 章的经典节奏曲线图（p.37），正文写明是起钩、上升、高潮、收尾。
- 跨章：第 5 章说丰富的系统往往太难预测，不总能照标准曲线走，节奏唯一的硬规则是要有变化（p.145–146）。和分支 4 相容，但作者没把两处连起来。
- 跨章：第 5 章把预定义的剧情选项和机制决策分开：前者的结果由设计者任意定，玩家没法学习和预测（p.125）。
