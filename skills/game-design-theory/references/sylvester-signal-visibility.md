# 玩家没注意到信息

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Often, adding visibility is the obvious and wrong solution to this problem.
>
> 译：给它加可见度，往往是这个问题显而易见又错误的解法。
>
> — Tynan Sylvester, *Designing Games*, Ch9 Interface / Visual Hierarchy, p.227

> In a VISUAL HIERARCHY, everything is displayed at once, but more important pieces of information are made more visible so that people notice them first.
>
> 译：视觉层级里，所有信息同时显示，但越重要的做得越显眼，让人先注意到它。
>
> — Tynan Sylvester, *Designing Games*, Ch9 Interface / Visual Hierarchy, p.228

> A better solution is to simply accept that players will miss important signals. Then, instead of forcing them to absorb the one signal we have, we send that signal several times.
>
> 译：更好的办法是干脆承认玩家会漏掉重要信号；然后不去强迫他们接收手上这一条，而是把这条信号发好几次。
>
> — Tynan Sylvester, *Designing Games*, Ch9 Interface / Redundancy, p.230

## I — 方法骨架 (Interpretation)

这张卡回答「试玩者没看到某条信息，怎么办」。作者的判断是：玩家很少因为信号不够显眼而漏看，多半是同一时刻的信号总量超过了他能吸收的量，超出的部分就成了噪声；再把漏看的那条调大，只会更过载（p.227）。吸收能力又随技能差很多，一种信号密度不可能同时适合新手和老手。

解法有两层。一是视觉层级（visual hierarchy）：让各条信息的相对可见度跟着重要性和应学顺序走，新手只看到最显眼的几层，能力上来再看到下一层（p.228）。二是对必须送达的关键信息，承认玩家会漏，用冗余（同一信息发多次）代替锁镜头、弹窗这类强制观看。

四个分支：分支 1 是「没看到」反馈的入口，判断过载还是太弱；过载转分支 2 重排层级，单条信息的档位和随数值提档交给分支 3；关键剧情、教学、指引类信息走分支 4。冗余会增加信号，它和分支 1 的过载怎么协调，作者没说。

## A1 — 书中案例 (Past Application)

- **分支 1｜漏看与马克·吐温（例题，p.227）**：每个开发过程都会遇到测试者没注意到屏幕文字、角色或台词；显然的办法是加指示、加音效、加动画，作者引马克·吐温：每个问题都有一个简单、明显而错误的解法。原书未说明具体结果。
- **分支 2｜新手与大个子（例题，p.228）**：新手被大个子打时会自动忽略小地图、血条、背包、音乐和背景角色，正好他也用不上；技能提高后才逐个注意到低血量、小地图上赶来的队友。**射击游戏的层级（转述，p.229）**：眼前的敌人大而居中，远处的小，弹药放在角落。
- **分支 3｜血量与弹药（转述，p.229）**：血量危急时红屏加痛苦音效，健康时这些效果消失；弹药快空时，有的游戏加提示音或在屏幕中下方弹出文字。原书未说明结果。
- **分支 4｜音频日志与跳窗（例题，p.231）**：同一条音频日志放五处，听过一条其余悄悄消失；要玩家跳窗时，同伴喊、挥手、高亮木板路径、HUD 目标标记四路并用，作者说高压下也大概能送到；玩家迟迟不跳才补第二、三句，是被动冗余。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 试玩者没注意到某个提示、通知、角色或台词。
2. 团队想给漏看的东西加闪烁、放大、加音效。
3. HUD 越堆越满，新手说乱、老手说信息不够。
4. 某条 HUD 信息（血量、弹药、饥饿值）该多显眼、要不要随数值变化。
5. 关键剧情或指引常被错过，有人提议锁镜头或弹窗。

**语言信号**

- 玩家没看到 ／ 提示不显眼 ／ 要不要加闪烁 ／ HUD 太乱 ／ 这个信息放哪 ／ 低血量怎么提醒 ／ 关键剧情被错过 ／ 要不要强制镜头
- playtester didn't notice ／ missed the prompt ／ make it more visible ／ HUD clutter ／ visual hierarchy ／ forced camera ／ redundancy ／ information overload

**与相邻卡的区分（初稿）**

- 换上美术后看不清敌人、路线 → `sylvester-mechanic-metaphor.md` 分支 3
- 不想明说，只想让玩家倾向某个选择 → `sylvester-non-directive-guidance.md`
- 决策该给多少信息、藏还是给 → `sylvester-information-balance.md`
- 同时要做的决策太多（不是信号太多）→ `sylvester-pacing-problems.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 试玩者没看到某条信号，想知道为什么 | 分支 1 |
| 整个界面的显眼程度要排一遍 | 分支 2 |
| 某一条信息该多显眼、要不要随数值变 | 分支 3 |
| 关键信息必须送到，又不想强制观看 | 分支 4 |

### 分支 1：漏看时先查总负载（u09-05）

- **输入**：漏看的信号；漏看的时刻；那一刻还有哪些画面、声音、触觉信号。缺这一刻的试玩描述先问，不猜。
- **步骤**：
  1. 盘点那一刻各通道的全部信号（画面、声音、触觉等，p.225）。完成标准：清单。
  2. 排查顺序：先查总量过载，排除后才考虑这条本身太弱。作者说玩家很少因为不够显眼而漏看，多半是知觉被其他信号压垮（p.227）。过载与否原文没有数字，也没给吸收容量的测量法，由设计者凭清单和试玩观察判断，本分支不替他下结论。完成标准：清单旁写明设计者的判断及依据。
  3. 过载：不要再加大这一条，那只会更过载（p.227）；把总密度往玩家的吸收能力上调，又因为不同技能段吸收量不同、单一密度顾不全，转分支 2 排层级（p.227–228）。完成标准：要减或降的信号清单，并转分支 2。
  4. 确实太弱：按分支 2、3 调它的相对可见度，起点是它的重要性，不是绝对音量（p.228）。完成标准：调整项。
- **输出**（约定）：表，列为「时刻 / 同时存在的信号 / 判断 / 依据 / 去向」。

### 分支 2：视觉层级构建与审查（u09-06）

- **输入**：界面上的全部信息元素；玩家应该按什么顺序学会它们。应学顺序由设计者给，缺了先问；原文只有射击游戏一个例子，没有通用排法。
- **步骤**：
  1. 列出所有信息元素，写上设计者给的应学顺序。各元素的相对重要性由设计者决定（p.229），本分支不替他排。完成标准：带顺序的清单。
  2. 记下每个元素当前的相对可见度：更大、更近、更亮、更快、更响的先被注意（p.228）。只看相对高低，不看绝对值（p.228）。完成标准：每个元素有相对排位。
  3. 用作者的审查问句逐对查：有没有哪部分应该先学、却更不显眼？有就互换可见度，直到与应学顺序一致（p.228）。完成标准：没有倒挂的对。
  4. 重要性随数值变化的元素交给分支 3。完成标准：已标出。
- **输出**（约定）：互换清单，列为「元素 / 应学顺序 / 当前相对可见度 / 与谁互换」。

### 分支 3：单条信息的档位与动态可见度（u09-07）

- **输入**：这条信息；它在分支 2 里的排位；它是否在某些数值下变得更重要。
- **步骤**：
  1. 参照梯度给出静态档候选。作者以射击游戏的弹药数为例，从静到响（p.229–230）：藏在配置文件、开发者网站、多层子菜单里 → 菜单里 → 10 秒不开火不换弹就消失 → 角落小字，要刻意去找 → 靠近中心的子弹图标，余光可见 → 绕在准星周围，不用刻意看就看到（作者的经验估计：真实游戏大概只需要到这一档）→ 占半屏、闪烁、每开一枪语音报数。档位名是弹药的例子，换到别的信息要按「要不要刻意去看」类比。完成标准：候选档与分支 2 的排位对应，不单独定绝对值。
  2. 判断要不要动态提档：重要性随数值变化的（血量、弹药越低越要紧），数值变关键时提档，平时降回去，如血量危急时红屏加痛苦音效、健康时安静（p.229）。在哪个数值提档原文没给，交给设计者。完成标准：写明是否提档和提档后的形式，阈值栏由设计者填。
- **输出**（约定）：表，列为「信息 / 静态档候选 / 是否提档 / 提档后形式 / 阈值（设计者定）」。

### 分支 4：关键信息用冗余代替强制观看（u09-08）

- **输入**：必须送达的信息；玩家要在什么时候懂；游戏能不能检测玩家已经收到（如听完一条日志）。
- **步骤**：
  1. 不用锁镜头、弹窗打断等强制观看，它们打碎心流和沉浸（p.230）；承认玩家会漏。作者的经验估计：漏掉一半内容是相当合理的比例，冗余要让玩家漏掉一半仍懂关键部分（p.230）。完成标准：方案里没有强制观看。
  2. 选冗余类型（p.231）：
     - 同质冗余（同样的方式重复）：能检测是否收到时可以悄悄做，收到一份其余消失；检测不到时只能重复，但单纯重复刺耳，常改用多样冗余
     - 多样冗余（不同方式各发一次）：对话、动画、关卡视觉、HUD 各一路
     - 被动冗余（主信息失败才发次要信息）：玩家迟迟没行动才补一句

     完成标准：通道表，每路写明类型和触发条件。
  3. 给每条被动冗余标风险：常常分不清玩家是漏看还是故意不理，后者会被惹烦（p.231）。原文没给区分办法，本分支不解决它，只标出来由设计者判断。完成标准：每条被动冗余有风险注记。
- **判停 / 转向**：发几次原书未说明。冗余会增加那一刻的信号量，它和分支 1 的过载怎么协调作者没说（p.227、p.231），由设计者判断。
- **输出**（约定）：表，列为「关键信息 / 通道 / 冗余类型 / 触发条件 / 风险」。

## B — 边界 (Boundary)

**不要用这张卡**

- 美术细节淹没了机制 → `sylvester-mechanic-metaphor.md` 分支 3。
- 不想明说，只想引导选择 → `sylvester-non-directive-guidance.md`。

**作者警告的失败模式**

- 漏看就调大，屏幕上高亮越来越多，更过载（p.227）。
- 用一种信号密度服务所有水平：适合新手的让老手出现无聊的心流空档，适合老手的淹没新手（p.227）。
- 强制观看：解决一个问题，又制造了更多问题（p.230）。
- 被动冗余对故意不理的玩家变成唠叨（p.231）。

**作者盲点与时代局限**

- 「漏掉一半是合理比例」（p.230）和「环绕准星大概是上限」（p.229）都是作者估计（批判节列为未验证的阈值）。
- 冗余与信号过载的张力作者没解（p.227、p.231；批判节「作者自留的张力」）。
- 档位梯度和层级例子都来自射击游戏，档位名不通用；单独给一条信息定档，违背「只看相对可见度」，要和分支 2 一起用。
- 诊断全靠人工试玩观察，书里没有遥测等手段（批判节：数据手段）。
- 可见度只按一般玩家的知觉讲，色弱、听障等感官差异不在讨论内（批判节：accessibility）。

**各分支的已知缺口**

- 分支 1：吸收上限没有数字，也没有测量法；过载与否靠设计者判断。
- 分支 2：重要性排序是设计者的判断，没有通用排法；可见度只有定性维度。
- 分支 3：提档阈值未给。
- 分支 4：漏看与故意不理无法区分；发几次未给。
