# 平衡改动评审

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> But even if a balance change creates wonderfully rich decisions and perfectly fair play, it’s worthless if it destroys narrative coherence, flow and pacing, accessibility, or clarity.
>
> 译：哪怕一项平衡改动造出了极其丰富的决策、完全公平的对局，只要它毁掉了叙事连贯、flow 与节奏、可及性或清晰度，它就一文不值。
>
> — Tynan Sylvester, *Designing Games*, Ch6 Balance / Balancing for Other Reasons, p.159

> Once you’ve got two viable strategies, there is no inherent value in adding more. … Improving the experience means making the decision process more nuanced.
>
> 译：一旦有了两个可行策略，再往上加并没有内在价值。……要改善体验，就得让决策过程更细腻。
>
> — Tynan Sylvester, *Designing Games*, Ch6 Balance / The Viable Strategy-Counting Fallacy, p.162

> Tuning a mechanic changes all the strategies it is involved in, not just the ones we intend.
>
> 译：调一个机制，会改变它参与的所有策略，而不只是我们想改的那些。
>
> — Tynan Sylvester, *Designing Games*, Ch6 Balance / Balance Challenges and Solutions, p.166

## I — 方法骨架 (Interpretation)

这张卡回答「这个太强（太弱）的东西该不该改、怎么改，加个新选项能不能加深度」。平衡（balancing）是调整机制、改变工具、单位、策略、队伍或角色之间相对强弱的方法；改法可以是调数字，也可以是更根本的改结构，比如拿掉法师的护盾（p.155）。作者强调平衡是方法不是目标：只有公平和深度主要靠它，别的目标多半另有主手段。难处在于好游戏是复杂系统，一个机制用在许多地方，调它会牵动它参与的每个策略，再牵动与之相连的策略。

术语：旋钮（knob）指工具的任一可调属性；关键属性指没了它这东西就不再是它的属性；可行策略指有理由导向好结果的策略；隐性目标指现在运转良好、没人想到要保护的东西。

五个分支：分支 1 是任何改动的入口，写目标、查体验代价；提议是「加选项」时走分支 2；改动起因是试玩里冒出的问题时，先走分支 3 写影响记录，再到分支 4 决定动哪个旋钮、要不要砍；分支 5 不由问题触发，是数值被磨得太平时的反向实验。常规顺序 1→3→4，分支 2、5 单独进入。

## A1 — 书中案例 (Past Application)

- **分支 1｜弓、跳跃、车（例题，p.159）**：给弓 10 英尺射程，也许公平、也许带来有趣决策，但在虚构层说不通；只在这一关缩短跳跃，违背玩家预期、制造挫败；把车调得又慢又笨，开车成了苦差，哪怕是公平的苦差。反方向：降乞丐的血量来突出他虚弱、提喷气机的速度来明确它的定位，平衡也能服务公平和深度以外的目标（p.156）。原书未说明结果。
- **分支 2｜作者重写整章（作者亲历，p.161–162）**：作者原以为平衡就是让可行策略尽量多，据此写完了这一章，再去找反例：石头剪刀布蜥蜴史波克有五个同等可行的策略、还能无限加，却不更深，只是更复杂；扑克很多手只有弃牌、跟注两个可行策略，却极其耐玩。他推翻了原结论。
- **分支 3｜剑与火的连锁（例题，p.166–167）**：为食人魔那一战削弱剑，剑打哥布林就太弱；再削哥布林去配，它们又被法杖和徒手轻易打死。作者引 Dörner：健康的人谈目标时不会提「健康」，生病了它才变成显性目标，这就是隐性目标（p.169–170）。原书未说明结果。
- **分支 4｜火箭背包与 Thor（例题 + 转述，p.167–169）**：火箭背包必须飞得远、飞得快，可以调价格、重量、脆弱度，或让它受损爆炸、持续漏油、慢慢吸血，太弱就让它护背或静音，但绝不能变慢；护甲可以贵、重、显眼、很吵，但不能变脆。StarCraft II 早期的 Thor 在野外像建筑一样建造、被毁能复活、转身极慢：量产太快、太难击败、被小快单位绕圈就能打死，这些只在高手测试后才暴露。Blizzard 没叠特例规则，把它缩成从工厂出、不能复活的普通机甲；作者判断游戏因此更好。
- **分支 5｜拧到 11（例题，p.170–171）**：名字取自电影 This Is Spinal Tap 里旋钮能拧到 11 的乐手。作者列的问题：护盾直接无敌？护全队？移速快 5 到 10 倍、瞬移？跳一百英尺、无限金钱？作者说多数实验要调回来；原书没有给出某次被保留的具体实验。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 试玩或对战数据显示某个单位、武器、卡牌、技能太强，团队要削；或太弱没人用，要加强。
2. 有人提议加新单位、新姿态、新选项来「加深度」。
3. 上一轮刚改完，下一轮在别处冒出新问题，同一个参数被来回调。
4. 一个很酷的工具怎么调都不对，考虑砍掉或加特例规则。
5. 数值调得很稳，试玩反馈「安全但平淡」。

**语言信号**

- 这个太强了怎么削 ／ 要不要 nerf ／ 加个新单位增加深度 ／ 改完又冒出别的问题 ／ 砍掉还是削弱 ／ 加条特殊规则补一下 ／ 调得太平了
- nerf ／ buff ／ overpowered ／ balance patch ／ tuning pass ／ more options for depth ／ whack-a-mole balancing ／ special-case rule ／ turn it up to 11

**与相邻卡的区分（初稿）**

- 还不知道哪里不平衡，要找一招鲜、看收益地形 → `sylvester-degenerate-strategy-hunt.md`
- 先定公平方式、平衡给哪个技能段、退化打法修不修 → `sylvester-balance-target.md`
- 试玩时怎么看、怎么问 → `sylvester-playtest-observation.md`
- 多人对抗里有没有固定最优解、克制关系 → `sylvester-strategic-interaction-equilibrium.md`
- 第 5 章的信息平衡（让决策不难懂也不明显）是另一个概念 → `sylvester-information-balance.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 有人提了一个平衡改动（削、加强、改结构），要评审 | 分支 1，再按来由进分支 3 或 4 |
| 提议加新单位、新选项、新姿态来加深度 | 分支 2 |
| 试玩里冒出一个问题，想马上调参 | 分支 3 → 分支 4 |
| 某个工具太强或太弱，不知道动哪个属性；该不该砍 | 分支 4 |
| 发现自己在把过好或过坏的东西磨平；游戏变平 | 分支 5 |

### 分支 1：平衡改动的目标与体验代价审查（u06-01）

- **输入**：改动内容（数值或结构）；提出改动的理由。理由只有「不平衡」三个字时，先问想达到什么。
- **步骤**：
  1. 写明改动服务的目标：公平、深度，或虚构一致、清晰、简洁、优雅等（p.156）。完成标准：一个具体目标，不留笼统的「平衡」。
  2. 判断平衡是不是这个目标的合适手段：公平和深度主要靠平衡；讲故事主要靠美术和文字，清晰主要靠界面（p.156）。完成标准：写「合适」或「另有主手段：……」。
  3. 逐项写改动对叙事（虚构）连贯、flow 与节奏、可及性、清晰度的影响，可对照 A1 三例（p.159）。完成标准：四项各一句。
  4. 分档：毁掉其中任一项的，改动一文不值，否决；只是有代价的，与收益并列（p.159）。完成标准：每项标「毁掉 / 有代价 / 无影响」。
- **判停 / 转向**：有代价但未毁掉时，收益与代价怎么换算原文没有方法，列出由设计者判断。通过后，改动来自试玩问题的转分支 3，要定动哪个属性的转分支 4。
- **输出**（约定）：评审记录，列为「目标 / 平衡是否合适的手段 / 四项影响 / 分档 / 结论（否决或交设计者权衡）」。

### 分支 2：「加选项来加深度」提议评审（u06-05）

- **输入**：现有决策及其可行策略；拟加的选项，以及它和现有选项有什么不同。
- **步骤**：
  1. 查该决策现在有没有至少两个可行策略；只有一个，它就是退化策略，决策成了非决策，先修它（p.161），转 `sylvester-degenerate-strategy-hunt.md`。完成标准：现有可行策略列表。
  2. 已有两个以上时，不把「可行策略变多」当作价值：RPSLS 加符号不加深度，扑克策略少却深（p.161–162）。完成标准：提案中以「选项多＝更深」为理由的部分标为不成立。
  3. 要求提案写明新选项给玩家的推理加了什么：新的变量、新的情境取舍、新的顿悟、怀疑与两难，而不只是同构地再复制一份（约定，由 p.159、p.162 推出）。原书只说平衡让决策涉及对更多变量的更细腻思考（p.159），求深度是要激起顿悟、怀疑与两难（p.162）；把它变成对提案的要求、加上「情境取舍」一项，是写卡时加的。完成标准：每个新选项标「新增推理变量：……」或「同构，无增益」。
  4. 把它和新增的复杂度并列：作者说多出的选项常常不值那份复杂度（p.162）。完成标准：列出新增了哪些规则、内容或要学的东西。
- **判停 / 转向**：推理是否更细腻、值不值那份复杂度，作者自认极难衡量（p.162），交设计者或试玩判断。
- **输出**（约定）：评审意见，列为「现有可行策略 / 新选项的新增推理变量或同构 / 新增复杂度 / 采纳或否决及理由」。

### 分支 3：调参前的影响评估，不做反应式修改（u06-08）

- **输入**：试玩里看到的问题；拟改的机制和改法；该机制在游戏里被用到的地方。
- **步骤**：
  1. 先不拧旋钮：一个个修问题，像把墙纸下的气泡推来推去，策略互相耦合，一个问题的解法就是另一个问题的起因（p.169）。完成标准：改动暂缓，开始写记录。
  2. 写下显性目标，即要解决的那个问题（p.169–170）。
  3. 列出该机制参与的所有地方和策略，再列与这些策略相连的策略（p.166–167）。完成标准：一阶、二阶两列，列到设计者能想到的范围为止。
  4. 列可能被波及的隐性目标：现在运转良好、没人提的东西（p.169–170）。完成标准：隐性目标清单，每项写改动会怎样碰到它。
  5. 提醒自己不要只修最近看到的那次失衡，游戏能出的失衡远多于见过的（p.274）。完成标准：写下见过之外可能出现的失衡。
  6. 只有判断改动造成的问题少于它解决的问题，才执行（p.170）。完成标准：写出设计者的净效果判断及依据。
- **判停 / 转向**：还没找到具体的强弱问题 → `sylvester-degenerate-strategy-hunt.md`。净效果怎么估原文没有方法；作者说能估的前提是测得足够、脑中已有系统模型（p.173），本卡不替设计者估。找不到净减少问题的改法时，转分支 4 换旋钮或加机制。
- **输出**（约定）：影响记录，列为「显性目标 / 一阶策略 / 二阶策略 / 隐性目标 / 未见过的可能失衡 / 净效果判断及依据 / 执行与否」。

### 分支 4：工具平衡阶梯：锁关键属性、调其余旋钮、加增减机制、平衡不了就砍（u06-09）

- **输入**：工具（单位、技能、道具）的角色与虚构身份；它的全部属性；问题方向（太强 / 太弱）。
- **步骤**：
  1. 找出对角色和虚构身份必不可少的属性；检验：没了它还算不算这种东西，火炮不能远程抛射就不是火炮（p.167）。完成标准：关键属性清单。
  2. 把关键属性推到尽可能极端并锁死，工具因此角色分明、策略空间变宽（p.167）。完成标准：每项标「锁定」。
  3. 用非关键属性解决平衡问题，如价格、重量、脆弱度（p.168）。完成标准：可调项及调整方向。
  4. 还不够就新增机制来加强或削弱，但绝不动关键属性（p.168）。完成标准：增减机制清单，没有一项落在锁定属性上。
  5. 只有改关键属性才能平衡时，砍掉或大幅缩小重做，不叠特例规则去补（p.168–169）。完成标准：写「建议砍」或「缩成……」及理由。
- **判停 / 转向**：还不知道哪个工具强弱有问题 → `sylvester-degenerate-strategy-hunt.md`。何时算平衡不了没有停止条件，砍还是缩也没有判据，交设计者。作者说追求高技能平衡时砍到底不是选择题（p.169）；目标技能段未定的先走 `sylvester-balance-target.md`。
- **输出**（约定）：工具属性表，列为「属性 / 关键与否 / 锁定或可调 / 调整方向」，附增减机制清单和砍或缩建议。

### 分支 5：Nigel Tufnel 极端化实验（u06-11）

- **输入**：一个要试的旋钮（挑哪个由设计者定）；能实际试玩的版本。
- **步骤**：
  1. 把这个旋钮推到荒谬的极端，参照 A1 的问题清单（p.171）。
  2. 实验时暂时放下讲道理，只问这样是不是很棒（p.171）。
  3. 实际玩一下；多数要调回来（p.171）。
  4. 若它显出错过的机会，或让人想起被磨平的情绪时刻，就吸收并保留，不撤回（p.171）。完成标准：记下保留或撤回，保留的写明符合哪一条。
- **判停 / 转向**：频率作者只说不时做一次；挑哪个旋钮、保留下来的极端怎么并入现有平衡，原文没说。
- **输出**（约定）：实验记录，列为「旋钮 / 极端值 / 试玩所见 / 保留或撤回 / 理由（错过的机会 / 被磨平的情绪时刻 / 无）」。

## B — 边界 (Boundary)

**不要用这张卡**

- 目标技能段没定，分支 4「砍到底」的前提就不成立 → `sylvester-balance-target.md`。
- 把「其他目标多半用别的手段」当禁令：作者说的是 mostly，平衡也能追求虚构和清晰（p.156）。

**作者警告的失败模式**

- 只按公平和决策深度评估改动，提案只附胜率、强度数据（p.159）。
- 用加选项、加单位来加深度，只加了复杂度（p.162）。
- 为一个情境调通用工具，别处被打破；每轮试玩后都追着上一轮的问题改，同一参数来回调（p.166–170）。
- 削弱工具名字所承诺的属性，或叠「但是……时除外」式的特例去撑一个平衡不了的概念（p.168–169）。
- 因为点子酷、做了很久而舍不得砍（p.169）；这一条作者只对追求高技能平衡的游戏说是硬要求。

**作者盲点与时代局限**

- 作者的可及性只指技能和知识门槛，不含身体或感官障碍（批判节）。
- 影响网络全靠心智模型推演，遥测、自动模拟几乎没提（批判节）。
- 「两个可行策略之后再加没有内在价值」是作者的经验判断，只靠两个反例，未经系统验证（批判节）。
- Thor 与 Blizzard 是作者转述的开发史；作者自称全书是模型和假设（p.375）。

**各分支的已知缺口**

- 分支 1：代价权衡没有量化方法，不能给打分公式。
- 分支 2：推理是否更细腻没有测量办法。
- 分支 3：影响网络指数扩展，列举无法穷尽；净效果判断依赖设计者已测够。WYSIATI（只看见眼前的就以为是全部）一步出自第三部分引言 p.274，作者本人在那里用平衡设计师过度修正作例子。
- 分支 4：关键属性凭角色和虚构判断，没有更硬的判据；「平衡不了」没有停止条件。
- 分支 5：频率只说不时做一次；保留判据是定性的；作者说多数实验不成功；保留下来的极端怎么并入平衡，原文没说。
