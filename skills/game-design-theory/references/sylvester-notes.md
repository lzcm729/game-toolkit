# Sylvester《Designing Games》：术语与只作参考的观点

> 能照着做的方法在能力卡里（见 SKILL.md 的选卡表）。这里放两类卡外的内容：
> 术语的意思，以及原书讲了、但没给出能照着执行的步骤的观点。用它们时说明是作者观点，不当规则。

## 术语

- **GAME DESIGN（游戏设计）**（p.4–5）：≠ 做游戏的全部工作（美术、程序、音频、搭建关卡）；= 只指「让棋子活起来」的那套规则；工艺只管「怎么实现」，不定游戏的目的
- **MECHANICS / EVENTS（机制 / 事件）**（p.7–8）：mechanic ≠「玩法」「系统」这类宽泛词；= 一条规则（A 键让 Mario 跳、兵斜着吃子），不论由人还是代码执行；event ≠ 设计师写好的剧情事件；= 游玩时机制和玩家互动生成的事，每次都不一样；设计师隔着一层间接性工作：只能设计机制，事件是生成出来的
- **EMOTIONAL TRIGGER（情绪触发器）**（p.11）：≠ 只指「有趣」的来源：作者明确说游戏情绪不限于 fun；= 任何引发情绪的事物或观察；多数是无意识的自动计算，有的写在基因里，有的是学来的；第 1 章 The Basic Emotional Triggers 一节逐一讲了学习、角色弧、挑战、社交、获取、音乐、奇观、美、环境、新奇技术、原始威胁、性信号 12 类，各有代价和风险
- **HUMAN VALUE（人的在乎之物）**（p.12–14）：≠ 道德意义的价值观（那是第 17 章的 VALUE，见 「VALUE（价值观）」）；≠ 市场价值（第 10 章 MARKET VALUE，见 「MARKET VALUE / VALUE CURVE（市场价值 / 价值曲线）/ value focus」）；= 人在乎、能在几个状态之间迁移的东西，写成 [life/death]、[victory/defeat]、[friend/stranger/enemy]、[wealth/poverty] 这样的对；情绪来自事件「暗含的」（implied）价值变化，作者叫 implications：同样丢一个兵，开局无所谓，残局可能就是从赢到输；预期中的变化（p.14）和信息揭示（p.15）也算变化
- **emotional misattribution（情绪错误归因）**（p.17–18）：≠ 玩家撒谎或不懂游戏；= 情绪是真的，但人会自动、真诚地给情绪安上错误的原因（吊桥实验、丝袜实验）；所以玩家说的「喜欢 / 不喜欢」可信，「因为……」只是待验证的线索
- **INSIGHT（顿悟）**（p.20–21）：≠ 单纯的惊讶，或拿到一条新信息；= 最后一块信息让许多旧信息连锁地讲得通（「I should have known!」）；前提是事先埋下玩家注意到却读不懂的线索
- **FICTION（虚构层）**（p.29–33）：≠ 小说、剧情文本；= 包在机制外面的意义外衣（图像、声音、名字、设定）：同一堆零件，包成人形就从「装成女人的机器人」变成「碰巧是机器人的女人」；fiction layer 和 mechanics 是两层，各自产生不同的情绪，而且很容易互相干扰
- **EXPERIENCE（体验）**（p.34）：≠「用户体验」UX、界面好不好用；≠ 单一情绪；= 从开始玩到结束、在玩家脑子里展开的一条弧，包括思考和决策；总是混合的，大于各成分之和
- **pure emotion / juxtaposition / antagonistic emotions / atmosphere（情绪组合方式）**（p.35–36）：pure emotion ≠ 只用一种触发器；= 多个触发器朝同一种情绪叠加（街机：快节奏音乐 + 风险 + 暴力虚构 + 社交竞争）；juxtaposition：有意混搭看似不相容的情绪；antagonistic emotions：单独都好、放一起互相削弱（轻松的社交乐趣 vs 残酷的技巧竞争）；atmosphere：不依附具体事件、弥散在整个体验里的情绪背景
- **FLOW（心流）**（p.39, p.139–140）：借自 Csíkszentmihályi。第 1 章按「挑战和能力相当」讲；第 5 章作者改写成「决策注入速率」：玩家的心是底部有孔的杯子，决策是水，要不停地加又不能溢出；flow 是体验的地基：在 flow 里玩家能接受怪异的虚构、粗糙的画面；游戏的「逃避」来自 flow 而不是幻想
- **IMMERSION / TWO-FACTOR THEORY OF EMOTION（沉浸 / 情绪二因素理论）**（p.40–43）：≠ 画面逼真、沉默主角、关灯玩：作者说这些都有反例；= 玩家的经历镜像角色的经历；配方三步：用 flow 把现实挤出脑子 → 用机制里的威胁和挑战制造生理唤醒 → 用虚构层把唤醒标成角色此刻的感受；二因素理论是这个配方的心理学依据（书外的可重复性待核，见编者评注）
- **GAME（游戏）**（p.44）：≠「有规则、有输赢、有目标的活动」，也 ≠「好玩的东西」：定义里刻意不提 fun 和胜负；= 生成体验的人工系统；该用的比喻是机器（engine of experience），不是故事或电影
- **ELEGANCE（优雅）/ smell like elegance**（p.49, p.52）：≠ 视觉或审美上的简洁、「少即是多」；= 一种效率：分子是情绪力量和体验多样性，分母是玩家的理解负担和开发成本；每个机制都有价签，最贵的是玩家注意力；「smell like elegance」= 九条经验启发式（与很多机制交互、简单、多用途、role 不重叠、复用惯例、尺度相近、使用频繁、不限制内容、用满界面表达力）；是训练出来的嗅觉，不是可证明的判据（作者自己没有系统验证，见编者评注）
- **EMERGENCE（涌现）**（p.50–52）：≠「随机」「失控」或「玩家自己找乐子」；= 机制之间交互，可能性相乘而不是相加（Halo 吉普车腾空翻滚的那局）；代价是改动难：在优雅的设计里，改一个高度互联的机制会牵动它的每一条关联（法杖例，p.51–52）
- **role（用途 / 职能）**（p.54, p.167）：≠ RPG 里的角色、职业；= 机制的一种用法：骚扰、侦察、致残、欺骗；挖掘、建造、装饰；第 6 章平衡时，role 和虚构身份决定哪些属性是必须推到极致再锁死的「旋钮」（见 「BALANCING（平衡）/ knob（旋钮）」）
- **DEEP / SKILL CEILING / LIMITLESSLY DEEP（深度 / 技能天花板 / 无限深）**（p.64–65）：≠ 内容多、系统多、流程长；= 到了高技能段仍有有意义的玩法；粗测法：比较理论上完美的玩家和人类最强玩家的表现差（国际象棋人机组合胜过大师 → 无限深）；第 6 章：深的决策要平衡到连专家都拿不准最优解
- **ACCESSIBLE / SKILL BARRIER（易上手 / 技能门槛）**（p.66–68）：≠ 无障碍设计（照顾身体或感官障碍）：作者只讲技能和知识门槛，编者评注已标为盲点；≠「简单」；= 低技能时能不能有有意义的玩法；门槛是进入有意义的游玩之前必须掌握的最低技能（FPS 的移动、转向、射击）
- **SKILL RANGE（技能区间）**（p.66–68）：= 从 skill barrier 到 skill ceiling 之间的区间；宽 ≠ 一定更好：按游戏的意义来源和时长来判断；会随玩家群体变化：老游戏里只剩高手，新人进不来（Counter-Strike 例）
- **REINVENTION — MANUAL / SITUATIONAL / MENTAL（三层重塑）**（p.69–71）：≠ 版本更新、重制；= 同一套机制随玩家技能提高，变出更深一层的游戏（「games inside games inside games」）；manual：掌握界面 → situational：知道打谁、何时、往哪派兵（大多数玩家和大多数设计停在这层）→ mental：维持专注、扰乱对手心理
- **ELASTIC CHALLENGE（弹性挑战）**（p.71–73）：≠ 难度选项；= 挑战本身分档：成功有几档（飞镖靶环、街机分数），失败也有几档（失败后放慢进度而不是结束）；对立面是 pass/fail：只服务刚好够格的那一小段技能
- **emotional life support（情绪维生）**（p.74–75）：≠ 新手教程，≠ 降低难度；= 玩家还在技能门槛以下时，用不需要技能的情绪触发器（壮美的画面、有趣的角色、和朋友开玩笑、音乐、技术展示）撑住体验，让学习期像一段半互动的开场
- **EXPLICIT / ADAPTIVE / IMPLICIT DIFFICULTY（三种难度调整）**（p.76–78）：implicit ≠「隐藏难度」：是玩家自己挑易执行或难执行的策略来定挑战，和 adaptive 的「系统暗中调」是两回事；adaptive：作者认为玩家不知道时效果最好（知情与公平问题作者未讨论，见编者评注）；explicit 和 adaptive 可以并存（Resident Evil 5：明面四档，内部十档在明面档位限定的范围内浮动）
- **FAILURE TRAP（失败陷阱）**（p.78–80）：≠ 难关、高难度；= 结局已定却还得接着玩的漫长时段（比分落后太多的球队、赛车里掉队）；常常是涌现出来的，比设计者预想的惩罚重得多；「惩罚玩家本人」= 让他等读盘、重打、刷回资源，也就是逼他玩一段烂游戏；作者主张改成小挫折、小损失，让游戏继续往前走
- **NARRATIVE TOOL（叙事工具）**（p.83–84）：≠ 剧本、故事本身；= 在玩家脑子里形成一段故事的任何装置（脚本、世界叙事、涌现故事……）；作者只讲工具不讲故事写作：「I’m not a dedicated story crafter」（p.83，编者评注列为自声明边界）
- **SCRIPTED STORY / SOFT SCRIPTING（脚本故事 / 软脚本）**（p.84–85）：scripted ≠ 一定是过场动画：cutscene 只是最基本的一种，必然打断 flow；soft scripting 不断 flow，代价是让出设计者控制（玩家可能从难看的角度看、错过，甚至干预）；每段脚本都要在「玩家影响—设计者控制」的光谱上定位
- **WORLD NARRATIVE（世界叙事）**（p.85–90）：近似常说的「环境叙事」，作者的强调点有两个：它不依赖时序，所以天然避开脚本和互动的冲突，可以按任意顺序发现、由泛到细揭示；强度取决于连贯性：每个核心机制在世界里都要有说法；手法包括布置事件残留的 mise-en-scène（p.87）
- **EMERGENT STORY（涌现故事）**（p.90–92）：≠ 玩家在游戏外自编的同人故事；= 机制、玩家和随机性一起生成的事件序列；作者认为它和「生成的体验」是同一个东西；价值在于换个提问角度：用人物塑造、高潮、铺陈去审机制生成的体验；只有它能跨过虚构和现实的边界（第一次赢哥哥的那盘棋）
- **APOPHENIA（空想性错觉）**（p.92–94）：心理学语境里多指错误认知甚至病理；作者把它当正面的设计资源，是涌现故事的发动机：少给细节、加个名字或标签，玩家自己就会把故事补齐；和第 1 章的 emotional misattribution 同属「心智自动编造」一类
- **labeling / abstraction / recordkeeping / sportscaster systems（放大涌现故事的四种手段）**（p.93–96）：四种都不新增玩法机制，只改玩家怎么读事件：labeling 给个体起名、贴性格标签（Medieval: Total War 的「Drunkard」）；abstraction 故意少表现；recordkeeping 记录并回放（Civilization IV 结局的疆域变迁回放）；sportscaster 系统像解说员一样把事件串成叙事
- **DESK JUMPING（跳桌子）/ agency**（p.101–106）：≠ bug、作弊；= 玩家的动机（试探极限、搞笑、机制收益）和角色的动机分岔，于是做出破坏叙事的事（Deus Ex 里在上司办公桌上跳来跳去）；处理阶梯：禁止（会让玩家不再相信机制是诚实的）→ 忽略、不作回应 → 写进叙事 → 最好是让两者的动机和能力对齐；agency 按常见义使用；作者把 desk jumping 和人际互动问题都归为 agency problems
- **predictability / partially predictable（可预测性 / 部分可预测）**（p.123–125）：≠ 常识里「可预测 = 套路、无聊」的贬义；= 玩家能感知并推断可能的未来；结果既不是不可知（只能乱选）也不是必然（决策消失）；前提是驱动结果的系统一致、可理解
- **INFORMATION BALANCING（信息平衡）**（p.127）：≠ 第 6 章的 balancing（那是改机制、调相对强弱）；= 不动机制，只增减玩家能拿到的信息，改变决策的难度和性质；目标落在 information starvation 和 glut 之间
- **information starvation / information glut（信息饥饿 / 信息过剩）**（p.127–131）：starvation ≠ 难度高；表现是「反应式乱撞、随机选择」，设计者因为自己知道全部信息而看不见（攻略站 FAQ 反而能救活这种游戏）；glut 的信号是试玩太顺、没有张力；修法是减信息（Modern Warfare 2 的心跳传感器加上 Ninja 技能的例外）
- **fictional ambiguity（虚构模糊）**（p.135–137）：≠ 剧情含糊；= 虚构外衣暗示的可能操作远多于机制实际做了的（桌上的烤火鸡：能拿吗、能吃吗、能卖吗、能扔去引开动物吗）；它是信息饥饿的常见来源之一（p.129）；第 9 章用 metaphor vocabulary（「METAPHOR / METAPHOR VOCABULARY（隐喻 / 隐喻词汇）」）来解
- **METAGAME INFORMATION（元游戏信息）**（p.137–139）：≠ 竞技圈说的「meta」（当前版本的强势打法、环境）；= 玩家从游戏外拿到的信息：类型惯例、口碑、工作室的老套路、技术限制、预告片和封面；它会改变决策的可预测性（看穿剧情反转、知道游戏不可能同屏一万人）
- **DECISION SCOPE（决策规模）**（p.140–142）：≠ 决策的重要性或影响范围（scope 容易被读成后者）；= 想清楚这个决定要花多少心思，即放进「杯子」的水量；五档带时间尺度：twitch 不到 1 秒、tactical 1–5 秒、profound 10 秒以上、impossible 超出理解只能乱选（秒数是作者经验值，编者评注已标）；nondecision 也是第 6 章退化策略把决策变成的东西
- **FLOW GAP / OVERFLOW（断流空档 / 决策溢出）**（p.142–144）：flow gap ≠ 很长的无聊段：一秒也算；常见来源是为平衡加的冷却（法杖两秒一发）、菜单过渡、动画、等待对手；overflow 很明显（试玩者会抱怨压力），多发生在技能门槛以下的弱玩家身上
- **micromanagement（两处两义）**（p.144–145, p.343）：同一个词在书里两处、两个意思：第 5 章是回合制游戏的设计病：小规模决策太多，和 analysis paralysis（决策规模太大）相对；第 14 章是管理病：领导对下属比自己更懂的细节下命令，是 arrogation（「ARROGATION（越权）/ swoop and poop」）最常见的形式
- **BALANCING（平衡）/ knob（旋钮）**（p.155, p.166–168）：≠ 只是改数字：也可以加机制、改机制；平衡的目标不止公平，还有深度和其他理由（Goals of Balance 一节），动手前要写明是哪一个；knob = 工具的任一可调属性，分两类：和 role、虚构身份相关的关键旋钮推到极致后锁死（火箭背包必须飞得远），只拿其余旋钮（价格、重量、脆弱性）去平衡；≠ 第 5 章的 information balancing（「INFORMATION BALANCING（信息平衡）」）
- **FAIR（公平）/ symmetric**（p.156–157）：≠ balanced：平衡还服务深度等别的目标；≠ 结果公平、胜率相等；= 开局那一刻没有人占优；对称游戏自动公平，非对称游戏要平衡出公平，也有刻意不公平的设计
- **STRATEGY（策略）**（p.157–159）：≠ 工具、单位、角色本身；平衡的对象是「某个情境里可选的策略」；脱离情境比较工具强弱（剑 vs 火焰法术打食人魔）没有意义；第 7 章博弈论里的 strategy 沿用这个意思
- **DEGENERATE STRATEGY（退化策略）**（p.159–161, p.163）：≠ 作弊、bug、exploit；也 ≠ 不体面的打法；= 显然最优、让决策消失（变成 nondecision）的策略：加了无敌的 Chuck Norris 单位，选兵就只剩「派 Chuck」；可以藏在涌现互动里（自我增强循环）；是否算退化依技能段而定：选定目标技能段，其他技能段允许存在；单人游戏未必非修不可（第 16 章，p.368）
- **viable strategy-counting fallacy（数可行策略的谬误）**（p.161–162）：≠「可行策略越多，平衡越好」：作者原稿就是这么写的，后来自己推翻了；反例：石头剪刀布蜥蜴斯波克策略更多却不更深；扑克常常只有弃牌、跟注两个选择却极深；判据是找最优策略的思考是否细腻，不是策略个数；「两个可行策略之后再加没有内在价值」是作者的经验断言（未经系统验证，见编者评注）
- **Nigel Tufnel moment（调到 11）**（p.170–171）：≠ 乱调参数或压力测试；= 有意把某个旋钮推到荒唐的极端去试（护盾变无敌、移速变瞬移），多数会调回来，但保留偶尔成功的那一次；目的：对抗「把一切磨平」造成的平坦策略地形。平衡不是所有策略等值，地形要有峰谷，执行门槛和效果相当
- **NASH EQUILIBRIUM（纯 / 混合纳什均衡）**（p.179–187）：用的是博弈论标准义，作者加了设计判据：只有一个纯均衡 = 坏设计，因为每人只剩一个可行选项，策略决策消失；均衡不一定对谁都最好（猎鹿博弈里双方猎兔）；混合均衡的要点是均衡时每个选项期望收益相等，可据此估出各选项的比例
- **YOMI（读心）**（p.187–197）：借自格斗游戏设计师 David Sirlin，原词是日语的「读」；≠ 博弈论里的混合策略计算：yomi 恰恰长在数学之外；石头剪刀布这类模式只是骨架，yomi 是骨架外的血肉；作者列的生长条件：策略能平滑混合、收益复杂难量化、随机性的心理、信息操纵、玩家人数少
- **DIVERGENT GOALS / GRIEFING / skill differentials（分歧目标 / 恶意破坏 / 技能差）**（p.197–202）：≠ 单纯的「玩家素质差」：作者把破坏性行为归因到设计；分歧目标常常是游戏自己造出来的（Modern Warfare 永久记录击杀数，于是有人不管夺旗只刷人头）；griefing 是以惹恼别人为乐的最坏一类，按严重度分级选防线；技能差也算一种分歧目标：新手想学、老手想赢
- **motivation vs fulfillment / wanting vs liking（动机 vs 满足）**（p.204–205）：≠「玩家还在玩 = 玩家喜欢」；motivation（想要：多巴胺、奖励预期）和 fulfillment（真正得到满足的体验）是两条线；本章只讨论产生动机的机制，以及怎样把它和满足配对
- **REINFORCEMENT SCHEDULE（强化程序）/ shelf moment**（p.206–212）：来自 Skinner 的操作性条件反射研究；类型有 fixed ratio、variable ratio、fixed interval、variable interval、DRL、DRH 等；单一程序必有动机低谷，玩家会在那里放下游戏（shelf moment）；对策是叠加多个程序并错开；大多数程序不是直接设计的，而是从底层系统涌现的（比赛结果分布、关卡结束点）
- **EXTRINSIC / INTRINSIC REWARDS（外在 / 内在奖励，两章两义）**（p.212–214, p.349–352）：≠「奖励越多动机越强」「内在外在可以相加」：作者认为外在奖励会挤掉内在动机（Deci 等研究，书外可重复性待核）；同一个概念在第 8 章用于玩家（打兽人掉金币），在第 15 章用于开发者（奖金、绩效）；并断言它在游戏开发里注定失败（四条理由，第一条是工作好坏难以从外部评判）
- **REWARDS ALIGNMENT（奖励对齐）**（p.214–216）：≠ 奖励够不够多、够不够诱人；= 奖励鼓励的活动和玩家本来就想做的事有多重合；检测不到的愿望（把城市建得像家乡、交到新朋友、发明一个水陷阱）就别硬奖励，或者另做专门模式
- **PLAYER’S REMORSE（玩家悔恨）/ compulsion machine**（p.216–218）：≠ 买后后悔，≠ 输了不甘心；= 被动机推着玩、却没有得到满足之后的悔恨；作者给了一条光谱：奖励对齐、核心体验有意义 → 强迫和满足交替（多半是工艺失误）→ 只求动机最大化的 compulsion machine（Cow Clicker 是对它的戏仿）；作者声明本书讲工艺不讲伦理（p.218）
- **METAPHOR / METAPHOR VOCABULARY（隐喻 / 隐喻词汇）**（p.220–224）：≠ 修辞里的比喻；= 界面意义上的借用：电脑「文件夹」一词立刻教会人它大致怎么用；来源有真实物体、文化原型与惯例、游戏陈规、逻辑系统；metaphor vocabulary = 一套标明「哪些虚构元素有机制」的视觉约定（Prince of Persia 墙上的长划痕表示能墙跑），建立后必须一致
- **NOISE（噪声）/ signal**（p.225–227）：≠ 只是无意义的杂讯、画面脏；= 任何没有给玩家的心智模型增加有效信息的信号：被美术复杂度淹没的、太难解读的、挤在一起的、超出吸收上限的；所以玩家「没注意到」时，把那个信号调大常常是错的，问题在总负载
- **VISUAL HIERARCHY（视觉层级）**（p.227–230）：借自平面设计，作者按常见义使用；特别之处在用途：用它解决「全显示会淹没新手、少显示老手不够用」的两难；按重要性和学习顺序给每个信息在可见度梯度上定档（弹药数、受伤红屏）
- **HOMOGENOUS / DIVERSE / PASSIVE REDUNDANCY（三种冗余）**（p.230–231）：≠「冗余 = 浪费」；= 为关键信息设计的多重传达，前提是玩家本来就会漏掉不少内容（跳窗例：同伴喊话、挥手动画、高亮木板路径、HUD 目标四重冗余）；passive 的风险：分不清玩家是没看到还是故意不理，反复提示会惹人烦；它和 noise 的「信号过载」怎么协调，作者没说（编者评注「作者自留的张力」）
- **INDIRECT CONTROL — NUDGING / PRIMING / SOCIAL IMITATION（间接控制及三法）**（p.232–235）：≠ 潜意识广告、神经语言程式学：作者明确排除；= 安排信息，让行为自然流向预期方向；nudging 改默认项、选项排列、照明；priming 激活概念（相关研究书外待核）；social imitation 用 NPC、同伴、AI 对手示范；「玩家察觉不到」被当成优点讲，知情问题作者没讨论（编者评注）
- **MAPPING / CONTROL EXCLUSIVITY（映射 / 控件互斥）**（p.236–237）：mapping ≠ 键位表本身；= 物理控件和游戏内效果之间的相似性（位置、形状、动作的对应），好的映射自带记忆提示；exclusivity = 由身体和控件的位置关系决定哪些控件不能同时用（两个键都只能用左手食指按），进而决定哪些动作能组合
- **CONTROL FEEL（操控手感）**（p.235–239）：≠ 手柄、外设的物理手感；= 每一刻把意图投射进游戏的体验，由一组玩家看不见的微规则构成（Mario 的跳跃）
- **INPUT ASSISTANCE（输入辅助）**（p.239–241）：≠ 自动代打、外挂；= 对原始输入的预处理，猜测意图后悄悄修正（Halo 的辅助瞄准）；作者主张隐形，公平与知情问题作者没讨论
- **CONTROL LATENCY（操控延迟）**（p.241–245）：≠ 网络延迟（ping）；= 本机从收到输入到显示可感知反馈之间的管线延迟，硬件里就有，无法消除；延迟长短决定玩家要提前多少预判；作者据此在 30 和 60 fps 之间取舍（技术前提有时代局限，见编者评注）
- **tournament market（锦标赛市场）/ Matthew effect / INNOVATOR’S DILEMMA**（p.249–251）：≠ 电竞锦标赛；= 游戏是非竞争性商品（nonrival good，多卖一份的成本近乎为零），所以每个细分市场赢家通吃，失败者大多看不见（幸存者偏差）；Matthew effect 让领先者更领先；innovator's dilemma 又让在位者成了守着旧胜利的静止靶子；推论：把资源集中到能胜过所有竞品的少数价值上（「MARKET VALUE / VALUE CURVE（市场价值 / 价值曲线）/ value focus」）
- **MARKET SEGMENT（细分市场）**（p.251–255）：≠ 只按年龄、性别划分的用户画像：作者的划分包括「已有技能」和「能用的技术」；细分之间彼此重叠，所以要用 value curve 细化；没被满足的细分无法事先测量（The Sims 早期在公司内部不被看好）
- **MARKET VALUE / VALUE CURVE（市场价值 / 价值曲线）/ value focus**（p.255–261）：market value ≠ 第 1 章的 human value（「HUMAN VALUE（人的在乎之物）」），≠ 第 17 章的 value（「VALUE（价值观）」）；= 游戏体验里以特定方式吸引某类人的一个方面（The Sims 的「创意建房」）；value curve 把自己和竞品按各项市场价值逐项打分、画在同一张图上；value focus：资源越少，越要把力气集中在少数优于所有竞品或独有的价值上（「成功小游戏几乎都是尖刺形」有幸存者偏差，见编者评注）
- **CONFIRMATION BIAS（确认偏误）/ setting expectations**（p.264–266）：常识里多指「只找支持自己观点的证据」；作者用在玩家的感知上：预期会直接改变玩家对品质的感受（加醋的 MIT Brew、盲测可乐）；所以设定预期本身就是设计工作
- **busy idiocy（瞎忙）**（p.269–270）：≠ 偷懒、效率低；= 很努力，但用力在对体验影响很小的地方：为几乎无关紧要的功能钻好几天技术难题、给注定被砍的东西做美术、该造的时候测、该测的时候造；不会自己纠正
- **borrowed / inborn assumptions（借来的 / 天生的假设）**（p.271–275）：borrowed：从电影、软件、工业借来的流程词（preproduction、beta、director）连带的隐含前提，在游戏里往往不成立；inborn：认知偏差，书里点名 halo effect（不能分开评判一个东西的各方面）、loss aversion（导致承诺升级）、availability heuristic、Kahneman 的 WYSIATI；≠「质疑一切」：只是把假设找出来，确认它基于事实而不是习惯
- **ITERATION（迭代）**（p.283–287）：≠「多改几版」，也不等于某个敏捷框架的冲刺；= 用「短程计划—实现—测试」的循环代替线性的「计划—建造—验证」；作者在第 12 章自称这个三步环是「criminal oversimplification」（p.321），真实过程是按情况出牌的知识创造（「knowledge creation（知识创造）/ rumination」）；「迭代轮数是质量最重要的决定因素」是作者的经验断言（编者评注）
- **PLANNING HORIZON（规划视距）/ overplanning / underplanning**（p.277–289）：≠ 项目排期总长、里程碑；= 两次测试之间往前计划多远；计划越不确定、测试越便宜，视距越短；原创游戏视距短、换皮游戏视距长；项目越往后视距越长；章首用 Overplanner（200 页设计文档）和 Underplanner（不计划就开干）两个故事说明两头的代价，作者认为过度规划更常见、伤害更大
- **hill climbing（爬山算法：迭代的边界）**（p.289–290）：= 迭代像蒙着眼的登山者，只能爬到脚下这座坡的顶（局部最优），看不见不远处的大山；要跳到别的山，只能不经测试地大改、做深度计划，自担落空的风险；什么时候该跳，作者没给判据（编者评注「作者自留的张力」）
- **THERAPEUTIC PLANNING（治疗性计划，原书拼作 THERAPUTIC）**（p.292–293）：≠ 心理治疗；= 不是为了协调工作、而是为了缓解不确定带来的焦虑而做的计划，制造虚假的确定感；是作者列的过度规划五个原因之一：文化习惯、天生的过度自信、治疗性计划、群体计划偏差（群体奖励过度自信者，「Confident Bob」）、后见之明偏差
- **HINDSIGHT BIAS（后见之明偏差）**（p.294–295）：按心理学常见义（原文举 Baruch Fischoff 的尼克松访华研究）；作者用它解释：为什么有人连做 10 个过度规划的项目还学不到教训——复盘时把弯路记成「本来就该知道」；作者在这里警告过它，却没用在自己若干「幸存者」式论证上（编者评注）
- **TEST PROTOCOL（测试协议）/ self-testing / over-the-shoulder / Kleenex testing**（p.295–300）：≠ QA 测试用例；= 一次试玩的规则与程序：谁来测、怎么看、问什么、测多少次；坏协议不会报错，反而让测试更顺，产出「以为游戏行了」的假知识；自测最便宜，用于最早几轮；旁观测试（over-the-shoulder）全程沉默；Kleenex 测试者只能用一次；第 12 章另区分 playtest、usability test、QA test、focus test（p.316）
- **GRAYBOX（灰盒）**（p.300–303）：≠ 只是关卡白模：几乎什么都能灰盒（过场换静图或文字、复杂界面换带标签的按钮、对白用 TTS）；≠ 设计文档：能跑的灰盒才是游戏的「剧本」；音画驱动的体验不适合灰盒（What Not to Graybox）；评审灰盒需要专门的能力，否则受 halo effect 影响
- **PREMATURE PRODUCTION（过早投产）**（p.301–302）：判据不是美术好不好、项目到了哪个阶段，而是「下一轮测试数据需不需要它」；代价：此后每轮迭代都要返工美术；美术还会改变玩家对机制的感受，加了要复测
- **PARADOX OF QUALITY（质量悖论）**（p.303–304）：≠「质量不重要」「凑合就行」；= 早期迭代里按成品质量要求每一步，会拖长每一轮、减少轮数，最后反而更差；造甲板、修水坝相反，因为那里的错误很难撤回
- **FALLACY OF VISION（愿景谬误）**（p.304–305）：≠「不要有愿景」；= 把脑子里的「体验电影」（Gilbert 所说的 prefeeling）当成生成这段体验的系统设计；年轻工程师描述的是一次飞行，不是一架飞机；回到 GAME 的定义（「GAME（游戏）」）：要设计的是系统
- **unknown unknowns / serendipity（未知的未知 / 意外发现）**（p.305–308）：借自 Rumsfeld 的三分法；= 连「可能存在」都没意识到的错误和机会（难修的退化策略、意外好玩的行为）；serendipity ≠ 纯靠运气：靠观察和应变去捕获；「意外发现是革命性设计的主要来源」有幸存者偏差（编者评注）
- **knowledge creation（知识创造）/ rumination**（p.311–321）：≠ 知识管理、写文档；= 发明并打磨「关于这个设计的知识」：游戏是知识系统，不是制造出来的物件（「It’s not a chess set. It’s chess.」，p.311）；方法像一副牌，按当前的未知来出：rumination（长时间反刍，需要放松）、research、artistic methods、brainstorming、written analysis、debate、testing、metrics、自创方法
- **DEPENDENCY（依赖）**（p.323–326）：≠ 软件包依赖，≠ 排期上的先后；≠ 泛泛的「互相影响」；= 设计上的牵制：底层的设计一变，上层就得跟着改（关卡美术依赖布局，布局依赖玩家工具，工具依赖基本界面）
- **DEPENDENCY STACK（依赖栈）**（p.324–329）：≠ 技术架构图；= 把设计拆成元素（机制、操控、界面、子系统），只标关键依赖、画成栈；用途是排开发顺序：先做栈底，底层迭代到足够稳再往上
- **cascading uncertainty（级联不确定性）**（p.328–329）：= 每个元素都有「不按预期工作」的概率，沿依赖相乘：下面每层都有 80% 把握，上面几层的把握就很低；冒险的设计每个系统常常不到 30%，往上五层几乎一定要改（算例数字是示意，不是实测；「上层几乎总要大改」列为经验断言，见编者评注）
- **DESIGN BACKLOG（设计待办池）**（p.330–332）：≠ Scrum 的 product backlog：名字借自它，但作者说它不属于任何正式流程；= 无序、「液态」、不互相锁定的灵感池；把想法存起来，而不写成互锁的详细设计
- **CORE GAMEPLAY（核心玩法）**（p.332–334）：≠ 常说的「核心循环」示意图或卖点描述；= 删减练习剩下的、不可再删的最小机制集合及其涌现物（现代电子游戏常常能删掉 95% 以上）；判据是删完是否仍有情绪意义
- **Taylorism / distributed mind / tacit knowledge（泰勒制 / 分布式心智 / 隐性知识）**（p.338–341）：Taylorism 在知识少、重复性强的工作里有效，在游戏开发里失败：知识量太大，而且多是 tacit knowledge（技能和直觉说不出来，交不到领导手里）；替代模型是蚁群式的 distributed mind：各自按局部情况行动，集体智能从中涌现
- **NATURAL AUTHORITY（自然权威）**（p.341–343）：≠ 职级、头衔、天生的领导气质；= 按「谁最有相关知识」分配决定权；≠ 各干各的：决定常需要多人的知识，仍要沟通汇集（会议只请带着必要知识的人）
- **ARROGATION（越权）/ swoop and poop**（p.343–344）：≠ 傲慢的态度（arrogant）：是一种行为，拿走本该归别人自然权威的决定；常见形式：micromanagement（第 14 章义，「micromanagement（两处两义）」）和 swoop and poop（领导旁听一小时评审，甩下一串一线看来很蠢的改动）；作者说领导这么做不是因为蠢，而是缺一线上百小时迭代测试得来的知识
- **INTENT / SUMMARIES（意图 / 摘要）**（p.344–347）：intent ≠ 任务清单、具体指令：不说「把靴子换个颜色」，说这个角色的外观要服务什么目的；summaries ≠ 事无巨细的汇报：是高层教训的浓缩（某个关键系统就是不行、试玩者普遍卡在哪）；两者是一上一下的知识通道，领导拿摘要在关卡进程、剧情结构、市场定位这些宏观层面迭代
- **SELF-IDENTIFIED COMMITMENT（自我认同式投入）**（p.352–353）：≠ 敬业度、愿意加班；= 把这份工作当成自我的一部分，表现为不由自主地在洗澡、开车时琢磨项目；靠有意义的工作得来，不靠外在奖励
- **CLIMATE（氛围）/ risk ledger**（p.354–356）：≠ 公司文化、价值观宣言（第 16 章另有 culture：团队共享的期待、假设和习惯）；= 每天对工作的情绪，来自「冒险或质疑之后会被怎样对待」的预期；坏氛围是「沉默杀手」：不引发灾难，只是让冒险的想法不被提出；作者用一本心理账本对比好坏氛围下的利弊；（p.354–355 的账本是表格，转换时被误标成页边要点，这里只概述，不作引文）
- **PROGRESS PRINCIPLE（进展原则）**（p.360–361）：借自 Amabile；≠ 里程碑式激励；= 频繁、看得见的小胜比进展的大小更重要，哪怕整个游戏此时还很糟

- **VALUE（价值观）**（p.371）：全书三个 value 各不相同：HUMAN VALUE（p.12，「HUMAN VALUE（人的在乎之物）」）：事件改变的、人在乎的状态；MARKET VALUE（p.255，「MARKET VALUE / VALUE CURVE（市场价值 / 价值曲线）/ value focus」）：吸引某个细分人群的体验方面；VALUE（p.371）：设计师想成为什么样的人的选择；作者给了 openness、candor、humility、hunger 四条
