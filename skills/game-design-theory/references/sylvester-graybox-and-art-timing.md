# 灰盒与美术介入时机

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> A GRAYBOX is a low-fidelity placeholder version of a game mechanic, system, or level.
>
> 译：灰盒，是游戏机制、系统或关卡的低保真占位版本。
>
> — Tynan Sylvester, *Designing Games*, Ch11 Planning and Iteration / Grayboxing, p.300

> PREMATURE PRODUCTION is when a designer adds art and audio to a graybox design before it is necessary to get the next round of test data. … Art should be added as late as possible to get useful test data.
>
> 译：过早制作，是在拿下一轮测试数据还用不着的时候，就给灰盒设计加上美术和音频。……美术应当在仍能拿到有用测试数据的前提下尽量晚加。
>
> — Tynan Sylvester, *Designing Games*, Ch11 Planning and Iteration / Premature Production, p.301–302

> Nobody without practice in evaluating grayboxes should be doing it, because they’re very likely to make poor decisions due to the halo effect.
>
> 译：没练过评估灰盒的人都不该来评，因为他们很可能受光环效应影响做出糟糕的决定。
>
> — Tynan Sylvester, *Designing Games*, Ch11 Planning and Iteration / Graybox Evaluation Skill, p.302

## I — 方法骨架 (Interpretation)

这张卡回答「哪些先做灰盒、现在加不加美术、美术什么时候进来、谁能评灰盒」。灰盒（graybox）是用方块、文字、哔声这类廉价替身做出的可玩版本。作者的道理是：多数点子行不通，给没验证过的设计做全套音画是浪费；美术一旦加在还会变的机制上，之后每一轮都要返工，还可能把弱的机制盖住、锁死。反过来，好灰盒玩起来不像好游戏，评它要靠练习；没练过的人会因为画面丑否掉整个设计，这是光环效应（halo effect）：一个方面的好恶渗进对其他方面的判断。

五个分支按工作顺序排：分支 1 定灰盒的范围和替身，并标出灰盒测不到的情绪；分支 2 是每轮都会遇到的「现在加不加美术」；分支 3 安排美术的两个介入点和上美术后的复测；分支 4 在灰盒要交给别人拍板时定评审人，必须由没练过的人决定时要接受部分过早制作，这是分支 2 判据的例外，加多少由设计者定；分支 5 是更一般的评审方法，评任何设计元素时按方面拆开写价值和代价，美术精良的原型最需要它。

作者观点（只作参考）：游戏里最接近电影剧本的不是设计文档，而是能跑的灰盒原型，因为文档写的是机制，没人能在脑中把机制模拟成事件（p.302–303）。

## A1 — 书中案例 (Past Application)

- **分支 1｜Mass Effect 3 的灰盒生物（转述，p.300）**：巨型战争机器人是一个大方块、底下两根长条、两侧各一个方块当手臂；另一个高高的黄方块用两侧黄长条抓住主角。看着怪，但发生了什么一目了然，完全可玩，设计者因此不用给未验证的生物投美术就能迭代。**LIMBO、Flower 对 Counter-Strike、StarCraft II（例题，p.301）**：前两者极依赖音画驱动的情绪，灰盒里会损失很大；后两者一直是机制取胜，灰盒也好玩。
- **分支 2｜原书未提供案例，以下是合成演练**：平台跳跃游戏第 3 关灰盒试玩失败，玩家分不清哪些平台能踩，美术提议先把整关美术做完。下一轮要回答的是平台可辨识度，整关美术不是这份数据所必需，所以不做；理由写返工代价和机制被美术锁住的风险。
- **分支 3｜作者的射击战斗流程（作者亲历，p.285–287）**：概念定下后关卡美术只做可行性咨询，给塔或桥一个暗示风格和故事的形状；两三周旁观测试后美术才做第一遍，随即复测，出问题时作者改脚本、美术补光或简化。作者说幸运的话美术不会带来大问题，几轮后机制和美术都成立。
- **分支 4｜原书未提供案例，以下是合成演练**：发行方高层下周要看一款原创动作游戏的灰盒并决定是否续投，他从没评过灰盒。两种安排：由有灰盒经验的主策评估、高层看结论；或高层必须亲自定，就为他要看的段落做有限的美术。
- **分支 5｜例题（p.273）**：长得好看的人显得更可信；游戏角色美术好，人就觉得它操控更准。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 要开始做原型，决定哪些东西用占位、用什么占位。
2. 里程碑或评审会前，有人想先上美术、特效、音效。
3. 试玩失败后，有人提议「加点美术就看清楚了」。
4. 关卡美术问什么时候能开始做，或上了美术后试玩变差。
5. 发行方、高层或外部评审要看灰盒并拍板；评审会上大家都很喜欢一个特效华丽的原型。

**语言信号**

- 先做白模还是直接上美术 ／ 现在加不加特效 ／ 评审会前要不要做得好看点 ／ 美术什么时候介入 ／ 老板看了灰盒觉得不行 ／ 这个原型看着很爽
- graybox ／ greybox ／ whitebox ／ placeholder art ／ premature production ／ when to add art ／ halo effect ／ stakeholders reviewing a prototype

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 要做原型：哪些部分灰盒、用什么替身、灰盒在这里管不管用 | 分支 1 |
| 现在要不要给灰盒加美术或音频 | 分支 2 |
| 关卡美术什么时候参与、上美术后怎么测 | 分支 3 |
| 灰盒要交给别人评审或拍板 | 分支 4 |
| 评一个设计元素，担心整体好恶（尤其美术）带偏判断 | 分支 5 |

### 分支 1：灰盒范围、替身与适用性

- **输入**：这次要测的部分；每部分的体验靠什么起作用（机制、虚构意义、音画）。说不清先问。
- **步骤**：
  1. 列出要测的部分；几乎什么都能灰盒，不只是关卡（p.300）。完成标准：清单。
  2. 每部分选替身（p.300）：过场 → 静图或静态文字弹窗；复杂界面 → 带标签的按钮；声音 → 廉价合成音；对白 → 文字转语音或屏幕文字；生物 → 方块组合。完成标准：每部分一个替身；这五类之外的替身原书未说明。
  3. 查可读性：替身看着怪没关系，要一眼看得出发生了什么，看得出就能玩（p.300）。完成标准：每个替身标「看得出 / 看不出」，看不出的重选。
  4. 判断这段体验多依赖音画驱动的情绪：越依赖，灰盒越没用（p.301）。原书只有程度原则和 A1 的两对正反例，没有分界线：列出作者的例子，由设计者判断。完成标准：每部分写出判断和理由。
  5. 写明灰盒测不到什么：缺失的美术和音乐本该驱动的情绪（p.301）。完成标准：「测不到」清单。这些部分该怎么测，原书未说明。
- **输出**（约定）：表「部分 / 替身 / 看得出吗 / 音画依赖判断 / 灰盒测不到的情绪」。

### 分支 2：过早制作的判断

- **输入**：想加的美术或音频；下一轮测试要回答的问题。后者说不清先问，没有它这条判据用不了。
- **步骤**：
  1. 认出冲动从哪来：评审会上好看、让人心动；或试玩失败后想用美术盖住设计问题（p.301–302）。完成标准：写明来源。
  2. 写出下一轮测试要拿的数据（p.301）。完成标准：一句话的测试问题。
  3. 问：拿到这份数据需不需要这份美术或音频？不需要就留在灰盒；需要就只加拿数据所需的部分，并尽可能晚加（p.301–302）。完成标准：每项写「加 / 不加」。
  4. 写理由，用作者的两重代价：此后每一轮都要返工美术去配合变动的机制；美术盖住弱机制后，不撕掉美术就修不了（p.302）。完成标准：每项有理由。
  5. 例外：评审者没有灰盒评估经验、又必须由他决定时，可能要接受一些过早制作并承担代价（p.302），转分支 4。「一些」是多少原书未说明。
- **判停 / 转向**：音画驱动的部分，这条判据要和分支 1 的适用性一起看。
- **输出**（约定）：决定表「拟加项 / 冲动来源 / 下一轮测试问题 / 加或不加 / 理由」。

### 分支 3：美术的两个介入点与上美术后复测

- **输入**：灰盒处在哪个阶段（概念刚定 / 已充分旁观测试）；团队有没有关卡美术。
- **步骤**：
  1. 概念定下、进入细化时，请关卡美术做美术可行性咨询，此时他还不直接做空间（p.285）。完成标准：咨询排进日程。
  2. 咨询的产出（p.285）：概念在美术上说不通，可能从头再来；更常见的是调整空间，让塔或桥这类形状暗示风格、主题、世界故事和氛围；美术可以做 mock-up 或美术测试关。一般灰盒同样请美术对「这个方块能变成什么」出意见，让他对之后要美化的灰盒已有参与、能认同（p.301）。完成标准：写下咨询结论。
  3. 第一遍美术在灰盒充分旁观测试之后做（p.286）；作者例子里是在战斗节奏和平衡都好之后，一般时机用分支 2 的判据。完成标准：写明开始条件。
  4. 上美术后立即复测：机制形状没变，美术也会改变玩家对它的感知；出问题时设计改脚本细节（增减角色或道具），或美术补光、简化以减少美术噪声（p.286）。原书只说要看美术怎样影响试玩，没给比较方法：由设计者对比美术前后试玩里出现的问题。完成标准：美术前后各有问题记录，新问题有处理去向。
- **输出**（约定）：介入表「介入点 / 时机 / 美术做什么 / 产出」；复测记录「美术前问题 / 美术后新问题 / 处理」。

### 分支 4：灰盒评审资格

- **输入**：会对这个灰盒下结论的人。
- **步骤**：
  1. 列出这些人（p.302）。完成标准：名单。
  2. 标出每人有没有评估过很多灰盒的经验：好灰盒玩起来不像好游戏，评估要靠练习得来的情绪校准（p.302）。「练过」的门槛原书未说明，由团队认定。完成标准：每人标「练过 / 没练过 / 不确定」。
  3. 没练过的人标光环风险：画面丑的印象会外溢成对整个设计的否定，运转良好的设计也会被否掉（p.302）。尽量让练过的人做决定。完成标准：风险逐人写明。
  4. 必须由没练过的人决定时，接受一些过早制作，给他做出能看的部分，并承担代价（p.302）；加多少、加哪些原书未说明（只说 some），由设计者定。完成标准：写明「换人评估」或「接受部分过早制作」。
- **输出**（约定）：评审人表「人 / 灰盒评估经验 / 光环风险 / 安排」。

### 分支 5：分方面评估

- **输入**：要评审的设计元素。原书没给方面清单，从项目自身或第二部分各视角取。
- **步骤**：
  1. 把元素拆成各个方面（p.273）。完成标准：方面清单。
  2. 每个方面写出价值和代价：总有某种价值，也总有某种取舍（p.273）。完成标准：每行两栏都填了。
  3. 写各方面怎样配合、怎样作用于最终体验（p.273）。
  4. 再下整体结论，留意某一方面（如美术好）是否在拉高对其他方面（如操控）的评价（p.273）（约定：原书只说要拆开看，最后这步是写卡时整理的）。完成标准：结论能指回各行。
- **判停 / 转向**：作者说靠理性压过偏差有限，更可靠的是带制衡的流程（p.274），所以本分支不承诺消除光环效应；流程层面的制衡见 `sylvester-process-and-planning-horizon.md`。
- **输出**（约定）：表「方面 / 价值 / 代价 / 与其他方面的配合」，加一句整体结论。

## B — 边界 (Boundary)

**不要用这张卡**

- 定迭代环和阶段 → `sylvester-iteration-loop.md`；美术噪声让玩家看不清机制，要改视觉 → `sylvester-mechanic-metaphor.md`。
- 用灰盒结论去判断以音画驱动情绪的部分：灰盒测不到那些情绪（p.301）。

**作者警告的失败模式**

- 过早制作：评审会上的笑容很短，美术成本却要在之后每一轮重付；弱机制被美术盖住后改不动（p.301–302）。预警：失败的试玩之后第一反应是「加点美术就好了」；原型评审被要求看起来像成品。
- 没练过的人因为丑否掉好灰盒，作者说这通常是真实流程里灰盒最大的问题（p.302）。预警：灰盒反馈集中在「看起来不行」；高层第一次看到的是灰盒。
- 对设计元素整体喜欢或整体讨厌，是偷懒又误导的捷径（p.273）。预警：评审意见只有整体好恶，没有分项。

**作者盲点与时代局限**

- 作者立场偏机制驱动游戏，对以音画或线性叙事取胜的游戏只给一两句承认（编者评注，非原书）。
- 默认团队里有专职关卡美术、测试资源充足（编者评注「团队规模」）。

**各分支的已知缺口**

- 分支 1：适用性只有正反例，没有判别标准；「灰盒成本可能低一百倍」是作者的经验估计（p.300）；替身清单只覆盖五类。
- 分支 2：例外里的「一些」没有量；两重代价是作者的定性论证；音画驱动的游戏要和分支 1 一起看。
- 分支 3：除第 2 步后半（p.301）外，各步都来自同一个射击战斗例子；与 `sylvester-iteration-loop.md` 分支 2 的细化轮、美术轮重叠；默认有专职关卡美术。
- 分支 4：「这通常是最大的问题」是作者的经验判断；评估能力怎么培养只说靠练习；外部决策者（发行、投资方）的权力关系作者没展开。
- 分支 5：作者说个人理性对抗偏差有限（p.274），要配合流程层面的制衡；原文只是偏差举例中的一段。
