# 信息平衡：决策太难懂或太明显

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> The same decision can be made incomprehensible with too little information, fascinating with the right amount of information, and trivial with too much information. … INFORMATION BALANCING is the design process of providing or denying information to a player to make a decision comprehensible without being obvious.
>
> 译：同一个决策，信息太少会让人看不懂，信息恰当会让人着迷，信息太多会变得无足轻重。……信息平衡，就是通过给或不给玩家信息，让决策可以理解、又不显而易见的设计过程。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Information Balance, p.127

> A useful FAQ is a warning sign. When a text file makes a game noticeably better, that game is probably information-starved.
>
> 译：有用的 FAQ 是个警告信号。一份文本文件能让游戏明显变好，这个游戏多半信息饥饿。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Information Starvation, p.129

> Nothing breaks when there is too much information. Testers don’t get confused and cry for help.
>
> 译：信息太多时什么都不会坏。测试者不会困惑，也不会喊救命。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Information Glut, p.131

## I — 方法骨架 (Interpretation)

这张卡回答「决策太难懂或太明显，不改机制能不能修」。信息平衡（information balancing）只增减、重组玩家拿到的信息，机制不动，通常比改系统快也便宜（p.127）；它和第 6 章调强弱的 balancing 名字相近、做法相反。失衡有两种：信息饥饿（starvation），信息太少，玩家乱打乱选；信息过剩（glut），答案已经写在给出的信息里，决策消失。分析前要确切知道玩家决策时掌握什么（p.135）。

五个分支：分支 1 是总流程，清点信息、判偏向、调结构、判停；偏饥饿进分支 2，其中「要玩家在看到挑战前做准备」单独走分支 3，只诊断；偏过剩进分支 4；分支 5 是藏信息的选项表，给分支 4 和完全信息游戏用。信息来自虚构外衣或游戏之外的，走 `sylvester-fiction-and-metagame-info.md`。

## A1 — 书中案例 (Past Application)

- **分支 1｜扑克史（转述，p.133–135）**：最早 20 张牌、一轮下注，信息饥饿；改用 52 张牌若不加信息只会更饥饿，关键是加了多轮换牌和下注，能从别人怎么换、怎么下注读牌；stud 亮三张明牌，滑到过剩（对方明牌三条而你只有一对，根本不必跟）；公共牌（德州扑克）让作者评价为恰好平衡，很少产生明显或无从理解的选择。基本机制几百年没变。作者没给出处，只取设计论点。
- **分支 2｜纸板与步枪（例题，p.128–129）**：棋盘中间立纸板、黑暗里打网球，都塌成乱打和随机选。虚构说步枪伤害随距离、部位、弹道大幅变化，机制里只是固定扣血；这个数在虚构里说不出口，常常就不告诉玩家。**GameFAQs（转述，p.129–130）**：玩家写的 FAQ 讲清每个能力和隐藏数值，饥饿的游戏读了反而好玩。
- **分支 3｜Mass Effect 2（转述，p.128–129）**：RPG 开局就要定种族、职业、技能，影响后面 50 小时；六个职业里发售后数据显示 80% 选了最普通的 Soldier。
- **分支 4｜MW2 心跳传感器（转述，p.130–131）**：照实显示墙后敌人会让猫鼠游戏塌掉；设计者加两条限制：带 Ninja 天赋的不显示，每 3.5 秒才闪一次光点。伤害、移动、地图都没改。
- **分支 5｜四种藏法（例题，p.132–133）**：扑克看不到手牌；象棋全公开，但三步后的局面藏在因果链里；对手的计划藏在他脑子里；石头剪刀布同时出手，对方的手来不及用。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 试玩者乱试、随机选，或者靠攻略、社区数值表才会玩。
2. 试玩顺利、没人卡关，评价却是「平淡」「没张力」。
3. 开局要选职业、天赋、带入装备，玩家此时什么都不知道。
4. 讨论数值、敌人位置、对手手牌该显示还是该藏。
5. 完全信息的对战「看一眼就知道谁赢」。

**语言信号**

- 玩家乱选 ／ 看不懂怎么选 ／ 社区自己整理伤害表 ／ 太顺了没张力 ／ 要不要显示数字 ／ 视野开多大 ／ 大家都选最普通的职业
- information starvation ／ information glut ／ hidden information ／ fog of war ／ show the numbers ／ FAQ

**与相邻卡的区分（初稿）**

- 结果难预测是因为规则不一致或太复杂 → `sylvester-decision-quality-audit.md`
- 玩家不知道哪些虚构交互是真的；类型惯例让威胁失效 → `sylvester-fiction-and-metagame-info.md`
- 要改的是数值强弱 → `sylvester-balance-change-review.md`
- 信息给了，玩家没注意到 → `sylvester-signal-visibility.md`；读心、虚张 → `sylvester-yomi-depth.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 不知道偏哪边，或要整体调一个决策的信息 | 分支 1 |
| 乱试乱选、靠攻略才会玩 | 分支 2 |
| 开局或事前要做的准备性选择 | 分支 3 |
| 太顺、没张力，某个信息源把答案递给了玩家 | 分支 4 |
| 想藏信息造决策，要备选手段 | 分支 5 |

### 分支 1：调信息不改机制

- **输入**：要调的决策；玩家决策时掌握的全部信息、何时得到、公开还是私有；试玩表现。信息清单缺了先列，不要猜（p.135）。
- **步骤**：
  1. 清点决策时玩家确切掌握哪些信息、怎么得到（p.135）。完成标准：每个决策一张信息清单。
  2. 判偏向：太少，决策无从理解 → 分支 2；太多，决策琐碎 → 分支 4（p.127, p.130）。完成标准：每个决策标「饥饿 / 过剩 / 合适」。
  3. 只调信息结构，胜负规则不动。列出可动的杠杆：哪些信息隐藏或公开、分几轮揭示、私有还是公开、是否由多人共享。这份清单是从扑克一例重建的（牌数、下注与换牌轮次、明牌、公共牌，p.133–134）。完成标准：杠杆清单，方案里没有改机制的项。
  4. 审反例规则：只增加可能性、不增加区分它们的信息，会更饥饿（p.133）。完成标准：每个「加选项」都配了区分信息，或删掉。
  5. 逐轮调，每轮后复看决策是否很少显得明显、也很少无从理解（p.134）；摆过头就调回，扑克从单轮下注（饥饿）到多轮换牌，到明牌 stud（过剩），再到公共牌（平衡）（p.133–135）。每轮只动一个杠杆（约定，便于看出是哪项起作用）。完成标准：迭代记录，每轮写明动了哪项、结果偏哪边。
- **判停 / 转向**：作者的判停口径是定性的：很少产生明显或无从理解的选择（p.134），没有数量指标。平衡点靠试玩判断，本卡不承诺数值；扑克的平衡点是长期实际游玩出来的，作者说花了两个世纪（p.135）。
- **输出**（约定）：表，列为「决策 / 现有信息 / 偏向 / 增减或重组项」，加迭代记录。

### 分支 2：信息饥饿诊断与修正

- **输入**：症状；游戏的主要情绪触发器；谁在测。
- **步骤**：
  1. 排除饥饿是设计目标的游戏：海战棋和多数赌博游戏的主要触发器不是决策，随机让它们更易上手、更社交（p.128）。完成标准：写明本作主要触发器是不是决策，不是则停。
  2. 查症状与警告信号：玩家只能被动反应、乱打、随机选（p.128）；一份 FAQ 或数值表让游戏明显变好（p.129）。完成标准：两项各写有无及证据。
  3. 查成因，对应修正方向（p.128–129）：遮挡式（视野小、牌没亮）→ 扩视野、多亮牌；驱动决策的机制数据（伤害、移动速度、任务结构、经济数表）在虚构里说不出 → 作者说常常最好绕过虚构直接给一部分，没给何时不该绕的条件；要在看到挑战前做准备 → 分支 3。完成标准：每个成因有修正方向或转出。
  4. 查盲区：设计者知道一切，体验不到新玩家的处境；找饥饿会威胁「终于做成了」的成就感，人不愿去找；没有试玩或其他保障就会误判（p.129–130）。完成标准：写明是否只有开发者在测，有没有安排外部试玩，争取发布前找到（p.130）。
- **判停 / 转向**：本分支只给方向，补到什么程度交分支 1 的逐轮迭代和试玩；补完按分支 4 复看是否摆到过剩。外部试玩怎么组织本节没展开，第 11 章有找从没玩过的人测开头几分钟的 Kleenex 测试（p.297–298）→ `sylvester-playtest-protocol.md`。
- **输出**（约定）：表，列为「成因 / 证据 / 修法 / 页码」，另附盲区一条。

### 分支 3：作者化挑战的准备问题

- **输入**：要玩家提前做的准备性决策（建角、预选装备、天赋）；做选择时玩家能看到什么；选择分布数据（如有）。
- **步骤**：
  1. 判成立条件：游戏由一串设计者编排的挑战组成，要求玩家在看到挑战前为它准备，而游戏内无法预知下一个挑战（p.128）。完成标准：问题点清单。
  2. 每个问题点列出玩家当时缺的信息，作者在建角上举的是战斗平衡、自己对工具的偏好、将遇到的敌人（p.128）。完成标准：「准备决策 → 缺的信息」。
  3. 用选择分布作旁证：选择是否扎堆在最熟悉、最保险的选项。原书描述了这种扎堆（p.128）和 ME2 发售后 80% 选 Soldier 的数据（p.129），没有把选择分布当检查手段（约定：从 ME2 一例推出的旁证做法）。完成标准：写明有无数据、是否扎堆。
- **判停 / 转向**：扎堆到什么程度算问题，原文没有阈值，由设计者定。原文只诊断、不给解法，本分支不补造解法，记为开放问题交设计者。
- **输出**（约定）：问题点清单，加数据信号。

### 分支 4：信息过剩诊断与减信息

- **输入**：「太顺、没张力」的试玩表现；可能直接给出答案的信息源。
- **步骤**：
  1. 识别：过剩不报错，测试者不困惑，游戏运转得过于顺滑，最难的是意识到它在发生（p.131）。完成标准：写明判为过剩的依据。
  2. 找出把某个核心决策的答案直接给出的信息源：答案明摆着就没有思考（p.130）。作者判 MW2 过剩的依据是，这款游戏很多最好的玩法来自判断敌人在哪，传感器抹掉了这个决策（p.130）。某个决策是不是本该存在，原文没有判据，由设计者认定。完成标准：信息源清单，每条写明它抹掉了哪个决策。
  3. 减信息而不删掉它，MW2 的两种做法：加例外（Ninja 不显示，「没显示」不等于没人）、改间歇（光点间歇出现，其间要推断）（p.131）。3.5 秒的间隔只属于该例。完成标准：每个信息源一个减法方案，或写明不改。
  4. 写出减法生出的新决策和高手策略，作者例：记住谁带了 Ninja，故意躲开光点位置（p.131）。完成标准：每个方案都写得出新决策，写不出就重想。
- **判停 / 转向**：本分支只承诺用这两种减法处理已认定的过剩信息源。它们只出自 MW2 一例，不是减信息手段的全集；要更多藏法 → 分支 5。
- **输出**（约定）：表，列为「信息源 / 减法 / 生出的新决策」。

### 分支 5：隐藏信息的四种方式

- **输入**：关键决策清单；每个决策现在靠什么藏信息。
- **步骤**：
  1. 逐个标隐藏方式（p.132–133）：不完全信息（部分状态对某些玩家不可见）；藏在复杂因果链后的未来；藏在玩家的内部状态（计划、看到和没看到的弱点）；被速度隐藏（零点几秒内到达的信息来不及用）。完成标准：每个决策标一种以上或「无」。
  2. 标「无」的列为过剩风险（p.131–132），配上可选的方式。各方式的前提从定义推出（约定）：内部状态要有对手，速度要有实时或同时出手，因果链要系统够复杂。完成标准：每个「无」至少一种候选，写明前提是否满足。
- **判停 / 转向**：选哪种原文没有判据，由设计者定。完全信息游戏也能靠后三种方式产生决策（p.132），候选不限于藏状态。
- **输出**（约定）：表，列为「决策 / 现有方式 / 候选方式」。

## B — 边界 (Boundary)

**不要用这张卡**

- 规则不一致、太复杂 → `sylvester-decision-quality-audit.md`；改数值强弱 → `sylvester-balance-change-review.md`。
- 饥饿本身是目标的游戏（海战棋、赌博类，p.128）。

**作者警告的失败模式**

- 以决策为核心的游戏信息饥饿，塌成乱打乱选（p.128）。
- 为保持虚构纯粹，机制数值只给形容词（p.129）。
- 新机制只由设计者自测（p.129–130）。
- 过剩因为不报错而没人发现；作者说它更像错失的机会而不是故障，最难的是意识到它在发生（p.131）。
- 只加可能性、不加区分信息（p.133）。
- 补信息补过头：分支 2 补完要按分支 4 复看。

**作者盲点与时代局限**

- 扑克史是作者的叙述、无出处，不宜当史实（编者评注，非原书），只取设计论点；分支 1 的杠杆清单也是从这一例重建的。
- FAQ 作为信号来自 2012 年前后 GameFAQs 的环境（p.129）。
- ME2 的 80% 是单一数据，不是阈值；作者用的是发售后数据，发售前要靠试玩里的选择分布。
- 本章发现问题几乎全靠人工试玩，ME2 是唯一的数据例；作者的埋点内容在第 12 章（p.316–318），编者评注认为全书对遥测着墨很少。
- 作者自称全书是模型和假设（p.375）。

**各分支的已知缺口**

- 分支 1：判停只有定性口径，没有数量指标。
- 分支 2：补多少、何时不该绕过虚构，原文没给；试玩怎么组织本节未展开。
- 分支 3：原书不给解法，扎堆没有阈值。
- 分支 4：只有 MW2 一例；发现过剩没有系统方法，只有「太顺」这一信号。
- 分支 5：选哪种方式没有判据；四种方式是作者对完全 / 不完全信息二分的补充，没说是穷尽的。
