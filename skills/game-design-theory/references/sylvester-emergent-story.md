# 涌现故事：查边界，再放大

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> The designer authors the boundaries and tendencies of the game mechanics, but it’s the interplay among mechanics, player choices, and chance that determines the actual plot of each emergent story.
>
> 译：设计者写的是机制的边界和倾向；每个涌现故事的实际情节，由机制、玩家选择和偶然之间的相互作用决定。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Emergent Story, p.91

> A label here, a name there, and the story blooms in the imagination.
>
> 译：这里一个标签，那里一个名字，故事就在想象里开出来了。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Labeling, p.93

> An image in the eye overrides an image in the imagination.
>
> 译：眼前的画面会盖掉想象里的画面。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Abstraction, p.94

> So sportscaster mechanics often work best when they don’t try to tell a whole story, but instead just kickstart the player’s own apophenic process.
>
> 译：所以解说类机制往往在不试图讲完整个故事、只把玩家自己的脑补启动起来时效果最好。
>
> — Tynan Sylvester, *Designing Games*, Ch4 Narrative / Sportscaster Systems, p.96

## I — 方法骨架 (Interpretation)

涌现故事是玩法中由机制和玩家互动生成的故事（p.90）。设计者不写具体事件，只通过机制决定游戏能生成哪类故事。它的发动机是 apophenia（空想性错觉）：人会在复杂数据里看出并不存在的模式，尤其爱看出性格和意图。游戏不必模拟真实的心智，只要让玩家把某物读成有意图的主体，玩家就会自己补完（参考单元，p.92–93）。

五个分支。分支 1 先查边界：想要的故事，机制能不能生成。分支 2–5 是四种放大手段，都不加玩法机制，只改玩家怎么读事件：给个体贴标签（2）；找出盖掉想象的表现细节（3）；替玩家记住发生过的事（4）；把事件串成解说（5）。2 和 3 相连：标签太具体或配上表演，会反过来盖掉想象。作者称 5 是一种更高级的记录，所以做 5 之前先看 4。

作者观点（参考单元）：涌现故事这个概念的价值只在于换个角度想。同一段生成的体验，可以用故事的眼光问：人物塑造有没有意思，高潮是否不可预测却必然，铺陈是否顺滑（p.91）。这几问只是例子，答案怎么判原书不给。

## A1 — 书中案例 (Past Application)

- **分支 1｜Assassin’s Creed: Brotherhood（转述，p.90–91）**：玩家经历了数百万个战斗、刺杀、屋顶逃亡的故事，却没有一个是刺客早上刷牙，因为刷牙不是机制。张力：Close Combat 没模拟战友情谊，玩家照样脑补出来（p.93）。
- **分支 2｜Close Combat 与 Medieval: Total War（转述，p.93）**：前者给每个士兵命名、记录战绩，玩家发现一个班只剩两人，会想象他们的羁绊，下一仗命令其中一人牺牲时心里不安；后者在结婚、打胜仗后给贵族贴「酒鬼」「无畏」「懦夫」，带加成和弱点，将军会因为有了女儿、太爱家人、不肯战死而输掉一仗。**戴鹿角的掠夺者（作者亲历，p.115）**：头盔让他成了「那个怪掠夺者」；作者建议给面目模糊的敌人加疯医生、酒保、主人、奴隶之类身份，原书未说明是否实施。
- **分支 3｜Dwarf Fortress（转述，p.94）**：全是 ASCII 字符，外人看是乱码，玩家看到河边草地上一对矮人夫妻在共度片刻。反事实：Medieval 的将军若配上和妻子互动的视频，Close Combat 最后两人若能拉近看到各自播待机动画，玩家脑中的性格和羁绊就没了。
- **分支 4｜三个记录（转述，p.95）**：Civilization IV 每回合暗中记下国界，终局放一段疆界变迁的缩时地图；Myth 留下每具尸体、断肢、焦痕和血迹，战后能读出「最后坚守」，作者称之为涌现的 mise-en-scène；The Sims 让玩家拍照配字做相册，好的做成了博客，如 Alice and Kev。
- **分支 5｜Hitman: Blood Money 的关后报纸（转述，p.96）**：报道随刺杀方式、命中率、开枪数、爆头、误杀、目击者等变化，标题从「无声刺客遭警方通缉」到「流氓屠杀 17 人！」，目击者越多，嫌犯画像越准。原书未说明效果。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 系统驱动的游戏（模拟、策略、沙盒、肉鸽）想让玩家自己讲出故事，或宣传要卖「每局都是你的故事」。
2. 单位、角色只有数值，没有故事感。
3. 在考虑做回放、战报、关后总结、解说或相册。
4. 美术和演出要加码（近景镜头、个体动画、配音），怕挤掉玩家的脑补。

**语言信号**

- 怎么让玩家自己讲故事 ／ 沙盒没有故事感 ／ 要不要给单位起名、加性格 ／ 做不做回放或战报 ／ 演出是不是做太细了
- emergent narrative ／ player stories ／ apophenia ／ unit names and traits ／ replay ／ after-action report ／ sportscaster ／ abstraction

**与相邻卡的区分（初稿）**

- 某块故事该交给涌现还是脚本、世界叙事；拆一段游玩逐段归因 → `sylvester-narrative-tool-allocation.md`
- 设计者预先布置的环境线索 → `sylvester-world-narrative.md`（本卡分支 4 的痕迹是玩法留下的）
- 机制决策要的数值、范围该给多少 → `sylvester-information-balance.md`、`sylvester-fiction-and-metagame-info.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 想让玩家讲出某几类故事，机制撑不撑得住 | 分支 1 |
| 个体只有数值，想要故事感 | 分支 2 |
| 要加美术、动画、配音或近景镜头 | 分支 3 |
| 玩家记不住发生过什么；想做回放、痕迹、相册 | 分支 4 |
| 想做战报、解说、关后报道 | 分支 5（先看分支 4） |

### 分支 1：故事种类 × 机制对照

- **输入**：团队希望玩家讲出的故事种类；现有机制清单。
- **步骤**：
  1. 对每种故事，找能生成其事件的机制（p.90–91）。
  2. 三档标注：完全没有机制生成相关事件的，标「不能涌现」（刷牙，p.90–91）；有能生成它的机制，标「能」；有相关事件但没直接模拟、可能靠 apophenia 脑补出来的，标「待设计者判断」（p.93）。完成标准：每种故事一档。
  3. 把「不能涌现」清单交回机制讨论：设计者正是通过机制划定涌现故事的边界与倾向（p.91）。改用其他叙事工具 → `sylvester-narrative-tool-allocation.md`（约定）。
- **判停 / 转向**：只能查边界，不能估各类故事出现的概率（倾向），原书未说明方法。
- **输出**（约定）：故事种类 × 机制对照表。

### 分支 2：给现有机制贴标签

- **输入**：玩家会持续关注或反复接触的个体；它们现有的数值。
- **步骤**：
  1. 找候选个体：士兵、贵族、将领、敌人（p.93，p.115）。
  2. 命名并追踪经历，让玩家能翻看记录（p.93）。
  3. 用事件触发的性格标签代替或补充数值，标签可带加成和弱点（p.93）。
  4. 给面目模糊的普通敌人加身份或外观标签（p.115）。
  5. 不为标签补模拟：故事在玩家脑中完成（p.93）。完成标准：候选个体与标签形式清单。
- **判停 / 转向**：给谁贴、贴多少、带不带机制效果，原书未说明（Close Combat 的名字没有效果，Medieval 的标签有），由设计者定。标签很具体或要配表演 → 分支 3。
- **输出**（约定）：表，列为「个体 / 名字与记录字段 / 标签 / 触发事件 / 效果」。

### 分支 3：找出会盖掉想象的细节

- **输入**：本作靠玩家脑补性格和关系的地方；拟加的表现细节。
- **步骤**：
  1. 找出靠脑补的地方：贴了标签的个体、远景表现的单位（p.93–94）。
  2. 列会盖掉脑补的细节：表现其态度的视频、彼此无视的通用待机动画、能拉近看清的镜头（p.94）。完成标准：每项写明盖掉了哪个解读。
  3. 每项权衡：画面、声音、对白越细，加了东西也挤掉解读空间，作者只说「有时值得」故意少传达（p.94）。删不删、抽象到多少由设计者定。
  4. 参考品类距离（作者观察）：用数值和符号远距表现的品类更容易生出玩家自编的故事，贴身视角的品类往往展示太多（p.94–95）。
- **判停 / 转向**：只管虚构表现层。机制决策需要的信息不能因此减少：第 5 章说这类信息常常只存在于机制里，虚构传达不了时，往往宁可绕过虚构直接给（p.129）→ `sylvester-information-balance.md`。
- **输出**（约定）：表，列为「细节 / 盖掉的解读 / 备选做法」。

### 分支 4：替玩家记住事件

- **输入**：要替玩家记住的事件类别；能让玩家回顾的时点。
- **步骤**：
  1. 写明要记住哪类事件；目的是让玩家不必全凭记忆拼出故事（p.95）。
  2. 按三种形式列候选：暗中记录、事后回放；在世界里保留痕迹；给玩家自建记录的工具（据三例归纳，p.95）。完成标准：每个候选写明它让玩家回想起什么。
  3. 安排在玩家能回顾的时点呈现，如终局、战斗结束后（p.95）。
- **判停 / 转向**：记哪些事件、用哪种形式，原书未说明。
- **输出**（约定）：候选记录功能清单。

### 分支 5：解说系统，只起头

- **输入**：系统能测到的事件变量；呈现时点。
- **步骤**：
  1. 列变量，参照 Hitman：击杀方式、命中率、开枪数、爆头、误杀旁人数、目击者数（p.96）。
  2. 把变量区间映射成解读性输出，如标题档位、画像清晰度（p.96）。
  3. 在一段游玩结束后呈现，把事件串成连贯叙述（p.95–96）。
  4. 逐条检查有没有替玩家讲完：系统很难解读对人重要的事，复杂的解读会挤掉玩家自己编故事（p.96）。完成标准：每条输出标「起头」或「已下结论」，后者改掉或交设计者。
- **判停 / 转向**：讲到多细算讲完了，原书未说明；作者明说这类机制很难做好。
- **输出**（约定）：「变量 / 区间 / 输出」映射表，附起头检查。

## B — 边界 (Boundary)

**不要用这张卡**

- 内容是预先写好的、要保证先后或分支 → `sylvester-story-structure.md`。

**作者警告的失败模式**

- 把宣传押在机制里根本没有的故事上（刷牙）。
- 高精度画面、动画、台词表现本该留白的东西，玩家编出的性格和关系被抹掉（p.94）。
- 解说讲得太满、解读出错，压住玩家自己的叙事（p.96）。

**作者盲点与各分支缺口**

- 分支 1 的对照表是据作者的描述重建的；和 apophenia 一节有张力，「不能涌现」只对完全没有相关事件的种类可靠；只能查边界，估不了倾向。
- 分支 2 依据两款策略游戏和 Fallout 3 一处点评，作者自己也说 Fallout 3 这点做得不够；标签太具体或配上表演，可能反而盖掉想象。
- 分支 3 只管虚构表现层，机制决策需要的信息不能因此减少（第 5 章，p.129）；没有「抽象到多少」的判据；品类判断是观察，没有数据。故意少传达，和第 9 章「从没被传达的事等于没发生」（p.219）之间怎么取舍，原书未说明。
- 分支 4 的三种形式是对三个例子的归纳，不是作者的分类；记录功能的成本和信息过载，原书没讲。
- 分支 5 主要依据 Hitman 一例和体育解说的类比，作者明说这类机制很难做好。
- 作者观点（参考单元）：Fallout 3 的滑稽底色能减轻情绪负担、为不写实的怪物开脱，也让涌现中难免的逻辑荒谬变得好笑。作者举的例子是背后连开三枪，守卫转身说「我好像听到了什么」（p.115）。只有这一个案例。
