# 试玩现场：观察、提问与解读反馈

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Don’t use feedback to gather suggestions. Use it to gather player experiences.
>
> 译：别拿反馈去收集建议，要拿它收集玩家的体验。
>
> — Tynan Sylvester, *Designing Games*, Ch6 Balance / Balancing Methods, p.171

> We can learn most of what we need just by watching a playtest. … The problem is that verbal reports are unreliable.
>
> 译：我们需要知道的，大多看着别人试玩就能知道。……麻烦在于，口头报告靠不住。
>
> — Tynan Sylvester, *Designing Games*, Ch11 Planning and Iteration / Questioning Technique, p.299

> If the tester starts making suggestions, try to work backward and figure out what experience motivated the suggestion.
>
> 译：测试者开始提建议时，试着倒推回去，弄清是什么体验让他提出这条建议。
>
> — Tynan Sylvester, *Designing Games*, Ch6 Balance / Balancing Methods, p.172

## I — 方法骨架 (Interpretation)

这张卡回答「试玩时怎么看、怎么主持、怎么问，玩家的建议和抱怨怎么用，改了一处之后怎么看出体验变了」。作者认为改法设计者自己想得出，缺的是别人玩这款游戏时的经历，所以试玩要收集体验，不收集建议。观察是主手段：成败、速度、决策、视线、表情把玩家的感知写在了行为上。口头报告靠不住：记忆会被改写甚至编造，体验里混着改设计的建议，对设计者的感情也影响判断；人还会自动给自己的情绪编原因并深信不疑，这叫情绪误归因（emotional misattribution）。所以玩家说的「喜欢 / 不好玩」可信，「因为……」只当线索。

五个分支大致按一次试玩的时间顺序：分支 2 定何时从自测换成旁观、旁观时怎么主持；分支 1 是现场的主流程，先看后问，把建议倒推成体验再定位到系统；分支 3 是测后访谈的问法和回答怎么读，比分支 1 的问题更细；分支 4 整理试玩之外也会收到的反馈（问卷、评论、口述），拆开情绪和原因；分支 5 在改了一处之后，用两组玩家对照看体验哪里变了，分支 4 的待验证假设可以交给它。

## A1 — 书中案例 (Past Application)

- **分支 1｜默认收回的建议（例题，p.171）**：一个玩家想让马跑快点，一个想让第二关简单点，第三个想让电池便宜点。**只看不问（作者亲历，p.172）**：作者办过很多次试玩，结束后根本不用提问。**直升机知识题（例题，p.172）**：问「直升机上下来了几个人」，测试者一脸困惑，说明没注意到直升机。**想删步枪（例题，p.172）**：多半是步枪给过他坏体验，再追问：该中的一枪没中，可能是瞄准系统；子弹老不够，可能是经济失衡；没看懂步枪的某个功能，可能要更好的教学或更清楚的界面。原书未说明结果。
- **分支 2｜炮塔房间（作者亲历，p.282–283）**：作者在 BioShock 下载内容里刷一个敌人冲向玩家、被墙上的火箭炮塔炸碎，用来交代炮塔；自己玩很完美，看别人玩时，没带武器的玩家转身逃出了房间，最后只好在玩家周围加打不碎的玻璃。**找门 15 分钟（例题，p.297）**：你很想说「就在那儿，按蓝色按钮」，但一说，测的就成了设计者钻进盒子里给提示的另一款游戏。
- **分支 3｜「讲讲刚才游戏里发生了什么」（作者亲历，p.299）**：作者最喜欢的测后问题，他常发现玩家记得的故事和他设计的、和实际发生的都很不一样。**左边那扇门（例题，p.300）**：不问是否注意到门，问为什么走那条路。
- **分支 4｜丝袜实验（转述，p.17–18）**：四双完全相同的丝袜，八成购物者选最右边那双，并说是颜色或质地更好。**格斗决胜局（例题，p.18–19）**：兴奋来自角色、招式、美术、和朋友的竞争、怕丢面子、闪光还是背景音乐，人分不出哪个因导致哪个果。
- **分支 5｜看三个人玩，改一个变量（例题，p.48）**：看三人玩，记下他们理解了什么、做了什么、记住了什么；改一个变量，再看三人，体验在某一处变了：一个想法被理解或丢失，一段记忆出现或消失。原书未说明具体结果。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 准备办一次试玩，要列观察项和访谈问题；或自测已经没新发现，要第一次请别人来玩。
2. 试玩报告满是「玩家希望……」，测试者提了具体改法：删掉某把武器、某关简单点。
3. 想知道玩家有没有注意到某样东西，或他为什么做了某个决定。
4. 问卷、评论或口头反馈里，玩家说「因为美术丑 / 操作差所以不好玩」。
5. 改了一处设计，想知道体验有没有变、在哪里变了。

**语言信号**

- 试玩时怎么问 ／ 测试时我要不要说话 ／ 玩家的建议怎么用 ／ 测试反馈全是要求改这改那 ／ 他到底看没看到 ／ 玩家说因为 X 所以不好玩 ／ 改了之后体验变了没有
- playtest interview ／ over-the-shoulder playtest ／ testers keep making suggestions ／ memory probe ／ leading questions ／ player feedback says it's because of X ／ did this change work

**与相邻卡的区分（初稿）**

- 写测试协议、找谁测、测几场够、何时停测 → `sylvester-playtest-protocol.md`
- 玩家没注意到提示或 HUD，要改界面让它被看到 → `sylvester-signal-visibility.md`
- 拿到试玩发现后定改法 → `sylvester-balance-change-review.md`
- 用埋点和统计数据验证假设 → `sylvester-metrics-and-telemetry.md`；拆一段体验找情绪来源 → `sylvester-experience-analysis.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 要办试玩，列观察项和问题；测试者提了改法 | 分支 1 |
| 自测没新发现了，要换人；旁观时怎么主持 | 分支 2 |
| 测完要访谈：怎么问才不诱导，回答怎么读 | 分支 3 |
| 手里是问卷、评论、口述，玩家给了「因为……」 | 分支 4 |
| 改了一处，想看体验在哪里变了 | 分支 5 |
| 测几场够、找谁测、协议怎么写 | `sylvester-playtest-protocol.md` |
| 问题已定位，要定改法 | `sylvester-balance-change-review.md` |

### 分支 1：试玩收集体验而非建议

- **输入**：这次想弄清什么（玩家在哪一段经历了什么）；能看着测试者玩的条件；要测的版本。想弄清的事说不清，先问设计者。
- **步骤**：
  1. 定目的：收集体验，不收集建议（p.171）。完成标准：目标写成「想了解玩家在 X 处经历了什么」，不写「征集改进意见」。
  2. 先观察：成败、推进速度、做了什么决定、看哪里、表情（p.172）。完成标准：观察记录覆盖这五项。
  3. 观察回答不了时，按目的选问题（p.172）：
     - 想知道什么在他心里最显著 → 让他讲讲发生了什么
     - 想知道他有没有察觉某样东西 → 出一道知识题，他一脸困惑就是没注意到
     - 想理解他的某个决定 → 让他复述当时的思路

     完成标准：每个问题标出对应的目的。更细的问法和回答判读见分支 3。
  4. 提问时保持开放、中立、专业：好奇而不质问的语气；避开可能扭曲或掩盖体验的个人互动和情绪；不鼓励、不奖励正面或「正确」的回答（p.172）。完成标准：问题单逐条对过这三条。
  5. 测试者提建议时倒推体验：问他为什么这么提，或先猜发生了什么，再追问具体是哪次坏体验（p.172）。完成标准：每条建议对应一次具体体验。
  6. 把体验定位到负责的系统，参照步枪例（p.172）。完成标准：每次体验对应一个系统。
- **判停 / 转向**：观察已能回答要弄清的事，就不必提问（p.172）。定位后的改法转 `sylvester-balance-change-review.md`；体验是「没看到、没注意到」的，转 `sylvester-signal-visibility.md`。
- **输出**（约定）：观察记录（五项）；问题单「问题 / 目的 / 回答」；映射表「建议 / 背后的体验 / 负责的系统」。

### 分支 2：旁观测试的切换时机与主持规则

- **输入**：最近几轮自测有没有新发现；要测的那一段；能找到的、没见过这一段的人；游戏还缺哪些部分。
- **步骤**：
  1. 早期几轮以自测收尾：自测最便宜，能看出心流、节奏和平衡问题，技术 bug 也最适合在自测里找（p.296）。完成标准：写明本轮是自测还是旁观。
  2. 自测不再教你新东西时，换成旁观测试：游戏不是做给你一个人玩的（p.285）。判据是作者的定性描述，原书没给次数，由设计者自评。完成标准：写出切换理由。
  3. 找没见过这一段的人：理想是从代表目标市场的公众里随机抽的真实玩家，做不到就用同事；每轮换一个还没玩过的人（p.286）。完成标准：名单，每人标是否玩过。
  4. 什么都不告诉玩家，站在他身后、视线之外，等设计出问题（p.286）。
  5. 几乎所有情况下全程沉默：不说话、不笑、不叹气、不以任何方式流露想法；被问就用中性语气说「抱歉，我不能回答」（p.297）。完成标准：测试记录里没有「告诉了玩家……」。
  6. 游戏缺的部分需要补信息时，只给协议里事先写好的内容（p.297），协议见 `sylvester-playtest-protocol.md` 分支 1。
  7. 测完列问题清单，改完再找新人测下一轮（p.286）。完成标准：问题清单。
- **输出**（约定）：测试记录「测试者 / 是否玩过 / 失败点与意外策略 / 有无破例开口 / 问题清单」。

### 分支 3：测后提问技巧

- **输入**：观察回答不了、又想知道的事；这场的观察记录。
- **步骤**：
  1. 先看行为：失败说明太难，秒赢说明太易，漏掉指示或机会说明不清楚（p.299）。完成标准：先写出观察结论。
  2. 只在需要知道玩家脑子里发生了什么时才问，并记住口头报告靠不住：记忆会被改写或整段编造，体验里混着对设计的建议，对设计者或工作室的感情影响判断（p.299）。完成标准：每个问题写明观察为什么回答不了。
  3. 测后先问「讲讲刚才游戏里发生了什么」，这是记忆探针，看哪些东西被感知、记住、觉得值得提；没被提到的可能是设计里的死重（p.299）。完成标准：记下提到与没提到的元素。
  4. 要确认某样东西有没有被感知，不问「你注意到左边那扇门了吗」：问题本身泄露信息，玩家常为显得聪明或讨好而答「注意到了」。改问那次选择的理由，如「讲讲你为什么走那条路」：提到门并说明为什么没走，说明看到了但放弃；没提，说明可能根本没看到（p.300）。完成标准：问题单里没有点名目标的是非题。
  5. 保持专业、开放的语气，流露挫败会让测试者闭嘴、不再说真话；感谢测试者（p.300）。
- **判停 / 转向**：「没提到」只说明可能是死重或没被感知，不是定论；要确认，转分支 5 做对照，或转 `sylvester-signal-visibility.md`。
- **输出**（约定）：访谈记录「问题 / 目的 / 回答要点 / 判读（看到并放弃 / 可能没看到 / 可能是死重）」。

### 分支 4：反馈解读：情绪当真，归因作线索

- **输入**：玩家反馈原文（试玩口述、问卷、评论）。
- **步骤**：
  1. 把每条反馈拆成原始情绪（喜欢 / 不好玩）和玩家附加的原因（p.18）。完成标准：每条拆成两栏。
  2. 情绪照记为真（p.18）。
  3. 原因不按字面接受（p.19），改写成待验证的假设，并列出同一情绪的其他可能来源，作者的格斗例逐个列了角色、招式、美术、和朋友的竞争、丢面子、闪光、背景音乐、背景故事（p.18）。完成标准：每条假设附候选来源。
  4. 不凭看游戏或听解释下结论，交给试玩或统计 metrics 去观察小改动的效果（p.19）：转分支 5，或 `sylvester-metrics-and-telemetry.md`。先测哪条假设原书未说明，交设计者。完成标准：每条假设写明检验去向。
- **输出**（约定）：表「反馈原文 / 情绪（记为真）/ 玩家给的原因（未验证）/ 候选来源 / 检验去向」。

### 分支 5：单变量对照观察

- **输入**：要检验的那一处改动；两个版本只差这一项；两组测试者。
- **步骤**：
  1. 看一组玩家玩（作者举三人），记下他们理解了什么、没理解什么、做了什么、记住了哪些事件（p.48）。完成标准：每人三栏记录（理解 / 行动 / 记忆）。
  2. 只改设计中的一个变量（p.48）。完成标准：写明改了什么，并核对两版没有别的差别。
  3. 看下一组玩家，用同样的栏目记录，找出体验在哪一处具体变了：一个想法被理解或丢失，一段记忆出现或消失（p.48）。完成标准：写出那一处变化。
  4. 把这一处变化归到这次改动。作者断言这样的效果是一致的（p.48）；三人一组和这种归因都是作者的经验做法，不当统计结论。组内结果不一致时算不算有效，原书未说明。
- **判停 / 转向**：这段原是讲设计者怎样积累校准经验，不是测试协议（p.47–48）；正式安排测试转 `sylvester-playtest-protocol.md`。
- **输出**（约定）：对照记录「组别 / 版本 / 理解 / 行动 / 记忆」，加一句「改了 X → 体验在 Y 处变了（作者的经验做法，待复现）」。

## B — 边界 (Boundary)

**不要用这张卡**

- 决定测几场、何时停测、找谁测、写协议 → `sylvester-playtest-protocol.md`。第 11 章的分档停测规则（p.299）在那张卡分支 4；第 6 章的 10–20 场说法（p.173）所在单元待核查，列在那张卡 B 段作对照。
- 把试玩当需求征集或功能投票。

**作者警告的失败模式**

- 把测试者的建议当改动清单（p.171–172）。预警：报告主体是「玩家希望……」。
- 访谈中流露情绪或倾向、鼓励「正确」的回答（p.172）；流露挫败会让测试者闭嘴（p.300）。
- 旁观时开口提示：测试更顺了，只因为缺陷被藏起来（p.297）。
- 按玩家说的原因去改，改的地方可能根本不是问题所在（p.18–19）。
- 拿整款游戏互相比较找原则：差异太多，分不出效果来自哪一处（p.48）。

**两章问法的差别（并列，不替作者选）**

- 第 6 章的知识题点名了要考的东西（直升机上下来几个人，p.172）；第 11 章反对点名目标的是非题（你注意到左边那扇门了吗），理由是问题本身泄露信息、玩家会为显得聪明而答是（p.300）。作者没讨论两者的关系。

**作者盲点与时代局限**

- 平衡与测试几乎全靠人工试玩，遥测只提了一句；测试资源默认中大型团队（编者评注，非原书）。
- 吊桥、丝袜等心理学研究在书外的可重复性待核（编者评注，非原书）。

**各分支的已知缺口**

- 分支 1：原书没有问卷或记录模板，输出格式是约定；口头报告不可靠，作者把多数理解寄托于观察。
- 分支 2：没玩过的人只能用一次，小团队每轮找新人很难，原书没给替代办法；同事不等于目标玩家，作者自己说是退而求其次；沉默规则社交上很难受，作者承认但仍要求；主持细节来自作者自己的流程这一个案例。
- 分支 3：「没提到」只是可能是死重，不是定论；回答只是线索；原书只给了两个问句例子。
- 分支 4：作者明说即使用试玩和 metrics，也永远无法完全理解游戏怎样影响玩家（p.19）。
- 分支 5：两组测试者之间的差异怎么控制，原书未说明；三人是作者的经验估计，不是样本量要求；作者说游戏设计没法从书里学会，要靠这种经验校准（p.47）。
