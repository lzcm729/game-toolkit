# 虚构与元游戏信息审查

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> Information from the fiction is often ambiguous because the player can’t know which aspects of the fiction are real game mechanics and which aren’t.
>
> 译：来自虚构的信息常常含糊，因为玩家无从知道虚构里哪些方面是真正的游戏机制、哪些不是。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Fictional Ambiguity, p.135

> Good game decisions, including good puzzles, are always based around nonobvious uses of mechanics that work in obvious ways.
>
> 译：好的游戏决策，包括好的谜题，总是建立在对运作方式一目了然的机制的非显然用法上。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Fictional Ambiguity, p.136

> The standard solution is to accept that it’s there and design systems that still create the desired experience even given metagame information.
>
> 译：标准做法是承认它存在，设计出即使玩家掌握元游戏信息、也仍能产生预期体验的系统。
>
> — Tynan Sylvester, *Designing Games*, Ch5 Decisions / Metagame Information, p.138

## I — 方法骨架 (Interpretation)

这张卡处理玩家决策时用到、却不来自机制本身的两类信息，作者称它们为有问题的信息来源（p.135）：它们让玩家实际知道的比设计者以为的少或多。

- **虚构模糊（fictional ambiguity）**：没有机制能模拟虚构外衣的全部性质，玩家看图像猜不出哪些交互是真的，于是预测不了涉及它的任何交互，谜题塌成穷举乱试。它是信息饥饿的一种来源。
- **元游戏信息（metagame information）**：玩家从游戏外的现实世界带进来的信息，如类型惯例、口碑、工作室习惯、技术极限、宣传物，以及「游戏是为娱乐做的、会公平」。它常造成信息过剩。它不是竞技圈说的「版本 meta」。

分支 1 管虚构那一侧，分支 2 管游戏外那一侧，互不依赖，按症状进入。

## A1 — 书中案例 (Past Application)

- **分支 1｜烤火鸡（例题，p.135）**：拿起、放背包、吃、卖、冷冻、扔去引开动物、藏把枪，现实里都行，各游戏分别允许过，没有游戏全允许。**两个冒险游戏谜题（转述，p.135–136）**：一款 1990 年代初的游戏要用树枝、绳子、泥巴做面具骗过守卫；一款近年获好评的游戏要调飞机电台频率、再去电台发消息，叫醒挂在树上戴耳机睡着的飞行员。作者评价：塌成机械的乱试。两作未点名。**Mario 跳跃谜题（转述，p.136–137）**：跳跃一致可懂，玩家能无歧义地想路径，一看到解法就知道对了。
- **分支 2｜丧尸城堡（例题，p.137–138）**：虚构说会长时间断供，玩家知道游戏不会这么不公平，于是按惯例和设计者习惯推测补给何时出现，紧张和沉浸下降。**System Shock 2（转述，p.139）**：资源真的少、敌人真的多、没有兜底机制，粗心的玩家会被一点点磨死；作者评价它可怕又沉浸，因为机制和虚构一致。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 试玩者把背包里的东西两两组合乱试，卡关后说「谁想得到」。
2. 玩家去试游戏里没有的交互：木板挡不挡子弹、这扇门能不能开。
3. 道德或角色选择开始影响数值、路线、升级。
4. 恐怖或生存游戏：虚构说资源稀缺，玩家却不紧张，能预言「快到补给点了」。
5. 讨论要不要打破类型惯例，做「真的不公平」。

**语言信号**

- 谜题玩家想不到 ／ 解法太跳 ／ 玩家以为能交互 ／ 这个东西到底能干嘛 ／ 惯例要不要打破 ／ 玩家不信威胁
- adventure game logic ／ moon logic ／ fictional ambiguity ／ genre convention ／ metagame information ／ no fail-safe

**与相邻卡的区分（初稿）**

- 机制内部的信息量问题（视野、明牌、数值显示）→ `sylvester-information-balance.md`
- 让美术和隐喻把机制讲清、视觉线索前后一致 → `sylvester-mechanic-metaphor.md`
- 「meta」指版本强势打法 → `sylvester-degenerate-strategy-hunt.md`
- 剧情选择该按预定义还是系统决策评 → `sylvester-decision-quality-audit.md` 分支 3

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 物件能不能交互、谜题解法靠猜、选择回馈到数值 | 分支 1 |
| 玩家按惯例或游戏外常识行事，虚构营造的威胁或目标失效 | 分支 2 |

### 分支 1：虚构模糊审查与谜题重建

- **输入**：要审的物件、谜题、选择；每个物件机制上真实支持的交互；选择会不会改变数值、路线、升级。
- **步骤**：
  1. 每个物件列出玩家看到它时可能想到的全部交互，核对哪些是真机制（p.135）。谜题之外同样要审：木板挡不挡子弹、火球能否一发打死人、玻璃能否打碎、门能否打开（p.136）。完成标准：歧义表，每个物件有「可能想到的交互 / 是否真机制」。
  2. 谜题判定：解法只是虚构上说得通的众多方案之一、玩家缺少机制层理解，判为虚构模糊（p.135–136）。完成标准：每个谜题标「依赖虚构 / 依赖已知机制」。
  3. 依赖虚构的，把谜题从虚构里拿出来，用玩家熟知的机制构造（p.136）。两问检查：涉及的机制玩家是否都知道、运作是否明白；解法是不是它们的非显然用法（p.136）。完成标准：每个改造方案两问都答「是」。
  4. 谜题之外的物件含混（挡不挡子弹、能不能打碎），必要时绕过虚构，直接给机制信息（p.129）。完成标准：歧义表里每个「非真机制但玩家会试」的项，写明补不补、补什么。
  5. 选择：只在虚构里有意义的道德或角色选择，可以只靠虚构信息；一旦回馈到数值、关卡路线或道具升级，就要配上明确的机制信息（p.137）。完成标准：每个选择标「纯虚构 / 回馈机制」，后者写出要补的机制信息。
- **判停 / 转向**：第 1 步的「全部交互」没有穷尽标准，靠设计者列。怎么让玩家先学会机制、补的信息怎么呈现，本节没给 → `sylvester-mechanic-metaphor.md`、`sylvester-signal-visibility.md`。
- **输出**（约定）：歧义表、谜题改造方案、选择标注。

### 分支 2：元游戏信息盘点与处理策略

- **输入**：虚构暗示的威胁、目标或节奏；机制实际的节奏（如补给间隔）；目标玩家。玩家掌握的元游戏信息因人而异，游戏记者最多、小孩少，多数人居中，但再天真的玩家也知道不少（p.138）。
- **步骤**：
  1. 按作者的来源清单盘点（p.137–138）：类型惯例、朋友的口碑、套路和工作室习惯、技术极限、预告片与封面、「游戏为娱乐而做、会公平」。完成标准：逐项标「相关 / 无关」，相关项写出它给了玩家什么。
  2. 判影响：设计者以为玩家没有、玩家其实有的信息，常造成过剩，表现是玩家按惯例和设计者习惯而不是虚构去推测（p.137–138）。效果多在玩家内心，不会让游戏坏掉，所以难看见（p.138）。完成标准：每个相关项写出它扭曲了哪个决策。
  3. 默认用标准法（p.138）：不要让玩家害怕他知道不会发生的事、盼望他知道不可能的事；用正当、公平、游戏式的威胁和明确平衡、可达成的目标；让虚构迁就元游戏信息，当作又一条设计约束。完成标准：每个相关项一条标准法约束。
  4. 疯狂法是对玩家摊牌：不公平、任意、打破技术极限（p.138）。是否走它交设计者，并附上作者的风险提醒：危险且难，惯例自有道理，多数情况下不该打破，但有些体验只能这样得到（p.139）。完成标准：疯狂法以「交设计者决定」的备选列出，附风险提醒；设计者选它时写明要换取的体验（约定）。
- **判停 / 转向**：疯狂法没有可操作的适用判据，只有 System Shock 2 一例。元游戏信息的效果多在玩家内心，作者没给探测方法，第 1、2 步的盘点靠推想。
- **输出**（约定）：表，列为「来源 / 给了玩家什么 / 扭曲的决策 / 标准法约束」，另附疯狂法备选（如有）。

## B — 边界 (Boundary)

**不要用这张卡**

- 信息多少的问题出在机制本身 → `sylvester-information-balance.md`。
- 把元游戏信息当成「版本 meta」做强势套路分析 → `sylvester-degenerate-strategy-hunt.md`。

**作者警告的失败模式**

- 谜题依赖虚构暗示的交互，玩家穷举乱试（p.135–136）。
- 选择回馈到机制，却只给虚构信息（p.137）。
- 虚构威胁玩家，玩家知道它不会兑现，紧张消失（p.137–138）。
- 没想清要换什么就打破惯例；疯狂法危险且难（p.139）。

**作者盲点与时代局限**

- 分支 1 的例子集中在 1990 年代以来的冒险解谜游戏，分支 2 在 PC/主机生存恐怖（编者评注：项目类型偏窄）。
- 分支 1 第 4 步取自同章信息饥饿一节（p.129），作者在那里和虚构模糊一节都把虚构含混当作饥饿的成因。
- 虚构模糊的解法在第 9 章的隐喻词汇，本卡只管诊断和谜题重建。
- 作者自称全书是模型和假设（p.375）。

**各分支的已知缺口**

- 分支 1：「玩家可能想到的全部交互」没有穷尽标准。
- 分支 2：疯狂法只有 System Shock 2 一个例子，判据只有「危险且难」「有些体验只能这样得到」；元游戏信息的效果难以观察，盘点靠推想。
