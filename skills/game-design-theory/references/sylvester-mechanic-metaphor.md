# 隐喻与美术噪声：让玩家看懂机制

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> METAPHOR is giving something new the appearance of something familiar in order to make it easier to understand.
>
> 译：隐喻，就是给新东西披上熟悉事物的外观，让它更容易被理解。
>
> — Tynan Sylvester, *Designing Games*, Ch9 Interface / Metaphor, p.220

> A game must establish a METAPHOR VOCABULARY that indicates which elements are simulated mechanically. It must then remain consistent with this vocabulary.
>
> 译：游戏必须建立一套隐喻词汇，标明哪些元素在机制上有模拟，之后必须始终守住这套词汇。
>
> — Tynan Sylvester, *Designing Games*, Ch9 Interface / Metaphor Vocabulary, p.224

> Just replacing gray surfaces with art has made the game become unplayable, even though the mechanics design has not changed at all.
>
> 译：只是把灰色表面换成美术，游戏就没法玩了，尽管机制设计一点没变。
>
> — Tynan Sylvester, *Designing Games*, Ch9 Interface / Noise and Art Complexity, p.226

## I — 方法骨架 (Interpretation)

玩家只能从画面和声音里读出机制。这张卡管「外观怎样把机制讲清楚」。作者认为虚构层最基本的用处，就是借玩家已有的知识（隐喻）让系统好懂（p.221）。但虚构只实现了真实物体的一小部分功能，玩家得自己分辨哪些是机制、哪些是布景，所以要有一套一致的外观约定，即隐喻词汇。美术细节越多，与机制无关的线条、颜色、声音也越多，机制信号会被淹没成噪声（noise：没能传达有效信息的信号）。

三个分支：分支 1 为一个机制选隐喻来源；分支 2 在可交互元素和布景混在一起时，建立并守住隐喻词汇；分支 3 从症状进入：灰盒（灰色方块搭的低保真关卡）好玩，换上美术后变差。设计期按 1→2，美术轮后出问题走 3。

作者总纲（参考单元）：没被传达出去的事件等于没发生（p.219）。

## A1 — 书中案例 (Past Application)

- **分支 1｜Zelda 的裂墙（作者亲历，p.222）**：作者看一名玩家在初代 Zelda 的一个房间里绕圈找出口，最后忍不住告诉他炸弹能炸开有裂缝的墙；作者说他不在场的话玩家可能就放弃了，因为裂缝并不必然意味着炸弹能打开它。**象棋（例题，p.223）**：64 格之间 2016 种关系，写成清单或用乒乓球加彩线表示都没法玩，放到二维平面借用空间直觉才可玩。
- **分支 2｜Prince of Persia: The Forgotten Sands（转述，p.224）**：墙上长划痕表示能跑墙，一种凸出的砖能攀爬；这种砖首次出现在显然别无出路的地方，之后在宫殿、下水道、神殿里外观从不改变。原书未说明结果。
- **分支 3｜作者的灰盒关卡（作者亲历，p.225–226）**：灰盒里树是杆上插大球、车是两个叠起的盒子，灰盒结束时关卡已平衡、测试者喜欢；和美术把它们换成树和大众、福特之后，谜题变得难解，路线被错过，敌人认不出。作者说在多个平台的多款游戏上反复见到；怎么修好的原书未说明。低噪风格（转述，p.226–227）：Team Fortress 2 用夸张轮廓配简单纹理，Portal 是白墙测试室，Mirror’s Edge 是裸白混凝土城市。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 新机制或系统要定外观，想让玩家一看就懂。
2. 试玩者认不出哪些东西能交互，在布景上乱试，或错过能用的。
3. 同一种可交互物在不同关卡里长得不一样。
4. 灰盒阶段好玩，美术轮之后玩家迷路、看不见敌人、谜题卡住。
5. 靠类型陈规（裂墙能炸、吃东西回血）传达机制，担心新玩家看不懂。

**语言信号**

- 玩家看不出这东西能干什么 ／ 哪些能爬哪些不能 ／ 换上美术反而不好玩了 ／ 美术太花看不清 ／ 交互提示要不要到处贴 ／ 视觉线索前后不一致
- players can't tell what's interactive ／ affordance ／ metaphor ／ visual language ／ art made it unreadable ／ graybox vs final art ／ visual noise

**与相邻卡的区分（初稿）**

- 谜题解法依赖玩家想到某个虚构推理，或要不要打破类型惯例 → `sylvester-fiction-and-metagame-info.md`
- HUD 提示、通知、台词没被注意到 → `sylvester-signal-visibility.md`
- 决策需要的数据玩家拿不到或太多 → `sylvester-information-balance.md`

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 要为一个机制或系统定外观、选借用什么 | 分支 1 |
| 可交互元素和布景混在一起，玩家分不清 | 分支 2（新机制先过分支 1） |
| 灰盒好玩，换上美术或音效后变难玩 | 分支 3 |

### 分支 1：隐喻来源选型

- **输入**：要表现的机制或系统；目标玩家（是否熟悉该类型、文化背景）。目标玩家说不清先问。
- **步骤**：
  1. 写出玩家要从外观上懂的关系或行为。隐喻的作用是让一个词或外观立刻教会玩家大部分要知道的东西（p.221）。完成标准：一句话写清。
  2. 按四类来源列候选（p.221–223）：真实物体（文件夹、汽车、背包）；文化原型与惯例（捻胡子的是反派、黑色是死亡）；游戏陈规及借自 UI、电影的惯例（食物回血、右上角 X 关窗、淡出到黑）；逻辑系统（牛顿物理、供求、人际关系，以及数字、时间、空间）。完成标准：每个候选写明来源类别和借用了玩家哪份已有知识。
  3. 标作者给的考量（p.222–223）：陈规对没有相应文化前置的人读不懂，游戏陈规尤其危险；模仿人人都懂的真实物理几乎没有学习负担，自创系统（相斥的引力）也许带来新玩法但极难理解；数字、时间、空间这类数学系统几乎通用；隐喻不必完美模拟，意思传得过去即可。完成标准：每个候选有文化前置依赖和学习负担的定性说明。
  4. 把候选表交给设计者选。来源怎么选原书没有规则，本分支不替他定；目标玩家有没有那份文化前置，原文没给评估方法，标为待试玩验证。完成标准：候选表完整，选择栏由设计者填。
- **输出**（约定）：表，列为「候选 / 来源类别 / 借用的已有知识 / 文化前置依赖 / 学习负担（定性）/ 设计者的选择」。

### 分支 2：建立并守住隐喻词汇

- **输入**：会暗示用途的虚构元素清单，以及哪些真有机制。哪些是机制由设计定，缺了先问，不要从画面推测。
- **步骤**：
  1. 逐个标「机制 / 布景」。游戏只实现真实物体功能的一小部分，玩家不能假设虚构里的一切都在机制里（p.223–224）。完成标准：每项有标记。
  2. 给每个机制元素定一个独特的虚构线索（墙上长划痕＝能跑墙）。作者认为满屏显式提示很快让人累、遮住虚构，长期更好的是教玩家读虚构线索（p.224）；何时宁可用显式提示，原文没说，由设计者判断。完成标准：每个机制元素有线索。线索够不够辨认，原书没有标准，交给试玩。
  3. 安排首次出现：放在很简单的谜题里，显然别无出路，玩家必然会去试（p.224）。完成标准：每条线索的首次出现位置满足「别无出路」。
  4. 一致性检查：同一线索在所有环境里外观不变（p.224）。完成标准：列出外观变了的机制元素，逐项改。
  5. 干扰物检查（由「保持一致」推出，原文没单列这一步）：找出带着同样线索、或像松砖和怪物血那样暗示用途却没有机制的布景（p.224）。完成标准：干扰物清单及改法。
- **输出**（约定）：词汇表，列为「元素 / 线索 / 首次出现位置 / 一致性问题 / 干扰物」。

### 分支 3：美术换入后的噪声排查

- **输入**：灰盒版与美术版各自的试玩观察；两版之间机制有没有改。缺两版试玩先补，不凭截图判断。
- **步骤**：
  1. 对症状：谜题变难解、路线被错过、敌人看不见（p.225–226）。先分噪声来自哪一类：复杂美术，还是信号过挤（p.225）；后者转 `sylvester-signal-visibility.md` 分支 1。完成标准：症状清单，写明机制是否改过（作者描述的情形是一点没变）和噪声类别。
  2. 找噪声源：对每条被遮住的机制信息（敌人、目标、工具、路线；角色的朝向、动作、手持物），找出与机制无关、遮住它的美术元素；音效、角色细节、动画同样会制造噪声（p.226）。完成标准：「被遮的信息 → 噪声源」对照。
  3. 列出三类对策（p.226–227）：调细节量；用专门线索标出画面里与机制相关的部分；或换一种天然低噪的美术风格。附上作者给的考量：换风格能同时解决几个部门的问题，但它是整体美术方向（p.227）；这个问题跨设计和美术，要两边紧密合作（p.226）。选哪类原书没有判据，交给设计者和美术；细节多少算太多也没量化。完成标准：每个噪声源旁列出可用的对策和考量。
  4. 改后复测（约定，依据作者的灰盒循环：找问题、修、重测，p.225）。完成标准：复测结果记入对照。
- **判停 / 转向**：漏看的是 HUD、通知、台词 → `sylvester-signal-visibility.md`。
- **输出**（约定）：对比记录，列为「症状 / 被遮的信息 / 噪声源 / 候选对策 / 选定（设计与美术填）/ 复测结果」。

## B — 边界 (Boundary)

**不要用这张卡**

- 谜题本身靠虚构推理，或在决定要不要打破类型惯例 → `sylvester-fiction-and-metagame-info.md`。
- 玩家漏看的是界面提示 → `sylvester-signal-visibility.md`。

**作者警告的失败模式**

- 用游戏陈规传达关键进度，不熟悉陈规的玩家卡住，可能直接放弃（p.222）。
- 虚构处处暗示可用、实际大多没做，又没有线索区分；或用满屏覆盖提示，虚构被遮住（p.224）。
- 美术追求作品集式的细节，放进快节奏画面里成了一团像素，机制信号被淹没（p.226）。
- 游戏被埋在界面后面：内部再精彩，传达不出去就没用（p.220）。

**作者盲点与时代局限**

- 文化原型带地域和年代性，作者举的是西方社会的例子（p.221），跨文化市场怎样判断原文没讲。
- 「多个游戏反复见过」是作者个人经验，主要来自第一人称射击的关卡设计（p.225）。
- 隐喻词汇的主案例只有 Prince of Persia: The Forgotten Sands 一个。
- 线索和噪声只按一般玩家的知觉讲，色弱等感官差异不在讨论内（编者评注：accessibility 不涉及感官障碍）。

**各分支的已知缺口**

- 分支 1：来源怎么选没有规则；评估目标玩家文化前置的方法未给。
- 分支 2：线索要多独特才算可辨认没有标准；词汇表规模、何时改用显式提示未给；干扰物检查是推出的步骤。
- 分支 3：三类对策选哪个没有判据；细节量没有量化标准；要求设计与美术合作，单方执行不了。
