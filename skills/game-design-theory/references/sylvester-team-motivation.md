# 团队动机与氛围：奖惩方案、沉默的团队、反复的小失误、看不到的进展

> **怎么用这张卡**：它是方法和书中依据的来源之一，不是回答的模板。回答围绕用户的处境：先给你自己的专业判断和具体做法，书外的实操（算一个例子、查数据、估成本）照常给；再用这张卡补方法、校正判断。不要按卡的分段复述这本书；卡里没写的，不等于不能答。书名和页码只在用户要出处时给。

## R — 原文 (Reading)

> EXTRINSIC REWARDS are rewards that are separate from the work itself, usually in exchange for some measurable performance on the job. … But they are doomed to fail in game design.
>
> 译：外在奖励是与工作本身分开的奖励，通常用来交换工作中某种可衡量的绩效。……但在游戏设计里它们注定失败。
>
> — Tynan Sylvester, *Designing Games*, Ch15 Motivation / Extrinsic Rewards, p.349

> Climate grows from people’s expectations of how they’ll be treated. If they take a risk and it fails, do they expect to be blamed or consoled?
>
> 译：氛围长在人们对「自己会被怎样对待」的预期上。冒了险、失败了，他们预期被责怪，还是被安慰？
>
> — Tynan Sylvester, *Designing Games*, Ch15 Motivation / Climate, p.354

> The PROGRESS PRINCIPLE is the observation that the strongest contributor of good inner work life is regular, visible day-to-day progress.
>
> 译：进展原则说的是：对良好的内心工作状态贡献最大的，是规律、看得见、每天都有的进展。
>
> — Tynan Sylvester, *Designing Games*, Ch15 Motivation / The Progress Principle, p.360

## I — 方法骨架 (Interpretation)

这张卡回答「怎样让开发团队有动力，又不把动力引错方向」。作者的立场是：游戏开发的贡献从外面量不准，好开发者的动力主要来自工作本身，所以按绩效发钱或罚钱会失败；该做的是保住让人敢冒险的氛围，用不伤氛围的小信号处理具体行为，让每个人天天看到进展。

术语：**外在奖励**是与工作分开、按可衡量绩效发放的奖惩；**氛围**（climate）是人们每天对工作的情绪，来自「冒险或质疑之后会被怎样对待」的预期；**风险账本**是一个成员决定说不说冒险点子时心里列的得失；**进展原则**借自 Amabile 的日记研究，频率比大小重要。

四个分支按问题分流：有人提出奖惩制度 → 分支 1；团队沉默、评审总是一致通过 → 分支 2；某个代价落在全队的小失误反复出现 → 分支 3；士气低、看不到进展 → 分支 4。分支 1 审下来不宜采用时，作者给的替代方向在分支 3、4。

作者观点（只作参考）：开发者想做有意义的工作，作者列了创作出口、平衡的挑战、自豪、认可、主人翁感、归属、责任、自由（p.352）；严厉管理适合维持标准的工作，不适合要冒险创造的工作（p.356）；以高期望待人、给团队一个要配得上的身份（p.358–359）。

## A1 — 书中案例 (Past Application)

- **分支 1｜展示会发购物券（转述，作者听说的制度，p.351–352）**：为购物券而不是为作品工作；做好看东西的人遭做底层技术的人怨恨；时间花在打磨演示上；还要惦记购物券，四条理由同时命中。作者评为几乎纯粹的恶，实际后果原书未说明。**律师与卸沙发（转述，p.350）**：高价律师免费帮贫困老人，给 30 美元一小时就不肯；陌生人肯免费帮你卸沙发，给一美元就不肯。
- **分支 2｜同一个冒险点子的两本账（例题，p.354–355）**：好氛围里代价只是花一分钟、可能没结果，他会说；在推卸、恐惧、越权的工作室里，失多于得，点子被埋。作者推演：重复成千上万次后，一两年后人们奇怪游戏为什么平淡、保守。原表在转换中被误标成页边要点，这里只按正文复述。
- **分支 3｜橡皮鸡（作者亲历，p.359–360）**：弄坏构建的人修好错误，桌上出现一只橡皮鸡，直到下一个人弄坏构建。作者自己领过很多次，评价它平衡、不对抗；没有对照。
- **分支 4｜任务墙与页数（转述 + 作者亲历，p.360–361）**：任务列在墙上用红笔划掉；作者独自写书多年，靠晚上看到页数涨上去的那点快乐坐下来再改四小时。

## A2 — 触发场景 (Future Trigger) ★

**情境**

1. 要定绩效奖金、按指标发奖、评月度最佳创意。
2. 评审会总是一致通过，没人提新方向，游戏越做越安全。
3. 某个小失误反复出现（弄坏构建、忘了解锁文件、约了试玩不到），代价落在别人身上。
4. 大任务挂了几周不动，团队士气低；一两个人的小团队做久了没劲。

**语言信号**

- 要不要发绩效奖金 ／ 按 KPI 奖励 ／ 团队不敢提意见 ／ 评审总是全票通过 ／ 老有人搞坏版本 ／ 士气低 ／ 看不到进展 ／ 做久了没动力
- performance bonus ／ incentive scheme ／ team morale ／ nobody speaks up ／ broken build ／ progress principle ／ task board

**与相邻卡的区分（初稿）**

- 给玩家的奖励、成就、积分 → `sylvester-reward-alignment.md`（第 8 章，同一组词的另一种用法）
- 谁有权拍板、领导评审越权 → `sylvester-natural-authority.md`
- 改动太频繁让团队不再投入（文化影响）→ `sylvester-complex-decisions.md` 分支 1

## E — 执行 (Execution)

### 先选分支

| 你的问题像…… | 走 |
|---|---|
| 有人提出按绩效发钱、罚钱或评奖 | 分支 1 |
| 没人提冒险点子；长期一致同意 | 分支 2 |
| 一个代价落在全队的小失误反复发生 | 分支 3 |
| 士气低、看不到进展；小团队没动力 | 分支 4 |

### 分支 1：外在奖惩方案审查

- **输入**：方案的完整描述：奖或罚什么、按什么指标、给个人还是小组。缺了先问。
- **步骤**：
  1. 确认属于外在奖惩：与工作本身分开、按可衡量绩效发放（p.349）。完成标准：写「是 / 否」及依据；与绩效无关的薪酬不进本分支。
  2. 过四条理由，逐条写是否命中（p.350–351）：① 绩效从外面难判断（贡献混在一起、好工作也会因运气失败、敢冒险的人看起来比求稳的差）；② 挤掉对工作本身的热爱；③ 反常激励（政治、八卦、藏工作、避险、拉小圈子）；④ 分心去算计奖励。完成标准：四行都有结论和理由。
  3. 靠威胁惩罚（开除、扣薪、吼人、翻白眼和嗤笑）的单独标出：作者说比奖励更糟，威胁下没有开放讨论和深度思考（p.351）。
  4. 对照作者点名的失败变体（p.352）：按机制或点子计酬（没用的机制泛滥）、惩罚失败的点子原型测试（压制冒险）、按工时（人坐满、产出少）、奖励个人（嫉妒）、奖励小组（分出偷懒的和监工）。完成标准：写出命中哪个。
- **判停 / 转向**：命中几条算不行，原书没有程度划分，作者的结论本身是绝对的（p.349）。不预测方案的实际效果。想表达认可或纠正某个行为 → 分支 3。
- **输出**（约定）：表「理由或变体 / 是否命中 / 理由」，末行注明「这是作者的论证，不是实测」。

### 分支 2：风险账本诊断氛围

- **输入**：团队过去怎样对待冒险失败和质疑领导的具体事例；以哪位成员为视角。原书没给收集成员真实预期的办法；缺了先问，不要由领导代填。
- **步骤**：
  1. 用作者的两问收集事实：冒险失败后，预期被责怪还是被安慰？质疑领导，预期认真回应还是当头一棒（p.354）？完成标准：每问至少一件具体事例。
  2. 站在一位想提冒险点子的成员角度写得失账本（p.354–355，按正文语义重建）。得：成了有功劳、游戏受益、能表达自己、从别人的回应学到东西、有乐趣；失：至少花一分钟、可能没结果；坏氛围里另有：功劳可能被偷、没说完就被否、漏洞被撕而丢面子、实施后被下一次 swoop-and-poop 践踏。完成标准：每条挂一件步骤 1 的事例，没有事例的标「推测」。
  3. 判断倾向：得占上风会提出，失占上风点子被埋（p.354–355）。完成标准：写「倾向提出 / 倾向沉默」及支撑条目。
  4. 补看沉默症状：没人提冒险点子、该有的辩论没发生、游戏越做越平淡安全（p.355）。坏氛围不造成事故，只让好事不发生。
- **判停 / 转向**：团队长期一致同意时，把它当启动本分支的警报；作者说它要么是思维懒惰、要么是恐惧氛围（Ch17，p.372），两者怎么区分原书没给方法，本分支不下这个结论。介于作者两张示例账本之间的，由设计者判断。
- **输出**（约定）：事实清单、账本、倾向判断。

### 分支 3：不严肃的社会信号

- **输入**：反复出现的行为；代价落在谁身上；现在怎么处理。
- **步骤**：
  1. 确认结构：代价主要落在团队、起因在个人，天然动力不足，这种行为会系统性偏多（p.359）。完成标准：写出「谁犯、谁付代价」。
  2. 排除罚款（引来愤怒和过度谨慎）和当面质问（伤关系、坏氛围）（p.359）。
  3. 设计一个不严肃、不明说、偶发的象征物（p.359）；犯错的人修好自己的错并拿到它，下一个人犯错才转走，不讨论、不对质（p.360）。完成标准：三条性质和转移规则逐条对上。
  4. 列出要观察的期望效果：人人想躲开，拿到的人不生气、不沮丧；不让人过度谨慎，也不让人满不在乎（p.360）。
  5. 别的场合用同类信号：跟人赌一杯酒，赌他想不出某个设计难题的解法（输赢都一起喝）；把游戏文件里新做的酷东西放上办公室显示器（p.360）。
- **判停 / 转向**：会不会伤氛围原书没给检验方法，由团队观察判断。这只是针对具体行为的小推动，作者说主要动力来自有意义的工作（p.352、p.357）。
- **输出**（约定）：信号设计「象征物 / 触发 / 转移规则 / 三条性质核对」和观察项。

### 分支 4：进展可见化

- **输入**：当前任务清单和粒度；团队人数；每个角色现在怎么得知自己工作的结果。
- **步骤**：
  1. 把任务切小，挂在大家看得见的地方，完成一个就用红笔划掉（p.361）。作者的经验估计：小到墙上每天能划掉两三个，团队就会觉得一直在往前走（p.361）；原文说的是墙上，没说每人。完成标准：几周才完成的条目已拆开。
  2. 让每个角色不靠别人就看到自己的进展：设计师看自己的试玩、程序员看自己的代码通过自动化测试、美术自己判断角色何时融进世界（p.361）。试玩带来的是自然、没有上限、可信的后果（p.357–358）。完成标准：每个角色有一条自己的反馈通路；进展只被别人在评审里看到的，标出。
  3. 一两个人的团队用详细的待办清单或产出计数维持动力（p.361）。
- **判停 / 转向**：作者没按人数换算两三个；三人团队够不够由团队定。
- **输出**（约定）：任务拆分、可见位置、各角色反馈通路三项。

## B — 边界 (Boundary)

**不要用这张卡**

- 对象是开发团队，不是玩家；玩家奖励见 `sylvester-reward-alignment.md`。

**作者警告的失败模式**

- 按产出数量或展示效果给奖，奖励了保守、惩罚了冒险（p.350–352）。
- 发怒的领导只看见被吼的人跑起来，看不见旁观的 30 个人的账本在变（p.356）。
- 用罚款或点名批评处理小失误（p.359）。
- 进展只被评审者看见，做事的人感觉不到（p.361）。

**作者盲点与时代局限**

- 「doomed to fail」是绝对断言，没讨论固定薪酬和分红。
- Amabile 日记研究经二手报道引用，Ariely 的金钱启动实验、期望效应研究，书外可重复性待核。
- 风险账本原是被误标成页边要点的表格，正反两栏按语义重建，不能当作者要点句引用；示例账本只有两个极端，中间状态靠判断。
- 作者没给获取成员真实预期的方法，恐惧氛围下成员未必说实话；长期一致同意是懒惰还是恐惧，原书没有区分方法。
- 橡皮鸡唯一完整的例子是作者团队的轶事；默认同处一室，远程协作和文化差异原书未讨论；它只是针对具体行为的小推动，主要动力仍来自有意义的工作。
- 「每天两三个」是作者的经验估计，原文说的是墙上每天两三个，没说每人。
- 例子默认雇佣制工作室（编者评注，非原书）。
