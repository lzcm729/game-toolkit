# 提取 Prompt 模板

启动 Explore agent 时使用此模板。将 `{DOC_LIST}` 和 `{FOCUS_AREAS}` 替换为实际内容。

---

你是设计文档结构化提取器。逐一阅读以下文档，提取所有可交叉比对的定义。

**文档清单：**
{DOC_LIST}

**请逐一阅读每个文件，然后按以下格式提取：**

页头自标「草稿」的页单独一节提取，条目前缀 `[草稿]`，不与现行页混列。
以下每个维度均带可打开的实际定位；CSV 行号含表头从一开始，不用列字母。

## 1. 数值定义
列出所有具体数字（金额、百分比、天数、次数、阈值等），格式：
- `[来源文件名:行号] 概念: 数值` —— Markdown 给实际行号（含 front matter）；CSV 给 `文件名 第 N 行 列名`，
  有 `revision_id` 的文件首次引用时附上版本。列序会漂，所以用表头名定位，不写列字母。
- 表头或单元格注明「已停用」「勿读」「占位」的值**照抄状态、不当现行数值**；空单元格不写成 0。

## 2. 概念定义
列出所有关键概念的定义，格式：
- `[来源文件名] 概念名: 定义内容`

重点关注：{FOCUS_AREAS}

## 3. 流程与规则
列出状态转换、触发条件、因果关系，格式：
- `[来源文件名] 规则: 描述`

## 4. 枚举列表
列出所有分类、类型、档位等列表，格式：
- `[来源文件名] 列表名: [项1, 项2, ...]`

## 5. 组内矛盾
如果同组文档之间有不一致的地方，列出：
- 文档A说: ...
- 文档B说: ...
- 矛盾点: ...

## 6. 模糊/未定义
定义不清、有歧义、缺少具体数值的地方：
- `[来源文件名] 问题: 描述`

**重要：只提取，不评价。尽量完整，不要遗漏任何数值或定义。**
