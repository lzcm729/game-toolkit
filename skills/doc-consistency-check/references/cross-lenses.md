# 三镜头共用规则

你的镜头为 `{LENS}`。Read **全部** `{EXTRACTION_FILES}`，不是只读某一组。
工程根 `{projectRoot}`；可选回填配置 `{doc_feedback}`；主流程传入的出处与排除规则 `{SOURCE_RULES}`。
先读本 skill 的 `references/cross-reference-checklist.md`，不改任何源文件。
有配置则读 `{doc_feedback.rulings_ledger}` 的裁决日期与 `{doc_feedback.owners}` 的负责人规则；
缺目标由主流程标为未配置，不猜页面名。版本历史只作溯源，页头草稿不当现行页。

- 两处现行页对同一概念的数值或规则直接不同才报矛盾。两边各给原文（不超过二百字）、
  文件及定位；Markdown 文件:行，CSV 第 N 行＋列名，不用列字母。不确定就 Read 源文件核对。
- 最新裁决已定而某页仍旧口径，category 为「残留」，analysis 带裁决日期与内容，
  suggestion 明确按哪条裁决改哪页；不能把已裁决当作页面已经同步。
- 已建专表的数值以专表为准，汇总页与专表冲突归汇总页；总览/规格的权威关系依项目页内声明。
- 现行页与页头自标草稿的差异标 category「草稿冲突」，初判严重度中，留复核者核定。
- 高＝同一概念数值或规则冲突且影响实现；中＝术语残留、定义分散或接口未齐；
  低＝格式过时或不影响实现的缺失。单纯粗细不同不报冲突。
- 只有一处定义不是矛盾。「模糊/未定义」只有两页对同一模糊点给了不同暗示才报。
  不写泛泛的「补文档／补测试」。likely_owner 从属主表按要改的页面读取，缺来源写未知。

## 镜头 A：数值与枚举

只比数值和枚举：同名概念的不同值、百分比/概率的基数、单位、成员及数量、
核心参数权威来源是否唯一、汇总页与专表、表内行列自相矛盾。
逐项核实体、阶段、单位与生效范围：不同档位的值不因同列就当同一参数。
枚举数量以实际成员为证，摘要数字与成员不齐时引两边，不只复述提取结论。

## 镜头 B：术语流程接口

只比术语、流程和接口：改名残留、计数方向、触发条件与步骤顺序、状态转换、
跨系统传参、历史裁决未同步到其他页、引用了已删除概念。
沿生产者→消费者核同一字段的含义与时机，单纯名称不同先查别名约定；
历史中出现旧词不算现行残留。流程粒度不同只有在顺序或拒绝/结果规则冲突时才报。

## 镜头 C：跨组数值机械扫描

把全部组的「数值定义」合并为概念→出现位置/单位/阶段/值的映射；同义词也归并，
但同义关系须来自原文语义或项目词表，不能凭名字相似臆断。
每个概念凡出现至少两个不同值，或专表与页面值不一致，全部列为候选并附双侧原文。
这是防漏的机械扫描，不先凭熟悉程度过滤候选，保留范围差异供复核者筛；
草稿候选照样标草稿，历史及明确排除的值不混入现行映射。记录归并过且无差异的概念。

## 三个镜头分别返回

`lens`（string）、`findings`（array）、`checked_ok`（string array，查过无问题的维度/概念）。
findings 每项：`id`（先留空）、`title`、`severity`（高/中/低）、`category`、
`sides`（每侧 `file / locator / quote`，至少两侧）、`analysis`、`suggestion`、`likely_owner`。
除数组外以上各字段均为 string。每项必须可凭定位打开原文；无发现时返回空数组及 checked_ok。
主流程按同一对引文去重，引证更完整者优先，再编号 C01…，镜头自身不抢编号。
