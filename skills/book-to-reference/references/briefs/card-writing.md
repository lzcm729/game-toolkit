# 按意图写卡或修订卡

主执行方填工作目录和负责的 slug。先读 [../method.md](../method.md)、[../card-format.md](../card-format.md)，
再读工作目录的 `Paths.card_plan`、`Paths.overview`，按计划取单元、原始复核和支持材料：

```text
python scripts/verify_units.py show <workdir> u01-01 u02-01
```

写每张卡前回读相关原文整节，再全书检索跨章条件、数字和反例；只凭摘要写不够。
为了避免模仿基线，不读待接替的旧参考。只写计划中的卡、元数据和获派的修订记录。
卡在 `Paths.cards/<slug>.md`，元数据在 `Paths.meta/<slug>.yaml`。
meta 的 `intents` 用用户会说的话写，每卡至少两三条，不能只抄卡名或留空；缺失或全空会阻止接入。
A2 写和最近那张卡怎么分，用 `**与相邻卡的区分**` 后接列表，首条会进入选卡表的近邻列。
同一分组有多张卡时不能缺这段；分组只有一张卡时选卡表可用“—”，仍应说明适用处境。
单元的 `supports.terms` 要填写实际使用的术语编号；没有相关术语可为空并说明，不能把已有术语漏掉。
notes 的术语节靠这些引用从术语候选中选入，不会因为术语表文件非空就自动全部发布。

一张卡对应一类用户意图，每个 verified 单元是保留自己输入/步骤/输出/判停的分支。
R/I/A1/A2/E/B 顺序、卡头和计划列顺序照 card-format；卡与入口都写用法句，围绕用户处境答，不按卡复述书。
复核 narrowing 决定 E 能承诺的范围；must_go_to_boundary 每条落实。
只影响某个分支的限制不能放成整卡禁用，B 中点名分支或写在该分支判停处。

每个实质步骤回原文核，附页码；格式安排标约定，不能把判断规则标成约定就混入作者方法。
经验数字标作者经验；缺判据写原书未说明，缺图按 card-format 区分「原书未附图」与「原图缺失（转换时丢失）」，两处冲突并列。
reference/needs_review 不写执行分支，可作作者观点或依据不足的对照；notes 承担读者可达的参考去向。
书中案例保留性质和未说明结果；合成演练明确标注；英文摘句每条至多 60 词、每卡至多 150 词，自译中文。

修订既有卡时，删掉计划已移出的分支并同步分流表、卡头和元数据；只修改受影响部分，revision 同步加一。
不借修订新增未经验证的方法，不为篇幅丢必要条件。

```text
python scripts/check_cards.py <workdir>
```

计划、摘句页码、步骤标记任一失败就停；修后重跑同一检查。成功后还须做传播核对，页码在场不等于支持动作。
交回：卡和 meta 路径、分支数/字符数、检查命令和结果、收窄/缺口、最不像能照做的分支。
