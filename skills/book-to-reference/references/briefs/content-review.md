# 冻结前的候选内容评审

这是只读独立评审，安排在公开化和确定性检查之后、可达和回答对比之前。
主执行方填基线/候选源码副本及差异范围、已完成检查的证据、允许看的原始材料和已定取舍。
不要照搬另一书的已通过结论，未验收的候选仍待验收。
先读目标仓库根 CLAUDE.md、[../card-format.md](../card-format.md)、[../method.md](../method.md)、
[../acceptance.md](../acceptance.md)，再读实际差异和消费入口。

按后果检查：

1. 消费链：旧文件/结构引用是否残留；新链接是否存在且任务对口；agent、设计讨论入口和模板是否仍指旧摘要。
2. 公开可用性：编号、内部去向、复核状态是否诱导读者找私有文件；替换后是否保留依据不足、经验估计、合成演练、缺图和分支限制；原文摘句是否被误改。查私有路径及真实项目数据。
3. 入口：description 与实际内容一致吗，旧书能力是否被挤掉；选卡表能否找到所有意图、近邻区分是否误排有效路线；是否有重复节、破链接或被截断文件名。
4. 生成与检查：同输入能否重跑；平票、排序、编码和路径规则是否明确；测试会不会误过或误报；扫描通过不能替代语义抽查。
5. 交接：删除/部分保留的旧资料、Codex 重新导出 agent 和开新会话，以及发版需写明的验证边界。

证据优先回具体文件和行、原文及复核；不提放之四海皆准的建议。
区分已明确裁定、不在本轮范围的取舍与待判断内容，不替用户追加裁决。
不得改文件、提交、发布或调付费接口。若需工具检查，只在主执行方提供的隔离副本运行获准的只读检查。

报告在最终回答交回：必须改/建议改/小处，每条含文件:行号、实际后果、依据与具体改法；
再列查过未发现问题的范围、未覆盖项和不确定性。不写新的书中观点来修问题。
主执行方汇总修复，重跑受影响的确定性检查和语义核对，再冻结候选。
必须改未解决就停；已验收后若再改模型可见输入，按“修改后重验”约束让相关证据失效，同批重跑基线和候选。
