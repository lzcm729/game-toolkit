# 冻结、盲评与判定

口径 B 按导入稿第 2 节第 4 条：回答质量不比旧的差，而且可核性更好，才迁移。
分组依据是现行整个插件已支持的任务，不能从新卡反推旧覆盖范围。
O、O-partial 和其他书受保护能力 O-other 合并为旧覆盖组 O；新增任务为 N。
旧脚本的 O-syl 也属于 O。题目、分组、权重、必测/可选、容差在看到回答前冻结。

每个问题有两套身份：item_id 是任务、受保护能力或诱饵，qid 是该次评测题号。
make_prompts 同时保存 id_map.json、items_meta.json，之后都从这两份文件取身份。
TSV 的提示词压成单行，冻结后两个版本使用相同文件，不能事后换题或挪组。
抽样使用局部种子；冻结 YAML 的清单顺序也属于输入。目标来源、配额、排除项和
其他书的最少题数写在 answer_compare，不在脚本里写死书名。

评分包只放问题、评分项和匿名回答，对照 key 另放目录，不能交给评分者。
作者、书名、页码、参考文件名要遮蔽；先检查 leaks，再交给没见过版本和答案的独立评分者。
失败、缺最终成功回答或读取失败的运行不能伪装为正常答案进入评分包。
每个版本按冻结次数重复；比较两组回答，矛盾或无法确定记 undecided，不取平均强行放行。
题目没指定作者时，其他合理方法也可完成任务，不能只按新卡路线打分。

`protocol=B` 用于新书验收和今后回归：必测 O、N 两组分别要求 worse ≤ better；
任何必测 worse 写了实质退步类型都进 substantive 并判 fail，交给人核实，脚本不替人豁免。
缺评分、重复评分、无效身份或未决判 incomplete；可选题保留逐题记录，不能抵消必测退步。
汇总另核 book.yaml 中冻结的 answer_compare.required_items（O/N 必测 item_id），或 quotas 的必测数量；
漏题、某组零必测但没有 empty_groups 非空理由、成绩缺非空 difference/regression，均 incomplete。
四项 0–3 分只作记录，不替代更好/持平/更差与差异说明。

`protocol=pooled-required` 只复现历史回归的必测合计数量规则，不能作为今后的验收口径。
它合计必测题的好坏，仍单列实质退步供当时的人工归因核查；pass 不证明历史规则的
人工归因部分已完成。不得把此协议的通过写成 B 通过，也不以 B 的新结果改写旧记录。
新 key 使用 arm/rep/forced；显式的 legacy 序列化仅用于旧 key 的字节对照，并另存新 key。

修改后重验：改入口、卡、消费指令或运行条件，相关证据失效；集中修复、冻结候选后，
基线与候选同批交错重跑，不拿昨天的基线答案比较今天的新答案。只改不进模型输入的
确定性测试，做对应验证。同批减少日期混淆，不消除随机性，后次通过不改写前次结论。

质量与归因分开：先盲评质量，再看消费链解释差异。报告逐题列判定、退步类型、差异和
两版本是否调用插件/读了哪些资料。plugin_use 仅为诊断列，不改计数、substantive 或 status。
自然链路未调用、未读到、原因说不清的差题仍计入；未读卡的好答案也不能归功于卡。
强制查阅单列为内容诊断，不能代替自然链路验收。

回答对比计划至少写：两个冻结版本、模型和宿主版本、题数与报价、种子、题目来源、
两组定义、必测与可选、运行和评分重复数、协议、容差、停止条件及部分迁移的混合版本预留。
报告保留逐题判定、两组计数、实质退步、未决/缺失、消费链及费用，按导入稿的走向收口。

可达测试中 STRICT/ANY 只是命中机械参考答案；OTHER 要独立判断所读路线是否足够完成任务，
不能直接算错。NONE 表示没有读目标卡，HIT/MISS 用于受保护能力，REJECT/FIRED 用于诱饵，
FAILED 不算正常完成。要测真实插件入口，也要测消费方按引用读卡的路径。

使用配额替代 required_items 时，按冻结的每个子组逐项比较必测数量，不能以 O 组总数相同抵掉漏测的 O-other 等子组。子组或 O/N 组确实没有必测时，都要在 empty_groups 以该组键写非空理由；分组键必须和 items_meta 一致。
